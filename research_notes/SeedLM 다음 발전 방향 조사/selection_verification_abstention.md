## 1. Ranking in programming by example: which features of programs and of their outputs predict generalization from one example, and how large are the gains?

### Takeaway
Learned ranking beat Occam ranking by a wide margin in every PBE study found (FlashFill: 0% -> 74% of tasks solved from one example; 4.17 -> 1.48 examples on average), and features of program *behaviour* on unlabeled inputs (output regularity, execution traces) generalized better to held-out tasks than features of program *structure* (66.5% vs 57.9% and 68.2% vs 49.9% test accuracy). A natural-language description plus one example is worth roughly 2-4x either alone (regex: 80% vs 43% vs 26%).

### Cited Findings
- Singh and Gulwani (CAV 2015), FlashFill, 175+ real benchmarks: a learned hierarchical linear ranking over the version-space DAG (frequency features of token sequences, occurrence ids, position-logic lengths, Boolean features such as "left and right position logic use the same token") against a hand-written Occam baseline that "chooses smallest and simplest program". Average examples needed: 4.17 (baseline) vs 1.49 +/- 0.06 (30-70 train-test split). Solved from just 1 example: 91 tasks (74%) vs 0 for the baseline; from at most 2 examples: 110 tasks (89%) vs 18 (14%); not solved even with all 5 examples: 4 vs 72 benchmarks — [Singh & Gulwani 2015, PDF](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/06/cav15-1.pdf); summary on the [MSR page](https://www.microsoft.com/en-us/research/publication/predicting-a-correct-program-in-programming-by-example/)
- Ellis and Gulwani (IJCAI 2017) add two feature classes that are "independent of the program structure": (a) execution-trace features that penalize pathological computations, (b) output features: find a compact "descriptor" (a learned regular-pattern description, with simple world knowledge about names, places, words, dates) for the candidate's outputs on the user's *unlabeled* inputs and prefer programs whose outputs are well described. String transformation (91% of problems had 1 example), held-out test accuracy: Trace 46.1 +/- 2%, Output 66.5 +/- 2%, Program-structure 57.9 +/- 4%, All 83.5 +/- 3% (random 13.7%); on training tasks the production PROSE ranker scores 76.4% vs 88.4% for All. Text extraction (all problems 1 example): Output 68.2 +/- 1%, Program 49.9 +/- 1%, All 69.2 +/- 2%; training PROSE 65.8% vs All 79.3% — [Ellis & Gulwani 2017](https://www.microsoft.com/en-us/research/wp-content/uploads/2017/04/ranking-ijcai17.pdf)
- Same paper, on why behaviour features transfer: "Output features are lower dimensional than program features because descriptors have simpler structures than programs; accordingly, predicting based on outputs is less prone to over fitting." The unlabeled inputs give a "semisupervised learning signal" — [Ellis & Gulwani 2017](https://www.microsoft.com/en-us/research/wp-content/uploads/2017/04/ranking-ijcai17.pdf)
- Gulwani (POPL 2011) ranks by Occam's razor ("the simplest explanation is usually the correct one") and, when consistent programs disagree on a row, fills in the top-ranked output but highlights the cell because "there are multiple computational interpretations" — [Gulwani 2011](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/popl11-synthesis.pdf)
- FlashMeta/PROSE (Polozov and Gulwani, OOPSLA 2015) makes ranking one of three first-class version-space operations (intersection, ranking, clustering) and extracts the top-k programs under a domain-specific ranking function h; "Designing a good ranking function is a challenging open problem; one promising approach is using machine learning" — [Polozov & Gulwani 2015](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/oopsla15-pbe.pdf)
- Neural-guided deductive search (Kalyan et al., ICLR 2018) trains a model to predict the generalization score of the best program in each search branch. On 73 real tasks with ONE example: PROSE 67.12%, best NGDS variant 68.49% with up to 12x speed-up; DeepCoder-style variants 35.81-62.92%, RobustFill-style variants 24.53-56.41% ("neural synthesis techniques ... learn intended programs from a single example in only 24-36% of scenarios") — [Kalyan et al. 2018](https://arxiv.org/abs/1804.01186)
- RobustFill (Devlin et al., ICML 2017): 92% generalization accuracy on 205 real FlashFill instances (4 observed examples, beam 1000) vs 34% for the previous neural system; all beam candidates are executed and "if multiple program candidates are consistent with all observed examples, the program with the highest model score is taken" — [Devlin et al. 2017](https://arxiv.org/abs/1703.07469)
- Li and Ellis (NeurIPS 2024), fine-tuned 33B code LLM on FlashFill-style text editing with rejection sampling against the examples: generalization accuracy 82% vs oracle accuracy 88% (a correct program was generated), i.e. about 6 pp lost to choosing an example-consistent but wrong program; classic FlashFill 33%. "Metrics of program length correlate poorly with problem difficulty"; description length under the fine-tuned posterior predicts success better than program size or prior description length — [Li & Ellis 2024](https://arxiv.org/abs/2406.08316)
- Base rate of spurious programs with several examples: on ARC (typically 2-4 training pairs) "about 9% of samples that fit the training examples are false-positives", and about half of that 9% are on problems where most probability mass is still on the correct output so a majority vote over outputs fixes them — [Li et al. 2024](https://arxiv.org/abs/2411.02272)
- Overfitting theory (Padhi et al., CAV 2019): the paper defines a "potential for overfitting" that "captures the number of spurious candidates"; no-free-lunch theorems show that for an expressive enough grammar every learner needs more than m examples on some problem, and the potential for overfitting grows with grammar expressiveness. Empirically, in 65% of grammar pairs LoopInvGen got slower with the more expressive grammar (180 benchmarks); adding one operator made CVC4 fail on 21 benchmarks it solved with smaller grammars. Mitigation by "hybrid enumeration" (interleaving grammars from least to most expressive): 115 -> 117 benchmarks solved, 2191 s -> 429 s — [Padhi et al. 2019](https://arxiv.org/abs/1905.07457)
- Pragmatic ranking (Pu et al., NeurIPS 2020): score a program by whether "a rational speaker would chose this particular specification to communicate that program" (Rational Speech Acts). User study, N=48: users needed fewer example symbols to communicate a target to the pragmatic synthesizer, mean difference 2.8 moves (95% CI 2.35-3.22, paired t=12.877, p<.0001); 77% of subjects found it easier — [Pu et al. 2020](https://arxiv.org/abs/2007.05060)
- Training on pragmatically chosen examples (Vaduguru, Fried, Pu, ICLR 2024; regex synthesis): outperforms models trained without choosing pragmatic examples "by 23% (a 51% relative increase)" and matches supervised training on human-provided pragmatic examples — [Vaduguru et al. 2024](https://arxiv.org/abs/2311.05740)
- Relational perturbation properties (An, Singh, Misailovic, Samanta, POPL 2020): augment the user's examples with properties relating input changes to output changes (permutation invariance/preservation, rotation, additive/multiplicative value invariance/preservation, permutation transposition). 197 benchmarks (143 Sketch, 40 SyGuS-CLIA, 14 hand-made; 1970 synthesis instances): "for benchmarks that satisfy some relational perturbation properties, SketchAX improves the success rate of Sketch by 61%, 60% and 59%, respectively, for the three UIs" — [An et al. 2020](https://par.nsf.gov/servlets/purl/10140045)
- Natural language plus ONE example (Manshadi, Gildea, Allen, AAAI 2013; text editing): with a single example the shortest-program PbE baseline reaches 10.3% task accuracy / 19.7% example accuracy; a learned probabilistic prior over functions and arguments 18.6% / 31.1%; adding the NL description 42.2% / 60.3%. "With only one input/output there are many possible programs ... and the shortest program heuristic does not seem to be a good predictor." Accuracy saturates near 76% with more examples — [Manshadi et al. 2013](https://www.cs.rochester.edu/~gildea/pubs/manshadi-aaai13.pdf)
- Multi-modal regex synthesis (Regel; Chen et al., PLDI 2020), 322 tasks: 80% with NL + examples (within four interaction rounds) vs 43% NL-only (DeepRegex) vs 26% examples-only — [Chen et al. 2020](https://arxiv.org/abs/1908.03316)
- AlgoLisp (Polosukhin and Skidanov, 2018): description-only seq2seq 54.1% test accuracy, description-only seq2tree 61.0%; search that also checks the I/O examples lifts these to 72.3% and 85.8%; examples-only neural model 2.2% (12.8% with search) — [Polosukhin & Skidanov 2018](https://arxiv.org/abs/1802.04335)
- Shared-blind-spot mechanism: neural synthesizers trained on synthetic program/example distributions generalize poorly to other distributions, "often achieving less than 5% generalization accuracy"; the authors show the bias comes from the data-generation procedure over both programs and inputs — [Shin et al. 2019](https://arxiv.org/abs/1912.12345)
- MDL as the only prior: CompressARC, a 76K-parameter network with no pretraining, minimizes description length at inference time and solves 20% of ARC-AGI-1 evaluation puzzles (34.75% of training puzzles) — [Liao & Gu 2025](https://arxiv.org/abs/2512.06104)

### Inferences
- The two feature families with measured value are (a) corpus statistics of program components (Singh-Gulwani) and (b) regularity of the candidate's outputs and traces on unlabeled inputs (Ellis-Gulwani). The brief's failed "structure prior" belongs to family (a); family (b) was the stronger one on held-out tasks in both Ellis-Gulwani domains and needs no language model: the 24 probe inputs already exist, so output-descriptor features (type and format uniformity across probes, share of exceptions, constant or input-echo outputs, output range/length relation to input) can be computed for every example-consistent candidate.
- Pure Occam/MDL is a weak selector whenever it was measured against a learned ranker (0% vs 74% one-example success; 10.3% vs 42.2%; program length "correlates poorly" in Li-Ellis). It is still a useful *search-order* device: Padhi et al.'s result implies that every operator added to the engine library raises the number of spurious example-consistent programs, and that enumerating sub-grammars from least to most expressive (accepting the first consistent program found in the smallest grammar) is the principled counter-measure.
- Pragmatic scoring is implementable without an LLM here: treat the task author's example as chosen to be informative, and down-weight candidates for which that example would be an uninformative or coincidental choice (for instance the example only exercises a degenerate branch of the candidate, while most probe inputs would have distinguished it from simpler alternatives).
- Li-Ellis's 82/88 = 93% "selection efficiency" (solved / tasks where a correct program was generated) with a 33B model is a realistic reference point. Reading the brief's ranges as paired by judge (strict: 58 solved of 62 reachable; lenient: 69 of 76), the system already selects at 94% and 91% — at or near that reference, so the remaining error is mostly reach (no correct candidate), not selection.

### Gaps
- No PBE-ranking paper evaluates the exact setting of the brief (one sentence + one example + a general Python-like operator DSL); all gains above are for string, regex, layout or bit-vector DSLs, mostly with large real-task corpora for training the ranker.
- An et al. report "improves the success rate by 61%" without my confirming whether that is absolute or relative.
- Could not retrieve Raza et al. (IJCAI 2015, NL + examples) or FlashFill++ ranking details; Laich et al. (ICLR 2020) numbers are unverified (see section 2).
- No study isolates which individual output features carry the Ellis-Gulwani gain.

## 2. Interactive and active disambiguation: how much does one extra example or one answered question buy?

### Takeaway
One extra bit of user evidence is worth far more than any offline reranker: a second example lifts learned-ranking FlashFill from 74% to 89% of tasks, one answered test query lifts Codex pass@1 on MBPP from 48.2% to 70.7% (TiCoder), and clarification questions add about 10 pp for GPT-4 on MBPP-sanitized. Choosing the question well (minimax over sampled consistent programs) saves 14-54% of questions versus random ones, and a bounded-error stop rule kept the error rate at 0.6%.

### Cited Findings
- Oracle-guided synthesis (Jha, Gulwani, Seshia, Tiwari, ICSE 2010): after finding a program consistent with the examples, solve for a *distinguishing input* — one on which another consistent program gives a different output — ask the I/O oracle for the output, add it as an example, and stop when no distinguishing input exists (the program is then semantically unique among the components). In the worked bit-vector example four further oracle queries pin down the intended program — [Jha et al. 2010, tech report version](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2010/EECS-2010-15.pdf)
- FlashFill's interaction model highlights the cells where the consistent programs disagree, so the user inspects exactly the ambiguous inputs — [Gulwani 2011](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/popl11-synthesis.pdf)
- Mayer et al. (UIST 2015) compare a baseline PBE interface (BI) with Program Navigation (browse alternative programs, PN) and Conversational Clarification (system asks about inputs on which top candidates disagree, CC): both "significantly reduce the number of errors ... without any difference in completion time" (BI+CC vs BI: W=78.5, p=0.01; BI+PN vs BI: W=99.5, p=0.06; no significant difference between the two) — [Mayer et al. 2015](https://www.microsoft.com/en-us/research/wp-content/uploads/2018/01/uist2015-disambiguation.pdf)
- Le, Perelman, Polozov et al. (2017): "over 80% of the FlashFill benchmarks required only two learning iterations, and over 90% of the FlashExtract benchmarks required three or fewer"; the framework unifies CEGIS counterexamples and distinguishing inputs as query types — [Le et al. 2017](https://arxiv.org/abs/1703.03539)
- Value of the second example under a learned ranker: 74% of FlashFill tasks from 1 example, 89% from at most 2 — [Singh & Gulwani 2015](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/06/cav15-1.pdf)
- Question selection (Ji, Liang, Xiong, Zhang, Hu, PLDI 2020): SampleSy samples programs from the remaining version space and picks the question by "minimax branch" (the question whose worst-case answer removes the most samples); EpsSy stops early when the recommendation survives enough "challengeable" questions. Random questions need 38.5% (program repair) and 13.9% (string) more questions than SampleSy, and 54.4% / 35.0% more than EpsSy; EpsSy's overall error rate is 0.60% — [Ji et al. 2020](https://zhenjiang888.github.io/pub/pldi20.pdf)
- TiCoder (Lahiri et al., 2022): the system proposes a test (input plus predicted output) and the user answers yes/no/undefined; candidates are pruned and re-ranked. Simulated with the reference solution as the user: MBPP pass@1 48.24% -> 70.73% after ONE query and 85.95% after five (+22.49 / +37.71 pp); HumanEval 30.49% -> 55.28% -> 84.47% (+24.79 / +53.98 pp). In the same setup CodeT (no user) reached 63.70% on MBPP and 58.54% on HumanEval — [Lahiri et al. 2022](https://arxiv.org/abs/2208.05950)
- TiCoder user study and scale-up (Fakhoury et al., 2024): 15 programmers; participants were "significantly more likely to correctly evaluate AI generated code" with less cognitive load; with four LLMs and two datasets the average absolute pass@1 improvement within 5 interactions was 45.97% — [Fakhoury et al. 2024](https://arxiv.org/abs/2404.10100)
- ClarifyGPT (Mu et al., 2023): a "code consistency check" runs sampled solutions on generated inputs and asks clarifying questions only when their outputs are not identical. With human answers GPT-4 goes 70.96% -> 80.80% on MBPP-sanitized and 51.52% -> 60.19% on MBPP-ET; averaged over four benchmarks (HumanEval, HumanEval-ET, MBPP-sanitized, MBPP-ET; the automated runs use simulated user answers) GPT-4 68.02% -> 75.75% and ChatGPT 58.55% -> 67.22% — [Mu et al. 2023](https://arxiv.org/abs/2310.10996)
- When to ask (Zhang and Choi, 2023): an intent-entropy estimate (Intent-Sim) selects which inputs to clarify; "when only allowed to ask for clarification on 10% of examples, our system is able to double the performance gains over randomly selecting examples to clarify" — [Zhang & Choi 2023](https://arxiv.org/abs/2311.09469)
- Models rarely ask on their own: on HumanEvalComm "more than 60% of responses from Code LLMs still generate code rather than ask questions" when descriptions are made ambiguous, inconsistent or incomplete — [Wu & Fard 2024](https://arxiv.org/abs/2406.00215)
- Semantic collapse limits disagreement-triggered questions: LLM samples "frequently collapse onto a single incorrect interpretation", affecting "over 10% of tasks in MBPP, 3% in HumanEval, and 32% of LiveCodeBench"; at k=10 samples, 50.3-73.0% of deliberately underspecified MBPP tasks yield semantically indistinguishable programs — [Richter et al. 2026](https://arxiv.org/abs/2607.01953)
- Distinguishing inputs without a user, answered by execution and an LLM judge (S*, 2025): clusters candidates, generates distinguishing inputs for cluster pairs, and picks by the execution results; Qwen2.5-7B-Instruct + S* beats Qwen2.5-32B-Instruct by 10.7% on LiveCodeBench, gains of 8.4-18.2% for the Qwen2.5-Coder series, +9.9% over majority voting for the best model — [Li et al. 2025](https://arxiv.org/abs/2502.14382)
- Learned output oracle (Laich, Bielik, Vechev, ICLR 2020): "reduce the problem of selecting which program generalizes well to the simpler task of deciding which output is correct" by generating extra inputs and letting a neural model choose among candidate outputs; trained on program outputs rather than ground-truth programs. Abstract checked; I recall an accuracy gain of roughly 35% -> 71% for an Android layout synthesizer but could not open the paper [UNVERIFIED] — [Laich et al. 2020](https://openreview.net/forum?id=BJl07ySKvS)

### Inferences
- The per-query gains (TiCoder +22 to +25 pp for the first answer; 74% -> 89% for a second example) are an order of magnitude larger than the brief's remaining selection headroom of 4-7 tasks (4-7 pp), so in any deployment with a user the highest-value mechanism is one well-chosen question, not a better offline ranker.
- The system already has what the question selector needs and no LLM is required: example-consistent candidates clustered by behaviour on probe inputs, with calibrated cluster weights. The SampleSy rule reduces to "show the probe input that splits the weighted candidate set most evenly in the worst case"; EpsSy's stop rule reduces to "stop when the top cluster's calibrated probability exceeds 1 - epsilon".
- A cheap offline proxy for "what would a second example buy" is available on existing data: give the system a second assert as an additional example and re-measure under the strict judge. This yields the system's own analogue of the 74% -> 89% curve and an upper bound for query-based disambiguation.
- Richter et al.'s collapse result predicts that disagreement-triggered questions will miss the cases where all candidates share the same wrong reading (the brief's shared blind spots), so question triggering should also fire on low calibrated confidence, not only on observed disagreement.

### Gaps
- No interactive study uses sub-100M-parameter generators; all LLM-era numbers are for Codex/GPT-class models whose candidate pools are much richer.
- Simulated-user results use the reference solution as a perfect oracle; real users answer some test queries wrongly, and I found no measurement of that error rate beyond the 15-person TiCoder study.
- Laich et al. numbers unverified; EpsSy's absolute question counts per task were not extracted (only relative savings).

## 3. Execution-based reranking with generated tests or inputs: which methods work when the test or verification generator is weak, and is there evidence on tiny models predicting outputs for new inputs?

### Takeaway
Methods that need only *inputs* (cluster candidates by behaviour, pick the heaviest or most central cluster: AlphaCode clustering, MBR-exec, functional overlap, differential testing) keep working without any trustworthy output oracle; methods that need *expected outputs* or a *learned verifier* degrade with the generator: even GPT-4o-class models write a fully correct test suite for only 44-59% of problems, a weak model's own tests give CodeT less than half the gain of a strong model's tests, and learned verifiers "drastically" lose accuracy with little training data. For tiny models predicting outputs (transduction) there is evidence only inside closed DSLs and grid puzzles, not for general Python.

### Cited Findings
#### Input-only behavioural agreement (no output oracle)
- AlphaCode (Li et al., 2022): filter on the examples in the problem statement (removes about 99% of samples), then cluster the survivors by their outputs on inputs from a separately trained test-input generation model; "selecting one solution from each cluster from largest to smallest performed best, perhaps because there are many ways solutions can be incorrect while correct solutions tend to behave the same". Build-up ablation, clustering step: 10@100K solve rate 21.5% -> 24.1%, 10@1M 24.2% -> 28.4%, but 10@1K 12.4% -> 12.2% (no gain when few candidates survive) — [Li et al. 2022](https://arxiv.org/abs/2203.07814)
- AlphaCode 2 (2023 tech report): example filtering removes about 95% of samples; survivors are clustered by behaviour, only the 10 largest clusters are kept, and a fine-tuned scoring model picks the best sample in each; 43% of Codeforces problems solved within 10 attempts vs 25% for AlphaCode — [AlphaCode 2 report](https://storage.googleapis.com/deepmind-media/AlphaCode2/AlphaCode2_Tech_Report.pdf)
- MBR-exec (Shi et al., EMNLP 2022): choose the sample with minimum Bayes risk under the loss "do the two programs differ on any test input"; MBPP 58.2 +/- 0.3 vs 47.3 +/- 2.5 greedy and 47.7 +/- 1.5 random sample (Codex, 25 of 125 samples); it "outperforms all no-execution baselines ... even when it has no access to ground-truth outputs" — [Shi et al. 2022](https://arxiv.org/abs/2204.11454)
- Functional overlap (SRank; To, Nguyen, Bui, 2023): model the overlap between solution clusters; HumanEval pass@1 69.66% (Codex002), 75.31% (WizardCoder), 53.99% (StarCoder), 60.55% (CodeGen), about 6.1% above CodeT and Coder-Reviewer on average, and "even in scenarios with a limited number of sampled solutions and test cases" — [To et al. 2023](https://arxiv.org/abs/2311.03366)
- DiffCodeGen (May 2026): coverage-guided differential testing among candidates, "without invoking any additional LLM inference" at selection time; candidates act as pseudo-oracles for one another. Gains of +0.5 to +13.5 pp pass@1 on LiveCodeBench across four LLMs, larger for weaker baselines — [He et al. 2026](https://arxiv.org/abs/2605.20473)
- ProbeGen (Allamanis and Yin, 2025): LLM-searched counterexample inputs; clustering samples by probe behaviour as "semantic self-consistency" improves pass@1 by about 10% — [Allamanis & Yin 2025](https://arxiv.org/abs/2502.18473)
- Incoherence (Valentin, Madadi, Sapia, Boehme; arXiv 2025, AAAI 2026 [snippet for venue]): the probability that two programs sampled for the same task behave differently lower-bounds the error; non-zero incoherence detects 69% (MBPP) and 66% (HumanEval) of tasks with non-zero error with no false positives; ranking 16 LLMs by incoherence matches ranking by 1 - pass@1 with Spearman 0.92-0.94 — [Valentin et al. 2025](https://arxiv.org/abs/2507.00057)

#### Generated tests with expected outputs
- CodeT (Chen et al., ICLR 2023): dual execution agreement (RANSAC-style consensus sets of programs and tests). code-davinci-002: HumanEval 47.0% -> 65.8%, MBPP 58.1% -> 67.7%, APPS-introductory 27.2% -> 34.6%, CodeContests 0.7% -> 2.1% — [Chen et al. 2022](https://arxiv.org/abs/2207.10397)
- CodeT with weak generators: with their OWN generated tests InCoder-6B reaches 20.6% (+4.2) and CodeGen-16B 36.7% (+7.0) on HumanEval, 34.4% (+13.1) and 49.5% (+7.1) on MBPP; replacing the tests by code-davinci-002's raises the same models to 26.8% and 47.7% (HumanEval) and 50.3% and 60.0% (MBPP), i.e. a further +6.2 to +15.9 pp from test quality alone. The authors attribute the difference to test accuracy and "toxicity": "the proportions of toxic test cases for Codex models are smaller than CodeGen/InCoder" — [Chen et al. 2022](https://arxiv.org/abs/2207.10397)
- How unreliable self-generated tests are (Chen et al., 2025): share of tasks whose whole generated suite is correct — GPT-4o 59.15% (HumanEval) / 58.73% (MBPP), Claude-3.5-Sonnet 56.71% / 58.47%, LLaMA-3-70B 49.39% / 51.85%, Qwen2.5-Coder-7B 44.50% / 44.44%; individual expected outputs are right 77-90% of the time and inputs 91-98%. "Testing on self-generated tests is more likely to result in false negative labels than true negative ones" — [Chen et al. 2025](https://arxiv.org/abs/2501.12793)
- Test accuracy on harder problems: 57.95% for a GPT-4 test agent on LeetCode-hard, 71.79% when inputs and outputs are generated separately and outputs are computed with an interpreter (TestChain) — [Li & Yuan 2024](https://arxiv.org/abs/2404.13340)
- LLM oracles "do not provide a strong oracle correctness signal" (below 50% accuracy in some settings) and are better at generating oracles than judging given ones (up to 13.29% more accuracy) — [Konstantinou et al. 2024](https://arxiv.org/abs/2410.21136)
- Treating tests as equally fallible: MPSC builds a 3-partite consistency graph over solutions, specifications and tests (ChatGPT: HumanEval +15.91%, MBPP +6.43%, CodeContests +9.37%) — [Huang et al. 2023](https://arxiv.org/abs/2309.17272). B4 derives the Bayes-optimal selection from the pass matrix under priors: up to 50% relative improvement over the strongest heuristic "in the most challenging situations where there are few correct solutions" (12% on average); it assumes at least one candidate is correct — [Chen et al. 2024](https://arxiv.org/abs/2409.08692)
- Weighting tests without knowing which code is right (ACES, April 2026): leave-one-out AUC of each test against the ranking induced by the others. Same GPT-3.5 pass matrix on HumanEval: MBR-exec 72.96, CodeT 78.05, majority voting 80.49, ACES-O 84.15 pass@1 (direct 68.38); the gain over majority voting grows from +3.66 (HumanEval) to +4.88 (HumanEval+) "when misleading tests are more prevalent" — [Sun et al. 2026](https://arxiv.org/abs/2604.03922)
- More and better tests: CodeRM-8B (scaling the number of generated tests) +18.43% for Llama3-8B, +4.95% for Llama3-70B, +3.42% for GPT-4o-mini on HumanEval+ — [Ma et al. 2025](https://arxiv.org/abs/2501.01054). CURE co-trains coder and tester by RL, +5.3% accuracy and +9.0% best-of-N — [Wang et al. 2025](https://arxiv.org/abs/2506.03136). BACE (2026) treats tests as "noisy sensors" with Bayesian belief updates anchored on the public examples — [Silva & Perera 2026](https://arxiv.org/abs/2603.28653)
- Strong reference oracle instead of tests (ALGO): an LLM-written brute-force solution is correct "for 88% of the cases" and gives 8x Codex's and 2.6x CodeT's one-submission pass rate on CodeContests — [Zhang et al. 2023](https://arxiv.org/abs/2305.14591)
- Filtering on the given tests remains the largest single effect: DOCE calls "filtering based on trial unit tests" a "simple and effective strategy that has often been overlooked" — [Li et al. 2024](https://arxiv.org/abs/2408.13745)

#### Learned verifiers and likelihood rerankers
- LEVER (Ni et al., ICML 2023): a verifier reads (description, program, execution result) and is combined with generator probability; +4.6 to +10.9% over execution-pruned baselines with code-davinci-002. Verifiers are T5-base/T5-large/RoBERTa-large. Removing the execution result costs 6.6 (WikiTQ), 5.6 (MBPP), 3.0 (Spider), 1.2 (GSM8k) points; "while verification can be learned with only hundreds of examples, the performance of finetuned T5 models drastically drops when less training examples are available"; fewer candidates (50 -> 10) costs 1.8-5.2 points — [Ni et al. 2023](https://arxiv.org/abs/2302.08468)
- CodeRanker (Inala et al., NeurIPS 2022): a non-executing ranker trained to predict the execution outcome, including error type; Codex pass@1 26% -> 32% on HumanEval and 36% -> 42% on MBPP; a GPT-Neo-125M ranker gives 36.8% where a CodeBERT ranker gives 39.6% (same Codex candidates) — [Inala et al. 2022](https://arxiv.org/abs/2206.03865)
- Coder-Reviewer (Zhang et al., ICML 2023): rerank by p(program | description) x p(description | program) using prompting of large code models; "up to 17% absolute accuracy gain" over coder-only likelihood, and with executability filtering it "can often outperform the minimum Bayes risk method" — [Zhang et al. 2022](https://arxiv.org/abs/2211.16490)
- Rankers without tests fall short for small generators: "in scenarios where unit-tests are unavailable, a ranking-based selection of candidates from the smaller model falls short of the performance of a single output from larger ones"; ranking "improves ... with the size of the ranking LLM" — [Hassid et al. 2024](https://arxiv.org/abs/2404.00725)
- Outcome reward models (neural rankers) trade accuracy for speed: with staged pruning they reach 11.64x throughput "at a cost of 8.26% accuracy relative to full test-suite verification" — [Orlanski et al. 2025](https://arxiv.org/abs/2506.10056). Other trained rankers: Top Pass (+32.9% relative pass@1 on CodeContests over the prior ranker) — [Top Pass 2024](https://arxiv.org/abs/2408.05715); RankEF (ranker trained jointly on execution feedback) — [Sun et al. 2024](https://arxiv.org/abs/2408.13976); AceCoder reward models trained on 87K synthesized-test tasks — [Zeng et al. 2025](https://arxiv.org/abs/2502.01718)
- Calibrated verification from sampled programs AND sampled specifications (Li, Key, Ellis; "Toward Trustworthy Neural Program Synthesis"): a logistic regressor over a handful of features (input-output spec pass rate, relation-spec pass rate under fuzzing, cluster size = number of other programs satisfying the same specs, their ordinal ranks, normalized log-probability); "we can achieve 100% precision on HumanEval (zero error rate), in exchange for dropping our recall from 93.4% to 44.4%" — [Li, Key & Ellis 2022](https://arxiv.org/abs/2210.00848)

#### Transduction (predicting outputs directly) as verifier or second view
- RobustFill compared an output-predicting "induction" model with the program-generating model on the same data: 53% vs 81% generalization accuracy (all six held-out outputs exactly right); induction "has no concept of consistency" with the observed examples — [Devlin et al. 2017](https://arxiv.org/abs/1703.07469)
- ARC (Li et al., 2024): induction (write a program) and transduction (predict the output grid) "are strongly complementary, even when trained on the same problems"; in one matched setting induction 18.78%, transduction 15.25%, ensemble (induction first, transduction as fallback) 26.50%; the scaled-up ensemble scores 56.75% on the public validation split — [Li et al. 2024](https://arxiv.org/abs/2411.02272)
- Tiny from-scratch transducers on grid puzzles: TRM, 7M parameters, 45% on ARC-AGI-1 and 8% on ARC-AGI-2 — [Jolicoeur-Martineau 2025](https://arxiv.org/abs/2510.04871); HRM, 27M parameters trained on about 1000 tasks, 40.3% on ARC-AGI-1 — [Wang et al. 2025](https://arxiv.org/abs/2506.21734)
- General Python is much harder: on CRUXEval output prediction GPT-4 scores 63% (81% with chain of thought, per the abstract), Code Llama 34B 46%, and "the best open-source models only achieve ... 44% on CRUXEval-O" — [Gu et al. 2024](https://arxiv.org/abs/2401.03065)
- Transductive test outputs with one small LLM (CoTT, Findings of EMNLP 2026; Llama-3.1-8B): expected outputs come from executing general programs ("inductive") and, only when their agreement is low, from programs written for that exact input ("transductive"); top-1 reranking accuracy 62.5 on HumanEval-R+ and 61.6 on MBPP-R+, at lower cost than always-transductive — [Lee et al. 2026](https://aclanthology.org/2026.findings-emnlp.1715.pdf)
- Natural-language hypotheses as an intermediate view (Hypothesis Search): 30% on a 100-task ARC subset vs 17% direct prompting; 33% when a human selects among generated hypotheses — [Wang et al. 2024](https://arxiv.org/abs/2309.05660)

### Inferences
- Availability without a strong LLM, by signal: (1) filtering on the given example — available, largest effect in every pipeline; (2) behavioural clustering on generated inputs — available, needs only an input generator (grammar- or mutation-based) and enough diverse candidates; this is exactly the signal that worked in the brief; (3) expected-output tests (CodeT, MPSC, B4, ACES, CodeRM) — NOT available: they presuppose a model that predicts correct outputs most of the time, and even 7B-70B models produce a fully correct suite for only 44-52% of basic tasks; (4) learned verifier over execution results — the brief's negative result matches LEVER's low-data collapse and CodeRanker's size sensitivity; a verifier needs thousands of labelled (task, candidate, result) triples and typically a pretrained encoder; (5) reviewer P(description | program) — published gains are with Codex-class models; nothing suggests a 12M model can score descriptions reliably; (6) transduction model in the system's own operator DSL — unproven at this scale but the only "second opinion" with published small-model precedent (RobustFill induction, TRM/HRM), and Li et al. show its errors differ from induction's.
- AlphaCode's ablation (no clustering gain at 1K samples, +2.6 to +4.2 pp at 100K-1M) suggests cluster-mass voting needs many surviving candidates; with dozens of survivors the cluster weights should come from calibrated per-candidate scores rather than raw counts.
- B4, ACES and the incoherence bound all formalize the same condition: agreement helps when correct candidates behave identically while wrong ones scatter. They do not help when wrong candidates coincide (section 4).

### Gaps
- No paper found that evaluates CodeT/MBR-style reranking with generators below about 100M parameters, or with a non-neural enumerator as one of the candidate sources.
- No evidence that a roughly 10M-parameter model can predict outputs of arbitrary short Python programs; the tiny-model results are for grid puzzles and string DSLs.
- CodeT's exact test-case accuracy per model is only shown as a density plot; I could not extract numbers.
- CoTT's baselines table was only partially read; its relative gains over CodeT-style baselines are not quoted here.

## 4. When is agreement evidence? Error independence, diversity, multi-view learning, and how to make models trained on the same small data err independently

### Takeaway
Agreement is evidence only to the extent that the agreeing parties would not make the *same* mistake: voting amplifies whatever the majority tendency is (helping where members are right more often than not, hurting on hard items), and co-training theory bounds error by cross-view disagreement only under conditional independence of the views given the truth. Empirically, re-seeding the same pipeline produces limited independence; changing the training data, the input view or the output representation produces much more.

### Cited Findings
#### Voting and correlated errors
- Dietterich (2000): "A necessary and sufficient condition for an ensemble of classifiers to be more accurate than any of its individual members is if the classifiers are accurate and diverse"; with independent errors at rate p < 1/2 the majority vote's error is a binomial tail, but "if the individual hypotheses make uncorrelated errors at rates exceeding 0.5, then the error rate of the voted ensemble will increase as a result of the voting" — [Dietterich 2000](https://web.engr.oregonstate.edu/~tgd/publications/mcs-ensembles.pdf)
- Compound LLM systems (Chen et al., 2024): the accuracy of Vote and Filter-Vote "can first increase but then decrease as a function of the number of LM calls" because "more LM calls lead to higher performance on 'easy' queries, but lower performance on 'hard' queries" — [Chen et al. 2024](https://arxiv.org/abs/2403.02419)
- Self-consistency (Wang et al., ICLR 2023): majority vote over sampled reasoning paths, GSM8K +17.9%, SVAMP +11.0%, AQuA +12.2%; the share of samples agreeing with the final answer "is highly correlated with accuracy" and can serve as an uncertainty estimate — [Wang et al. 2022](https://arxiv.org/abs/2203.11171)
- Correlated LLM errors (Kim, Garg, Peng, Garg, ICML 2025): "models agree 60% of the time when both models err" on a multiple-choice leaderboard where chance would be 1/3; more accurate models and models from the same provider or architecture have more correlated errors — [Kim et al. 2025](https://arxiv.org/abs/2506.07962)
- "Model mistakes are becoming more similar with increasing capabilities"; LLM judges favour models similar to themselves, and gains from training on another model's labels depend on "complementary knowledge" — [Goel et al. 2025](https://arxiv.org/abs/2502.04313)
- CNNs are "remarkably consistent with one another" in which inputs they get wrong "irrespective of architecture" (error consistency, a chance-corrected kappa) — [Geirhos et al. 2020](https://arxiv.org/abs/2006.16736). ImageNet models "agree in their predictions well beyond what we can conclude from their accuracy levels alone" — [Mania et al. 2019](https://arxiv.org/abs/1905.12580)
- For code: a single LLM's samples collapse onto one wrong reading in over 10% of MBPP tasks, so within-model agreement gives a false signal of correctness there — [Richter et al. 2026](https://arxiv.org/abs/2607.01953)
- Diversity measures are a weak guide: after studying ten measures, Kuncheva and Whitaker conclude their "results raise some doubts about the usefulness of diversity measures in building classifier ensembles in real-life pattern recognition problems" — [Kuncheva & Whitaker 2003](https://link.springer.com/article/10.1023/A:1022859003006)

#### Sources of diversity
- Random initialization: deep ensembles need only random initialization and data shuffling; bootstrap resampling "can sometimes hurt performance since a base learner trained on a bootstrap sample sees only 63% unique data points" — [Lakshminarayanan et al. 2017](https://arxiv.org/abs/1612.01474). "Random initializations explore entirely different modes, while functions along an optimization trajectory or sampled from the subspace thereof cluster within a single mode predictions-wise" — [Fort et al. 2019](https://arxiv.org/abs/1912.02757)
- Snapshot ensembles (cyclic learning rate, one training run) reach 3.44% / 17.41% error on CIFAR-10 / CIFAR-100 — [Huang et al. 2017](https://arxiv.org/abs/1704.00109); by Fort et al.'s result their members are less decorrelated than independent runs.
- Bagging helps unstable learners ("the vital element is the instability of the prediction method"; test error reductions of 6% to 77% for trees) — [Breiman 1996](https://link.springer.com/article/10.1007/BF00058655)
- Training methodology matters most: "model pairs that diverge more in training methodology (in order: reinitializations, hyperparameters, architectures, frameworks, datasets) produce increasingly uncorrelated errors"; two ImageNet models of 76.5% and 75.5% accuracy trained very differently ensemble to 83.4% (+7 pp) — [Gontijo-Lopes et al. 2021](https://arxiv.org/abs/2110.12899)
- Explicit decorrelation: the ambiguity decomposition (ensemble error = average member error - ambiguity; "a combination of the output of several networks ... is only useful if they disagree on some inputs", and ambiguity can be estimated on unlabeled data) — [Krogh & Vedelsby 1995](https://papers.nips.cc/paper/1994/file/b8c37e33defde51cf91e1e03e51657da-Paper.pdf); negative correlation learning as control of the bias-variance-covariance trade-off — [Brown et al. 2005](https://www.jmlr.org/papers/volume6/brown05a/brown05a.pdf)
- Diversity through disagreement on unlabeled inputs: DivDis learns "a diverse set of hypotheses that achieve low source loss but make differing predictions on target inputs" and then disambiguates with a few labels — [Lee, Yao & Finn 2022](https://arxiv.org/abs/2202.03418); D-BAT "enforces agreement among the models on the training data, but disagreement on the OOD data" — [Pagliardini et al. 2022](https://arxiv.org/abs/2202.04414). Ensemble-aware "oracle" losses give "significantly higher oracle accuracies than classical ensembles" — [Lee et al. 2015](https://arxiv.org/abs/1511.06314)
- Underspecification: pipelines return predictors with "equivalent held-out performance" that "behave very differently in deployment domains", even when only the random seed differs — [D'Amour et al. 2020](https://arxiv.org/abs/2011.03395)

#### Multi-view learning
- Co-training (Blum and Mitchell, 1998) assumes each view suffices for classification and the views are "conditionally independent given the label". Web pages (page text vs anchor text of incoming links), error rates: supervised 12.9 / 12.4 / 11.1 (page / hyperlink / combined) vs co-training 6.2 / 11.6 / 5.0 — [Blum & Mitchell 1998](https://www.cs.cmu.edu/~avrim/Papers/cotrain.pdf)
- Dasgupta, Littman, McAllester (2001): under that assumption "a bound on the generalization error of each of the rules ... in terms of the empirical agreement rate between the two rules", justifying agreement as the training objective — [Dasgupta et al. 2001](https://papers.nips.cc/paper/2001/file/4c144c47ecba6f8318128703ca9e2601-Paper.pdf)
- Weaker conditions: "expansion" of the data distribution suffices for iterative co-training — [Balcan, Blum & Yang 2004](https://papers.nips.cc/paper/2004/file/9457fc28ceb408103e13533e4a5b6bd1-Paper.pdf); with a single view, "if the two classifiers are with large diversity, co-training style algorithms can succeed" (their 2007 result, restated in the 2010 paper) — [Wang & Zhou 2010](https://icml.cc/Conferences/2010/papers/275.pdf)
- Description view vs example view in synthesis: 80% vs 43% vs 26% (Regel), 85.8% vs 54-61% vs 2-13% (AlgoLisp), 60.3% vs 19.7% (Manshadi et al.); see section 1 — [Chen et al. 2020](https://arxiv.org/abs/1908.03316), [Polosukhin & Skidanov 2018](https://arxiv.org/abs/1802.04335), [Manshadi et al. 2013](https://www.cs.rochester.edu/~gildea/pubs/manshadi-aaai13.pdf)
- Induction vs transduction as views: complementary "even when trained on the same problems", stable across seeds (p<.004) — [Li et al. 2024](https://arxiv.org/abs/2411.02272)

#### Agreement as an accuracy estimate
- The disagreement rate between two SGD runs of the same architecture on unlabeled test data tracks test error, which follows if the ensemble is well calibrated — [Jiang et al. 2021](https://arxiv.org/abs/2106.13799); the reproduction warns that "a deep ensemble's calibration can deteriorate as prediction disagreement increases", exactly where the estimate is needed — [Kirsch & Gal 2022](https://arxiv.org/abs/2202.01851)
- Agreement-on-the-line: when in-distribution vs out-of-distribution accuracy is linear across models, pairwise agreement is linear with the same slope, so "without any labeled data, we can predict the OOD accuracy"; it "appears to only hold for neural network classifiers" — [Baek et al. 2022](https://arxiv.org/abs/2206.13089)
- For code generation, incoherence gives a lower bound on error, not an estimate: zero disagreement does not imply correctness — [Valentin et al. 2025](https://arxiv.org/abs/2507.00057); [Richter et al. 2026](https://arxiv.org/abs/2607.01953)

### Inferences
- Likelihood-ratio reading of the brief's findings: when two candidates behave identically on the probes, the evidence for correctness is P(agree | right) / P(agree | wrong). The denominator is the *collision probability on a wrong behaviour*. Inside one model's beam the candidates are near-duplicates, so the collision probability approaches the agreement probability itself and the ratio is about 1 (no evidence, and it can displace the better-scored candidate — consistent with "agreement inside one beam hurt"). Between separately trained coders wrong behaviours scatter more, so the ratio is well above 1 — consistent with what worked. Illustration (my arithmetic, not a measurement): if a second coder reproduces a correct behaviour 60% of the time and the same wrong behaviour 5% of the time, agreement multiplies the odds by 12.
- The 24-coder committee failing on the hardest tasks is the textbook case: under independence, majority accuracy for members at p = 0.3 falls from 0.22 (3 voters) to 0.03 (21) and 0.02 (25), while at p = 0.7 it rises from 0.78 to 0.97 and 0.98 (my computation from the binomial formula Dietterich cites). Plurality over a large space of behaviours is more forgiving than binary majority (wrong answers scatter), but only if errors are not shared — and the brief says engine and coders share blind spots because the coders were trained from the engine's library (the Shin et al. mechanism).
- Ranked by the Gontijo-Lopes ordering, the system's current diversity lever (separate training runs) is the weakest one. Stronger levers that remain feasible at 12M parameters on CPU: (a) different training corpora per coder (disjoint task families or teacher rounds, or one coder trained only on tasks the engine cannot solve); (b) different input views — a description-only coder and an example-only synthesizer are the natural co-training pair, and the rule engine already is an example-view learner; (c) different output representations (program vs direct output prediction; the brief's prefix vs postfix coders are a mild version); (d) an explicit disagreement penalty on unlabeled probe inputs in the style of D-BAT/DivDis, applied only where the training example is still reproduced.
- Following Kuncheva-Whitaker, do not optimize a generic diversity index. Measure the quantity that enters the likelihood ratio directly: on train-side tasks, for each pair of sources, the rate at which their *wrong* example-consistent candidates coincide on the probes, versus the rate at which their right ones do.

### Gaps
- No study measures error correlation between a symbolic enumerator and neural models trained on its outputs; the shared-blind-spot claim rests on the brief plus Shin et al.'s distribution-bias result.
- Negative correlation learning and DivDis/D-BAT are validated for classification and regression; I found no application to program synthesis or sequence generation.
- Nigam and Ghani (2000) on what happens when views are not independent could not be retrieved (PDF extraction failed).
- Classical Condorcet-with-correlation analyses (for example Ladha 1992) were not fetched; the binomial figures above are my own computation.

## 5. Evaluation rigor with few tests: test insufficiency, differential testing against references, input-domain contracts, mutation analysis

### Takeaway
A three-assert judge is known to pass wrong programs at rates of roughly 12-30% on basic-Python benchmarks, and adding about 80x more tests cut reported pass@k by up to 19-29%; but differential testing against a reference is itself unreliable unless probe inputs are restricted by explicit contracts and the references are audited: EvalPlus hand-wrote contracts for 83 of 164 tasks, about a third of mutation-generated inputs in one benchmark were invalid, and about 11% of reference solutions in HumanEval (and of sanitized MBPP tasks) were defective or ill-formed. The brief's "one in six disagree, half of them artifacts" fits both halves of that picture.

### Cited Findings
#### Measured insufficiency of small test suites
- EvalPlus (Liu, Xia, Wang, Zhang, NeurIPS 2023): HumanEval+ has 80x more tests (average 9.6 -> 764.1 per task; 774.8 in a later release); across 26 LLMs pass@k drops "by up-to 19.3-28.9%" and model rankings change (WizardCoder-CodeLlama and Phind-CodeLlama overtake ChatGPT only on HumanEval+) — [Liu et al. 2023](https://arxiv.org/abs/2305.01210)
- EvalPlus construction: ChatGPT writes seed inputs after seeing the ground-truth solution; "type-aware mutation" multiplies them (int/float +/-1; list/tuple/set remove, repeat, insert or replace an element; string remove, repeat or replace a substring; dict remove, update or insert a pair); outputs are judged by "differential testing against the ground-truth implementation"; a greedy set-cover reduction that preserves coverage, killed mutants and killed LLM samples shrinks the suite 47x to 16.1 tests per task — [Liu et al. 2023](https://arxiv.org/abs/2305.01210)
- Contracts: "invalid inputs should not be passed into the function as they can incur undefined behaviors to create false-positives in differential testing"; EvalPlus adopts programming by contract with preconditions written as assertions (for example `assert n > 0`), and "83 out of the 164 programming tasks are annotated with hand-crafted contracts" — [Liu et al. 2023](https://arxiv.org/abs/2305.01210)
- Faulty references: EvalPlus "found 18 defects (11% of problems) even in the original ground-truth in HumanEval": 5 unhandled edge cases, 10 wrong logic, 3 performance problems — [Liu et al. 2023](https://arxiv.org/abs/2305.01210)
- MBPP+ (release notes, read through an automated page summary [snippet]): from about 427 sanitized MBPP tasks, hand verification kept 399 (v0.1.0), wrong reference implementations were fixed, tests grew 35x (3.1 -> 108.5 per task); v0.2.0 "removed some broken tasks (399 -> 378)"; later releases keep "improving contracts & oracle" — [EvalPlus releases](https://github.com/evalplus/evalplus/releases)
- MBPP itself (Austin et al., 2021): 974 crowd-sourced problems with three asserts each; the authors note questions that "lacked detail, were somewhat ambiguous ... or performed unexpected operations in a function that were paired with the provided tests" and hand-verified 426. With extra "challenge" tests on 50 problems, 33 were solved on the normal tests and 29 also on the challenge tests (66% vs 58%), i.e. 4 of 33 task-level solutions (12%) were false positives of the three asserts — [Austin et al. 2021](https://arxiv.org/abs/2108.07732)
- AlphaCode's estimate of false-positive rates (programs that pass all tests but are wrong): APPS 60% (21.0 tests per problem), HumanEval 30% (7.8), raw CodeContests 62% (12.4), CodeContests after adding mutation-generated tests 4% (203.7; 46% "false positive or slow") — [Li et al. 2022](https://arxiv.org/abs/2203.07814)
- ProbeGen (2025): on a common synthesis benchmark, 24.3% of LLM samples that pass the provided unit tests are shown to differ from the ground truth by a counterexample input, 18.7% after correcting for spurious counterexamples — [Allamanis & Yin 2025](https://arxiv.org/abs/2502.18473)
- HardTests (2025): its test synthesis pipeline raises verification precision by 11.22 pp and recall by about 11 pp over existing tests on LLM-generated code — [He et al. 2025](https://arxiv.org/abs/2505.24098)

#### Input validity and the intended domain
- CodeContests+ (2025): agents write an input generator, an input *validator* and an output checker for each problem. Checking the original CodeContests' 1.18 million mutation-generated test cases with the validators, "only 0.79 million of these passed validation, which is 67.1%" (about one third invalid). Test quality is scored against 1.72 million labelled submissions by true-positive rate (flawed tests reject correct code) and true-negative rate (insufficient tests accept wrong code); at equal thresholds it yields twice as many usable problems — [Wang et al. 2025](https://arxiv.org/abs/2506.05817)
- Underspecified task text rather than wrong code: MBUPP rewrites MBPP descriptions to remove ambiguity and accepts any of several assertion sets ("one-to-many testing") because MBPP relies "on test cases to convey the function signature" and has weak alignment between instructions and tests; solvability jumps by 45% on average after both fixes (about 48% for phi, 54% for mistral) — [Uniyal et al. 2024](https://aclanthology.org/2024.findings-emnlp.902/)
- Over 10% of MBPP tasks (3% of HumanEval) make LLMs settle consistently on a reading that the reference does not share — [Richter et al. 2026](https://arxiv.org/abs/2607.01953)
- Executable specifications from language models: GPT-4 produced a test-set-correct postcondition for 96% of EvalPlus problems (158/164; 77% of all generated postconditions were correct), and correct postconditions discriminated up to 81% of buggy mutants on average — [Endres et al. 2024](https://arxiv.org/abs/2310.01831). Property-based tests: a valid and sound test needs 2.4 samples on average with the best model, but only 21% of documented properties get covered — [Vikram et al. 2023](https://arxiv.org/abs/2307.04346). On real codebases, generating preconditions and postconditions is "substantially more challenging than code generation" (best model 20.2% on repository-level tasks) — [CodeSpecBench 2026](https://arxiv.org/abs/2604.12268). LLMs write valid test-case generators "in most cases" but struggle to write targeted ones that expose a given bug — [Cao et al. 2025](https://arxiv.org/abs/2506.06821)

#### Test adequacy and statistics
- Mutation analysis is a valid proxy for fault detection: "a statistically significant correlation between mutant detection and real fault detection, independently of code coverage"; 73% of real faults are coupled to mutants, 17% are not coupled to any — [Just et al. 2014](https://homes.cs.washington.edu/~rjust/publ/mutants_real_faults_fse_2014.pdf)
- Reporting with few tasks: give the standard error next to every score, analyse "question-level paired differences" when comparing two systems, and run a power analysis before trusting an eval; at HumanEval's 164 questions the standard error is about 3 pp — [Miller 2024](https://arxiv.org/abs/2411.00640). Underpowered comparisons are common in NLP and make observed significant differences exaggerated — [Card et al. 2020](https://arxiv.org/abs/2010.06595)

### Inferences
- Position of the brief's numbers: 69 lenient vs 58 strict means 11 of 69 (16%) three-assert passes disagree with the reference on probes. Literature rates for small suites: 12% (MBPP challenge tests), 18.7-24.3% (ProbeGen), 30% (AlphaCode's HumanEval estimate). If about half of the 11 are artifacts, the true strict count lies between 58 and 69 and is probably near 63; both bounds should be reported together with a third "contract-strict" figure.
- Why half are artifacts: probe generators that mutate values without a contract leave the intended domain often (one third of inputs in CodeContests), and about one reference in nine is itself wrong (HumanEval 11%; MBPP+ dropped or repaired a similar share). The EvalPlus recipe transfers directly and needs no LLM at run time: (1) derive a per-task input envelope from the three asserts (types, container shapes, value ranges, emptiness, sign) and treat any input on which the reference raises as out of domain; (2) mutate only within the envelope using the type-aware operators; (3) hand-write a one-line contract for tasks where disagreements persist — 83/164 in EvalPlus suggests about half the tasks need one.
- Reference audit without an LLM: a disagreement where several independently produced candidates agree with each other *against* the reference is a pseudo-oracle signal that the reference or the task text is at fault; these go to manual review and are reported as a separate category instead of being counted as errors.
- A per-task adequacy score is cheap: generate single-edit mutants of the reference and record the share killed by the three asserts versus by the probe set. Tasks where the asserts kill few mutants are the ones where spurious programs survive; this also gives a principled way to reduce 24 probes to the few that matter (EvalPlus's set-cover reduction).
- Statistical resolution on 94 tasks (my computations): 58/94 = 61.7% has a standard error of 5.0 pp and a 95% Wilson interval of 51.6-70.9%. In a paired comparison an exact McNemar test needs at least 6 one-directional flips with none against (p = 0.031; 5-0 gives 0.063, 7-1 gives 0.070, 8-1 gives 0.039), so the brief's maximum selection gain of 4-7 tasks is at the edge of detectability. With the usual normal-approximation sample-size formula for McNemar's test, detecting a net +6 pp (7% flips up, 1% down) at 80% power needs about 170 tasks, and a net +4 pp (5% up, 1% down) about 290.

### Gaps
- No published false-positive rate for the MBPP three-assert judge on outputs of small models or enumerative synthesizers; all rates above are for LLM samples.
- No automated precondition-inference method with a reported accuracy on MBPP-style tasks was found; EvalPlus contracts are hand-written, and classical invariant inference (for example Daikon, PIE) was not surveyed.
- The EvalPlus leaderboard's per-model MBPP vs MBPP+ gaps were not extracted; MBPP+ details come from release notes via a page summary.
- No agreed protocol exists for labelling a probe disagreement as real error vs artifact; the brief's 50/50 split has no direct literature counterpart.

## 6. Selective prediction and calibration for code: which confidence signals are reliable, and how are abstaining systems evaluated?

### Takeaway
Token-probability confidence is poorly calibrated for code out of the box (ECE 0.09-0.73) and generic uncertainty measures fail to track correctness, but execution-grounded agreement statistics fed to a small calibrator are reliable: 100% precision at 44% recall on HumanEval, or two thirds of faulty tasks detected with no false alarms. Abstaining systems are judged by risk-coverage curves (area under the curve, coverage at a fixed risk), abstention precision and recall, and scores that charge more for a wrong answer than for an abstention; guarantees come from thresholds calibrated on held-out tasks.

### Cited Findings
#### Framework and metrics
- Selective classification (Geifman and El-Yaniv, 2017): a pair (classifier, selection function) is characterized by its risk-coverage curve; "selection with guaranteed risk" picks a confidence threshold on held-out data and returns a risk bound that holds with chosen probability, e.g. 2% top-5 ImageNet error "guaranteed with probability 99.9%, and almost 60% test coverage"; the confidence used is simply the maximum softmax response — [Geifman & El-Yaniv 2017](https://arxiv.org/abs/1705.08500)
- Maximum probability is hard to beat: across tasks and IID, out-of-domain and adversarial settings "none of the existing [selective prediction] approaches consistently and considerably outperforms MaxProb" — [Varshney et al. 2022](https://arxiv.org/abs/2203.00211)
- A trained calibrator helps under shift: predicting the QA model's errors from held-out and known out-of-domain data answers 56% of questions at 80% accuracy vs 48% with model probabilities — [Kamath et al. 2020](https://arxiv.org/abs/2006.09462)
- Low-risk operation is expensive: VQA models with over 70% accuracy can answer under 7.5% of questions at 1% risk using softmax scores; a learned multimodal selector raises that from 6.8% to 15.6%. The proposed "Effective Reliability" score "places a larger cost on incorrect answers compared to abstentions" — [Whitehead et al. 2022](https://arxiv.org/abs/2204.13631)
- Area under the risk-coverage curve has known flaws; AUGRC (area under the generalized risk-coverage curve) "can be directly interpreted as the average risk of undetected failures" — [Traub et al. 2024](https://arxiv.org/abs/2407.01032)
- Abstention survey (Wen et al., 2024) lists abstention accuracy, abstention precision ("proportion of model abstain decisions that are correct"), abstention recall, and coverage at a target accuracy, and concludes that "LLMs can struggle with self-evaluation, but combining multiple LLMs has been effective in enhancing abstention" — [Wen et al. 2024](https://arxiv.org/abs/2407.18418)
- AbstentionBench (2025): over 35k unanswerable questions; "reasoning fine-tuning degrades abstention (by 24% on average)" — [Kirichenko et al. 2025](https://arxiv.org/abs/2506.09038)

#### Calibration of code models
- Spiess et al. (2024): across completion, function synthesis and repair, code LMs are "not well-calibrated out of the box", ECE "ranging from 0.09 to 0.73"; Platt scaling "generally improves calibration" but "does require some data to determine the parameters"; self-reflection prompts are inconsistent (best case: skill score from 0 to 0.15) — [Spiess et al. 2024](https://arxiv.org/abs/2402.02047)
- Multicalibration (Campos, Kuschnereit, Ulges, Dec 2025): calibrating per group (problem complexity, code length, programming language) improves skill score by +1.03 over raw token likelihoods and +0.37 over standard calibration on three function-synthesis benchmarks — [Campos et al. 2025](https://arxiv.org/abs/2512.08810)
- Generic uncertainty estimators (semantic-entropy style, with text or code embeddings, or CodeBLEU clustering) "fail to exhibit a correlation between estimated uncertainty and correctness when applied to code"; clustering by behaviour (symbolic execution) restores a significant correlation and supports abstention with "a false positive rate below 0.02%" — [Sharma & David 2025](https://arxiv.org/abs/2502.11620)

#### Agreement- and execution-based confidence
- Speculyzer (Li, Key, Ellis): logistic regression on spec pass rates, cluster size and normalized log-probability gives a calibrated probability; HumanEval precision 100% at recall 44.4% (93.4% without abstention), checked with cross-validation — [Li, Key & Ellis 2022](https://arxiv.org/abs/2210.00848)
- Incoherence: when sampled programs never disagree "the mean error is substantially lower than the average"; non-zero incoherence flags 66-69% of faulty tasks with no false positives — [Valentin et al. 2025](https://arxiv.org/abs/2507.00057)
- HonestCoder: confidence from the multi-modal similarity among generated programs; +27.79% AUROC and +63.74% AUCPR over the best baseline, and fewer wrong programs shown to developers — [Li et al. 2024](https://arxiv.org/abs/2410.03234)
- Share of samples agreeing with the majority answer "is highly correlated with accuracy" (self-consistency) — [Wang et al. 2022](https://arxiv.org/abs/2203.11171)
- Limit: coherent-but-wrong collapse in over 10% of MBPP tasks is invisible to within-model agreement; Richter et al. call it "a fundamental blind spot in disambiguation and correctness estimation techniques that rely on incoherence" — [Richter et al. 2026](https://arxiv.org/abs/2607.01953)

#### Guarantees for generation
- Conformal language modeling (Quach et al., ICLR 2024): calibrate a sampling stop rule and a rejection rule so that the output set "provably contain[s] at least one acceptable response with high probability" — [Quach et al. 2023](https://arxiv.org/abs/2306.10193)
- PAC prediction sets for code (Khakhar, Mell, Bastani, 2023): prediction sets represented as partial programs with holes in the uncertain parts, with a PAC guarantee, on PICARD (SQL) and Codex — [Khakhar et al. 2023](https://arxiv.org/abs/2302.08703)
- Selective code generation with false-discovery-rate control (Jeong, Kim, Park; arXiv 2025, ICML 2026 [snippet for venue]): abstain unless a score exceeds a threshold calibrated so that the share of wrong programs among answered tasks is bounded; correctness labels come from fuzzing-generated unit tests instead of hand-written ones — [Jeong et al. 2025](https://arxiv.org/abs/2505.13553)
- Task abstention (May 2026): Learn-then-Test calibration over sample-test consistency and cluster-entropy thresholds gives P(risk <= alpha) >= 1 - delta for admitted tasks; +26.5% absolute abstention precision over the best existing method; "if no cluster meets this confidence threshold ... the model implies a lack of consensus and abstains" — [Zhou et al. 2026](https://arxiv.org/abs/2605.17029)
- Deciding when to ask instead of abstain: intent-entropy doubles the gain from a 10% clarification budget over random — [Zhang & Choi 2023](https://arxiv.org/abs/2311.09469)

### Inferences
- Signals that are both available here and supported by the literature, in decreasing order of evidence: (1) cross-source behavioural agreement (how many independently trained sources, and the engine, fall in the chosen cluster); (2) the coder's own probability and the margin between the two best clusters (the MaxProb baseline that Varshney et al. found hard to beat); (3) execution health on probes (share of probes raising exceptions, output-descriptor regularity from section 1); (4) reach indicators (search depth at which the engine first found a consistent program, number of consistent candidates). Speculyzer shows that a logistic regression over exactly this kind of feature set is enough; nothing larger is needed, and Platt-style fitting requires only labelled train-side tasks.
- The brief's negative results line up with the calibration literature: a learned verifier over raw execution text is a high-capacity estimator fit on little data, whereas the methods that worked in the literature compress execution evidence into three to six agreement statistics before fitting.
- What a calibration set can certify (my Clopper-Pearson computations, one-sided 95%): risk <= 10% requires, for example, 0 errors in 29 answered tasks, at most 1 in 46, at most 2 in 61, at most 5 in 100, or 10 in 200 (upper bound 8.3%). The 94 held-out tasks alone therefore cannot certify much below 10-15% risk at useful coverage; thresholds should be calibrated on a few hundred train-side tasks and the held-out tasks used once for confirmation.
- Illustrative arithmetic for this system (assumptions, not predictions): if all 36 strict failures are currently answered with a wrong program and an agreement-based detector caught two thirds of them with no false alarms (the Valentin et al. rate), coverage would be 74% and risk among answered tasks 17% instead of 38%; if it also withheld 10% of correct answers, coverage 68% and risk 19%.
- Reporting set for an abstaining version: risk-coverage curve with bootstrap bands; AURC and AUGRC; coverage at risk <= 10% and <= 20%; abstention precision and recall; a penalty score (correct minus c times wrong, for c = 1 and a larger c); reliability diagram with few bins and Brier score (ECE with many bins is too noisy at n = 94).

### Gaps
- No calibration or selective-prediction study exists for code models under 100M parameters or for hybrid symbolic-neural synthesizers.
- Conformal and Learn-then-Test guarantees assume calibration and test tasks are exchangeable; the effect of calibrating on train-side tasks and deploying on held-out MBPP-style tasks is unmeasured.
- For Jeong et al. and Zhou et al. only the method and headline claim were read; achieved FDR levels and coverage were not extracted.
- Whether the "no false positives" property of incoherence survives when the candidate sources share blind spots (the brief's situation) is exactly what Richter et al. dispute; no study quantifies it for non-LLM systems.

## 7. Concrete recommendations: the two or three selection or abstention mechanisms most likely to help, expected gains, and how to measure them

### Takeaway
(1) Replace separate heuristics by one calibrated selector over agreement, likelihood and output-behaviour features; (2) turn its calibrated score into abstention with a risk-coverage report; (3) build a genuinely different second view and, wherever a user or any extra evidence is available, spend it on one distinguishing-input question. Selection alone is capped at the brief's 4-7 tasks and is already about 91-94% efficient, so the realistic selection gain is 1-3 tasks (below what 94 tasks can resolve); abstention can roughly halve the error rate among answered tasks; one answered question is the only mechanism with published double-digit gains.

### Cited Findings
- Behaviour features beat structure features for picking the generalizing program, and all features together beat either (83.5% vs 66.5% vs 57.9%) — [Ellis & Gulwani 2017](https://www.microsoft.com/en-us/research/wp-content/uploads/2017/04/ranking-ijcai17.pdf)
- A logistic model over cluster size, spec pass rates and log-probability yields calibrated correctness probabilities and 100% precision at 44.4% recall — [Li, Key & Ellis 2022](https://arxiv.org/abs/2210.00848)
- Behavioural clustering needs no output oracle and works with weak generators; expected-output tests do not (suite correctness 44-59% even for strong LLMs) — [Shi et al. 2022](https://arxiv.org/abs/2204.11454); [Chen et al. 2025](https://arxiv.org/abs/2501.12793)
- Learned verifiers collapse with little training data — [Ni et al. 2023](https://arxiv.org/abs/2302.08468); rankers for small generators without tests fall short — [Hassid et al. 2024](https://arxiv.org/abs/2404.00725)
- Agreement detects about two thirds of faulty tasks without false alarms when samples are independent enough — [Valentin et al. 2025](https://arxiv.org/abs/2507.00057); it fails under coherent collapse — [Richter et al. 2026](https://arxiv.org/abs/2607.01953)
- Diverging training methodology (data, architecture) decorrelates errors far more than re-seeding — [Gontijo-Lopes et al. 2021](https://arxiv.org/abs/2110.12899); induction and transduction are complementary even on the same training problems — [Li et al. 2024](https://arxiv.org/abs/2411.02272)
- One answered query: MBPP pass@1 48.24% -> 70.73% — [Lahiri et al. 2022](https://arxiv.org/abs/2208.05950); second example: 74% -> 89% of tasks — [Singh & Gulwani 2015](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/06/cav15-1.pdf); minimax question selection saves 14-54% of questions with a 0.6% error rate — [Ji et al. 2020](https://zhenjiang888.github.io/pub/pldi20.pdf)
- More voters hurt on items where the typical member is wrong — [Chen et al. 2024](https://arxiv.org/abs/2403.02419); [Dietterich 2000](https://web.engr.oregonstate.edu/~tgd/publications/mcs-ensembles.pdf)
- Contracts and reference audits are prerequisites for trusting a strict judge — [Liu et al. 2023](https://arxiv.org/abs/2305.01210); paired analysis and power analysis for small evals — [Miller 2024](https://arxiv.org/abs/2411.00640)

#### Mechanism A — one calibrated selector (ranking)
- Design: for every example-consistent candidate compute (i) calibrated coder log-probability, (ii) weight of independent sources in its behaviour cluster, (iii) margin to the runner-up cluster, (iv) output-descriptor regularity and exception rate over in-domain probes, (v) optional pragmatic score; fit a logistic model on train-side tasks with strict labels; choose the top cluster by summed probability.
- Expected gain: bounded by the brief's 4 (strict) to 7 (lenient) tasks. Since selection efficiency is already about 91-94% — the level a 33B model reached in Li-Ellis — a realistic expectation is 1-3 tasks, mostly from the output-behaviour features, which were the complementary family in Ellis-Gulwani. This is an extrapolation from string-DSL results.
- Measure: selection efficiency (solved / tasks with a correct candidate) on train-side folds of at least 200-300 tasks, paired per task against the current selector with an exact McNemar test; then one confirmation run on the 94 held-out tasks, reporting flips in both directions.

#### Mechanism B — abstention on the calibrated score
- Design: answer only if the calibrated probability of the chosen cluster exceeds a threshold fixed on train-side tasks for a target risk (selection with guaranteed risk, or Learn-then-Test); abstain also when no cross-source agreement exists and the coder margin is small.
- Expected effect: no change in the number solved; the error rate among answered tasks could fall from about 38% to the 15-20% range at 65-75% coverage if detection rates near the published two thirds transfer (illustrative arithmetic in section 6). Shared blind spots will leave a residue of confident wrong answers; the size of that residue is the main unknown.
- Measure: risk-coverage curve, AUGRC, coverage at risk <= 10% and <= 20%, abstention precision/recall, all with bootstrap intervals; report certified risk from the calibration set separately from observed risk on held-out tasks.

#### Mechanism C — a decorrelated second view plus one distinguishing question
- Design: (i) make at least one source independent of the engine's library and data: a description-only coder trained on tasks the engine cannot solve, and/or a small transduction model that predicts the output for a probe input from the description and the example; (ii) track, on train-side tasks, the collision rate of wrong behaviours between every pair of sources and weight agreement by the implied likelihood ratio; (iii) when the top two clusters are close, pick the probe input that splits the weighted candidates most evenly (minimax) and either ask the user for its output or, in batch mode, abstain.
- Expected gain: in batch mode, a stronger confidence signal for mechanisms A and B rather than new solved tasks. With one answered question, recovery of most of the selection headroom (4-7 tasks) plus whatever re-running the engine with two examples adds to reach; published first-query gains of 22-25 pp come from far richer candidate pools and should be read as an upper reference, not a forecast.
- Measure: (a) pairwise wrong-behaviour collision rates before and after (target: clearly below the within-source rate); (b) simulated-oracle experiment in the TiCoder style: answer the selected probe with the reference solution, report strict accuracy after 0, 1, 2 questions and questions per task; (c) the cheap proxy of supplying a second assert as an extra example.

#### What the evidence says not to pursue
- Test generation with expected outputs from the 12M models, a reviewer model, larger committees of same-recipe coders on hard tasks, and a text-reading verifier without an order of magnitude more labelled data: each has a published failure mode matching the brief's own negative results.
- Diversity indices as optimization targets (Kuncheva-Whitaker); optimize the collision rate that enters the likelihood ratio instead.

#### Evaluation hygiene that these measurements presuppose
- Probe inputs restricted by per-task contracts; disagreements labelled as error / artifact / reference-suspect; lenient, strict and contract-strict counts reported together; standard errors and paired tests on every comparison (section 5).

### Gaps
- Every expected gain above is extrapolated from LLM-scale or PBE-DSL studies; no source measures these mechanisms for 12M-parameter from-scratch models with a rule engine.
- The brief does not say whether the 36 strict failures are wrong answers or empty outputs, nor how the 62-76 range pairs with the two judges; the abstention arithmetic and the "91-94% selection efficiency" depend on those readings.
- No evidence was found on how well a tiny transduction model's errors decorrelate from an enumerator's in a general operator DSL; mechanism C(i) is the least supported element.
- Unverified items in these notes: Laich et al. (2020) accuracy figures; venue labels marked [snippet]; MBPP+ release details (page summary only).
