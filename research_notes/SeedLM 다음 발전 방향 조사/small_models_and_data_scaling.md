# Small from-scratch language/code models: what they reach, how much data they need, and how synthetic data, self-training and training-efficiency techniques can supply knowledge

Conventions for the report writer: every number below was read from the primary source text during this research (arXiv/ar5iv HTML, ACL Anthology, Hugging Face cards, GitHub READMEs, the EvalPlus `results.json`) unless it is explicitly marked "(unverified)" or placed under Gaps. "From scratch" means no pretrained weights. HumanEval/MBPP numbers are pass@1 unless stated. Budget arithmetic used throughout (my computation from the stated throughput): 8k tokens/s on the target CPU = 28.8M tokens/hour, i.e. 19.2M tokens in 40 minutes and 57.6M tokens in 120 minutes.

## Q1. What accuracy do transformers trained from scratch reach on HumanEval / MBPP (and HumanEval+/MBPP+) as a function of parameter count and training tokens?

### Takeaway
Below about 100M parameters every from-scratch code LM with a published HumanEval score that I found sits at 1.5-8% pass@1 even after roughly 100B training tokens (Codex-12M: 2.0%, AlphaCode-13M: 1.5%); 150-400M models reach 9-13% HumanEval and 11-19% MBPP+. The only sub-1B model far above this trend is phi-1-small (350M, 45% HumanEval), and it got there through data quality (filtered "textbook" code plus about 880K GPT-3.5 exercises), not scale. I found no published MBPP or MBPP+ number for any model under 50M parameters.

### Cited Findings

**Models under 100M parameters (HumanEval only)**
- Codex size sweep, all trained for 100B tokens on 159 GB of Python from 54M GitHub repositories: Codex-12M 2.00% pass@1 (3.62% pass@10, 8.58% pass@100); Codex-25M 3.21% (7.1 / 12.89); Codex-42M 5.06% (8.8 / 15.55); Codex-85M 8.22% (12.81 / 22.4); Codex-300M 13.17% (20.37 / 36.27); Codex-679M 16.22%; Codex-2.5B 21.36%; Codex-12B 28.81% (46.81 / 72.31) — [Chen et al. 2021, Codex, Table 1](https://arxiv.org/abs/2107.03374)
- Codex models were fine-tuned from GPT checkpoints, but "we did not observe improvements when starting from a pre-trained language model, possibly because the fine-tuning dataset is so large" (only faster convergence), so the sweep is effectively a from-scratch result — [Chen et al. 2021](https://arxiv.org/abs/2107.03374)
- AlphaCode decoder-only baselines, pre-trained on the Python-only subset of GitHub and evaluated without fine-tuning (best temperature, 1000 samples): 13M 1.5% (3.6 / 8.6); 29M 3.4% (5.8 / 11.2); 55M 4.2% (8.2 / 16.9); 89M 4.3% (12.2 / 20.0); 302M 11.6% (18.8 / 31.8); 685M 14.2% (24.4 / 38.8); 1.1B 17.1% (28.2 / 45.3) — [Li et al. 2022, AlphaCode, Appendix Table A3](https://arxiv.org/abs/2203.07814)
- General-purpose LMs on HumanEval: GPT-Neo 125M 0.75%, GPT-Neo 1.3B 4.79%, GPT-Neo 2.7B 6.41%, GPT-J 6B 11.62%; TabNine 2.58%, "roughly equivalent to Codex-12M" — [Chen et al. 2021](https://arxiv.org/abs/2107.03374)

**Models of 100M-400M parameters**
- CodeParrot-small (GPT-2, 110M; 150,000 steps on 16 A100, "roughly 29 billion tokens"): 3.80% pass@1, 6.57% pass@10, 12.78% pass@100 — [codeparrot-small model card](https://huggingface.co/codeparrot/codeparrot-small)
- PyCodeGPT (110M, GPT-Neo-125M configuration with a new 32K code tokenizer; 96 GB / 13.0M deduplicated Python files; 200K steps = 100B tokens; 16 V100 for about 2 days): 8.33% pass@1 (13.36 / 19.13). In the same table: CodeParrot 1.5B 3.58%, PolyCoder 160M 2.13%, PolyCoder 400M 2.96%, PolyCoder 2.7B 5.59% — [Zan et al. 2022, CERT, Appendix A](https://arxiv.org/abs/2206.06888)
- CodeT5 (220M), CodeGPT-adapted (124M, GPT-2 further trained on CodeSearchNet) and CodeClippy (125M) score pass@1 = 0 on HumanEval — [Zan et al. 2022, CERT, Table 1 caption](https://arxiv.org/abs/2206.06888)
- tiny_starcoder_py (164M, Python part of StarCoderData for about 6 epochs = 100B tokens, 50k steps, 32 A100 for 18 hours): 7.84% pass@1 — [bigcode/tiny_starcoder_py model card](https://huggingface.co/bigcode/tiny_starcoder_py)
- CodeGen-350M trained sequentially: NL (ThePile, 354.7B tokens, random init) 2.12% -> Multi (BigQuery) 6.67% -> Mono (BigPython, 71.7B Python tokens) 12.76% (23.11 / 35.19) — [Nijkamp et al. 2022, CodeGen, Table 1 and Table 5](https://arxiv.org/abs/2203.13474)
- TinyCodeLM-150M and -400M: pre-trained from scratch on 72B tokens (10.4B FineWeb + 61.8B The Stack Python) for 2 epochs on 4 H100, then instruction-tuned on about 88.9K instruction+program pairs (50,661 Self-OSS-Instruct + 38,284 Magicoder OSS-Instruct Python). Results: 150M Instruct 9.1 +/- 2.3 HumanEval, 11.5 +/- 1.9 MBPP(+); 150M LintSeqInstruct 12.8 +/- 2.6 HumanEval, 13.6 +/- 2.1 MBPP(+) (pass@10 24.4); 400M Instruct 11.3 +/- 0.9 HumanEval, 15.5 +/- 2.1 MBPP(+); 400M LintSeqInstruct 13.4 +/- 2.0 HumanEval, 19.4 +/- 2.4 MBPP(+) (pass@10 29.9). MBPP is scored with the MBPP+ extended tests; scores are temperature-tuned — [Piterbarg, Pinto, Fergus 2024, LintSeq, Table 1, Sec. 3.1-3.2, App. D-E](https://arxiv.org/abs/2410.02749)
- Same table, evaluated by the LintSeq authors: SmolLM-135M-Instruct 7.7 +/- 0.8 HumanEval and 10.1 +/- 1.8 MBPP(+); SmolLM-360M-Instruct 11.3 HumanEval and 19.4 +/- 2.4 MBPP(+); CodeGen-Mono-350M 9.4 +/- 1.8 MBPP(+); CodeT5+ 220M 12.0 HumanEval — [Piterbarg et al. 2024, Table 1](https://arxiv.org/abs/2410.02749)
- SmolLM-135M and -360M were each trained on 600B tokens of SmolLM-Corpus; SmolLM-1.7B on 1T tokens reaches 24 pass@1 on HumanEval — [SmolLM blog, Hugging Face 2024](https://huggingface.co/blog/smollm)
- SmolLM2-360M was trained on 4T tokens and SmolLM2-135M on 2T tokens (no HumanEval reported for them); SmolLM2-1.7B reaches 22.6 HumanEval after 11T tokens, and its HumanEval by training stage was 10.97 (0-6T tokens), 9.15 (6-8T), 17.68 (8-10T, after Stack-Edu was introduced) and 22.60 (10-11T) — [Allal et al. 2025, SmolLM2, Table 4, Table 8, Sec. 6](https://arxiv.org/abs/2502.02737)

**phi-1 family (data quality at 350M-1.3B)**
- phi-1 (1.3B): 50.6% HumanEval and 55.5% MBPP, trained for about 8 passes over less than 7B tokens (slightly over 50B tokens seen; 770 GPU-hours on 8 A100) and then fine-tuned 6,000 steps (7 hours) on less than 200M tokens of CodeExercises; phi-1-base (before the exercises) 29%; phi-1-small (350M, same pipeline) 45% — [Gunasekar et al. 2023, Textbooks Are All You Need](https://arxiv.org/abs/2306.11644)
- 350M models trained on unfiltered deduplicated Stack Python + StackOverflow saturate at 12.19% HumanEval after 96k steps (about 200B tokens); the classifier-filtered subset gives 17.68% after 36k steps; filtered + synthetic textbooks gives 20.12%; adding the CodeExercises fine-tune gives 45% — [Gunasekar et al. 2023, Sec. 2.1 and Table 2](https://arxiv.org/abs/2306.11644)
- phi-1's Table 1 lists, for comparison: Codex-300M (100B tokens) 13.2%; CodeGen-Mono-350M (577B tokens) 12.8%; SantaCoder 1.1B (236B tokens) 14.0% HumanEval / 35.0% MBPP; Replit 2.7B (525B tokens) 21.9%; StarCoder 15.5B (1T tokens) 33.6% / 52.7% — [Gunasekar et al. 2023, Table 1](https://arxiv.org/abs/2306.11644)
- An independent 2025 evaluation of 20 small models (0.4B-10B) reports phi-1 at 0.52 HumanEval but only 0.22 MBPP pass@1, and PolyCoder-0.4B at 0.03 HumanEval and 0.00 MBPP — [Assessing Small Language Models for Code Generation, 2025, Table 3](https://arxiv.org/abs/2507.03160); this conflicts with phi-1's self-reported 55.5% MBPP — [Gunasekar et al. 2023](https://arxiv.org/abs/2306.11644)

**Models of 1B or more with HumanEval+/MBPP+ (the smallest entries with EvalPlus numbers)**
- EvalPlus leaderboard data (125 models; none below 1B): zyte-1B 2.4 / 1.8 (HumanEval / HumanEval+) and 9.8 / 7.5 (MBPP / MBPP+); DeepSeek-Coder-1.3B-base 28.7 / 25.6 and 56.9 / 47.9; DeepSeek-Coder-1.3B-instruct 65.9 / 60.4 and 65.3 / 54.8; CodeGen-2B 24.4 / 22.6 and 46.3 / 36.0; CodeT5+-2B 25.0 / 22.0 and 48.4 / 38.1; phi-2 (2.7B) 49.4 / 45.1 and 64.0 / 54.2; StarCoderBase-1B 14.6 / 12.2; SantaCoder-1.1B 14.6 / 14.0; InCoder-1.3B 12.2 / 11.0; CodeGen2-1B 11.0 / 9.1 — [EvalPlus leaderboard results.json](https://evalplus.github.io/results.json)
- OpenCoder-1.5B-Base (from scratch, 2T tokens over four epochs plus 100B annealing tokens, from the 960B-token RefineCode corpus): 54.3 / 49.4 HumanEval(+), 70.6 / 58.7 MBPP(+) — [Huang et al. 2024, OpenCoder, Table 6 and Sec. 4](https://arxiv.org/abs/2411.04905)
- MBPP's original study covered models from 244M to 137B parameters, found synthesis performance "scales approximately log-linearly with model size", 59.6% few-shot for the largest model, a roughly constant gain from fine-tuning on only 374 problems, and that even the smallest models write syntactically correct Python about 80% of the time — [Austin et al. 2021, Program Synthesis with Large Language Models](https://arxiv.org/abs/2108.07732)

### Inferences
- Scaling slope: at a fixed 100B-token budget Codex goes from 2.0% (12M) to 13.2% (300M), about +2.4 points of HumanEval pass@1 per doubling of parameters (11.2 points over 4.6 doublings). AlphaCode's sweep has the same shape. A 10-50M general Python LM therefore sits at 1.5-5% pass@1 and 8-17% pass@100 regardless of the exact recipe.
- The token budgets are out of reach on the target machine: 100B tokens at 8k tokens/s is about 145 days per pass; a 120-minute run sees 0.06% of what Codex-12M saw. General-purpose Python pre-training from scratch is not a credible route here.
- Data quality moved a 350M model from 12.19% to 45% (a factor of 3.7) in phi-1; there is no evidence that the same factor holds below 50M parameters, and phi-1's own authors note that phi-1-small "does not have enough capacity to learn the correct function calls".
- The system this research is for scores 72/151 = 47.7% on its MBPP+ test split. The protocol differs from the benchmark numbers above (one input/output example is given and candidates are verified by execution, plus a rule engine), so it is not directly comparable; but as a rough reference it is at the level of 1.3B from-scratch code LMs on the full MBPP+ (47.9) and far above anything published for LMs of 400M parameters or fewer (at most 19.4). The hybrid design (operator library + search + execution check) already extracts far more per parameter than any LM-only result in the literature.
- For a system that executes candidates on an example, pass@k with a filter is the relevant column: Codex-12M and AlphaCode-13M both reach only about 8.6% at k=100.

### Gaps
- I found no HumanEval or MBPP results for from-scratch models under 50M parameters other than Codex-12M/25M/42M and AlphaCode-13M/29M (HumanEval only), and nothing below 135M with an MBPP, MBPP+ or HumanEval+ number. One targeted web search for 2025-2026 sub-50M code models found none; it surfaced only larger models (for example a 2.5B "Mify-Coder", December 2025, not read).
- The per-size numbers of the MBPP paper (for example the 244M model) are only in its figures and could not be read from the text.
- SmolLM (v1) 135M/360M base-model HumanEval scores are shown only as an image in the blog; SmolLM2-135M/360M HumanEval scores are not reported in the paper or model card.
- PyCodeGPT's paper calls GPT-Neo its "base model" while training a new tokenizer; whether the transformer weights were initialised from GPT-Neo is not explicit.

## Q2. What do TinyStories, phi-1, BabyLM (2023, 2024, 2025) and SmolLM say about data quality versus quantity and the minimum token budget for transferable knowledge? Can 1-50M-parameter models learn word semantics from 10M-100M words?

### Takeaway
The consistent lever is narrowing the domain and raising data quality, not adding tokens: 1-33M models become fluent on a 1,500-word-vocabulary synthetic corpus, and 24-30M models reach about 80% on grammar tests from 10M words. But the same BabyLM models stay near chance on world-knowledge and hypernym tests even with 100M words, so lexical and world semantics do not emerge from scratch at this scale; they have to be put into the data explicitly.

### Cited Findings

**TinyStories (restricted domain)**
- TinyStories is a GPT-3.5/GPT-4-written corpus restricted to words a typical 3-4-year-old understands; models "below 10 million total parameters" (embedding dimension 256) or with a single transformer block produce fluent, consistent multi-paragraph stories, whereas 125M models such as GPT-Neo-small or GPT-2-small trained on broad corpora "can rarely generate coherent and consistent English text beyond a few words" — [Eldan and Li 2023, TinyStories](https://arxiv.org/abs/2305.07759)
- Diversity mechanism: a vocabulary of about 1,500 basic words split into nouns, verbs and adjectives; each generation call must use 3 randomly chosen words (one verb, one noun, one adjective) plus randomly chosen story features (dialogue, bad ending, moral value, plot twist, foreshadowing, conflict); the authors state that without this, even high-temperature prompting gives "a very repetitive dataset" — [Eldan and Li 2023, Sec. 2](https://arxiv.org/abs/2305.07759)
- Model range 1M-35M parameters, 1-8 layers, each trainable on a single V100 in at most 30 hours, tokenizer cut to the 10K most common tokens. Consistency with the story start emerges when hidden size grows from 64 to 128; one-layer models struggle with instruction following while two layers suffice to some extent; a 1M-parameter model fails every factual prompt while a 33M model answers most; "knowledge of facts seems to rely more on the embedding dimension, whereas for context-tracking the number of layers is more important" — [Eldan and Li 2023, Sec. 3-4](https://arxiv.org/abs/2305.07759)
- The dataset has 2.12M training stories (2,141,709 rows in total) — [TinyStories dataset card](https://huggingface.co/datasets/roneneldan/TinyStories); and about 373M words — [Theodoropoulos et al. 2024, BERTtime Stories](https://arxiv.org/abs/2410.15365)
- Data-size sweep with the TinyStories-33M GPT-Neo configuration trained on 5M / 10M / 25M / 50M / 75M / 100M words of TinyStories: BLiMP 55.5 / 58.4 / 59.9 / 62.8 / 64.0 / 64.8 and EWoK 51.1 / 51.9 / 52.4 / 53.0 / 53.4 / 53.1; "50M words appear to be a cutoff point, with notable drops in performance for data sizes less than that" — [Theodoropoulos et al. 2024, Table 1](https://arxiv.org/abs/2410.15365)
- llama2.c TinyStories models trained "in a few hours" on 4 A100: 260K parameters val loss 1.297; 15M (dim 288, 6 layers, 6 heads) 1.072; 42M 0.847; 110M 0.760 (about 24 hours); the README's summary is that "very small LLMs can have surprisingly strong performance if you make the domain narrow enough" — [Karpathy, llama2.c README](https://github.com/karpathy/llama2.c)

**phi-1 and SmolLM (quality filtering and synthetic textbooks)**
- phi-1's datasets: about 6B tokens of code selected by a classifier trained on GPT-4 annotations of about 100K samples for "educational value" (from more than 35B tokens of The Stack and StackOverflow), less than 1B tokens of GPT-3.5 synthetic textbooks, and about 180M tokens of GPT-3.5 Python exercises; the authors summarise this as outperforming competitors "despite being 10x smaller in model size and 100x smaller in dataset size" — [Gunasekar et al. 2023](https://arxiv.org/abs/2306.11644)
- The exercise fine-tune also improved abilities that are not in the exercises (use of Pygame and Tkinter), which the authors interpret as fine-tuning "reorganizing and consolidating the knowledge acquired during pretraining"; after pruning more than 40% of CodeExercises (everything similar to HumanEval by embedding and AST distance) a retrained phi-1 still scores 45.1-50.6% versus 41.5% for StarCoder-prompted — [Gunasekar et al. 2023, Sec. 3 and Table 3](https://arxiv.org/abs/2306.11644)
- SmolLM-Corpus: Cosmopedia v2 (28B tokens, 39M synthetic documents from Mixtral-8x7B over more than 34,000 topics, with web pages as seed samples; "approximately 1000 GPU hours to generate 2B tokens"), Python-Edu (4B tokens) and FineWeb-Edu (220B deduplicated tokens) — [SmolLM blog](https://huggingface.co/blog/smollm)
- Python-Edu: an educational-code classifier trained on Llama3 annotations of 500,000 Python samples kept only score 4 or higher, shrinking 40B Python tokens to 4B; "the model trained on Python-Edu converges more than 3 times faster than the model trained on unfiltered Python code, achieving 16% pass@1 after only 12B tokens" — [SmolLM blog](https://huggingface.co/blog/smollm)
- Synthetic textbooks written for middle-school students gave the best score on every benchmark except MMLU in the Cosmopedia ablation; for the 135M/360M models "the performance gains after 400B tokens begin to slow" — [SmolLM blog](https://huggingface.co/blog/smollm)
- Stack-Edu filtering (450B -> about 125B tokens over 15 languages) raised MultiPL-E Python from 20.7 to 25.6 in annealing ablations; "math and code capabilities typically emerge only after extensive training"; the 135M/360M SmolLM2 models did better with a single-stage mixture of consistently high-quality data (DCLM filtered with the FineWeb-Edu classifier) than with the staged curriculum used for 1.7B — [Allal et al. 2025, SmolLM2](https://arxiv.org/abs/2502.02737)

**BabyLM (10M and 100M words)**
- 2023 setup and winners: tracks Strict (100M words) and Strict-Small (10M words). ELC-BERT (LTG-BERT backbone) won both: Strict-Small BLiMP 0.80, GLUE 0.74, MSGS 0.29, BLiMP-supplement 0.67, aggregate 0.66; Strict 0.85 / 0.78 / 0.47 / 0.77 / 0.74; skylines Llama 2 0.84 / 0.84 / 0.26 / 0.75 / 0.71 and RoBERTa-base 0.87 / 0.79 / 0.24 / 0.76 / 0.70 — [Warstadt et al., Findings of the BabyLM Challenge 2023, Table 2](https://arxiv.org/abs/2504.08165)
- The ELC-BERT model used for Strict-Small has 24M parameters (98M for Strict) — [Charpentier and Samuel 2023, ELC-BERT, Appendix A](https://arxiv.org/abs/2311.02265)
- "Strict models did not outperform those in Strict-Small by a large amount, even though the size of training data was an order-of-magnitude larger"; the winners trained for "over 450 epochs" (Strict) and "over 2000 epochs" (Strict-Small), so the winning submission "trained on about as many samples as BERT, despite having a training set only about 3% as large" — [Warstadt et al. 2023 findings](https://arxiv.org/abs/2504.08165)
- 2023 method findings: "Curriculum learning attempts, which accounted for a large number of submissions, were largely unsuccessful"; knowledge distillation with auxiliary models "was often a successful approach"; consistently successful modifications were shorter training sequences and "training for more epochs or long epochs with data augmentation"; MSGS correlations "were largely negative, indicating that language models trained at this scale tend to prefer surface features over linguistic features" — [Warstadt et al. 2023 findings](https://arxiv.org/abs/2504.08165)
- 2024 winners: GPT-BERT (hybrid causal + masked objective). Strict-Small: BLiMP 81.2, BLiMP-supplement 69.4, (Super)GLUE 76.5, EWoK 54.6, text average 70.4 (best baseline 61.6); Strict: 86.1 / 76.8 / 81.5 / 58.4 / 75.7 (best baseline 64.8) — [Hu et al., Findings of the Second BabyLM Challenge 2024, Sec. 5.1](https://arxiv.org/abs/2412.05149); the Strict-Small GPT-BERT has 30M parameters and the Strict one 119M — [Charpentier and Samuel 2024, GPT-BERT](https://arxiv.org/abs/2410.24159)
- World knowledge and word semantics: "current systems do not learn world knowledge within 100M words. Most submissions perform near chance, at 50%" on EWoK, with a maximum of 58.4%; and "the hypernym test suite is beyond the ability of language models of this scale. All models (including last year's skylines) perform very close to chance" — [Hu et al. 2024 findings](https://arxiv.org/abs/2412.05149)
- 2024 statistics over 64 models: more training FLOPs predicts a higher score (beta = 2.7, p < 0.01); significant positive effects for training-objective innovations (beta = 4.5), dataset creation (beta = 4.8) and architectural innovations (beta = 3.5); negative for "linguistic bias" (beta = -7.3); curriculum learning trends negative (beta = -3.6, p = 0.055) and "is not an effective strategy ... at least in the BabyLM setting" — [Hu et al. 2024 findings, Sec. 6](https://arxiv.org/abs/2412.05149)
- 2024 synthetic-data submissions: GPT-4-written "variation sets" (paraphrase runs imitating child-directed speech) "can indeed improve the performance ... although the exact characterization of this relationship remains unclear" — [Hu et al. 2024 findings](https://arxiv.org/abs/2412.05149); adding story completions generated by a small TinyStories-trained GPT-Neo to LTG-BERT's training data "can occasionally offer modest gains, but overall have a negative influence on linguistic understanding" — [Theodoropoulos et al. 2024](https://arxiv.org/abs/2410.15365)
- 2025 (third challenge): compute was capped and intermediate checkpoints evaluated; a new interaction track let students learn from larger teacher models; "new training objectives and architectures tend to produce the best-performing approaches", "interaction with teacher models can yield high-quality language models", and "we do not observe a complete correlation between training FLOPs and performance" — [Charpentier et al., Findings of the Third BabyLM Challenge 2025 (abstract)](https://aclanthology.org/2025.babylm-main.28/)

**Other small-data evidence**
- BabyBERTa: a RoBERTa variant trained on a 5M-word child-directed corpus "acquires grammatical knowledge comparable to that of pre-trained RoBERTa-base - and does so with approximately 15X fewer parameters and 6,000X fewer words" — [Huebner et al. 2021, BabyBERTa](https://aclanthology.org/2021.conll-1.49/)
- MiniBERTas (RoBERTa pre-trained on 1M, 10M, 100M, 1B words): "LMs require only about 10M or 100M words to learn representations that reliably encode most syntactic and semantic features we test", 90% of the attainable probing improvement is reached with fewer than 20M words, but "a much larger quantity of data is needed in order to acquire enough commonsense knowledge", and the Winograd task "only rises significantly between 1B and 30B words" — [Zhang, Warstadt, Li, Bowman 2021](https://arxiv.org/abs/2011.04946)
- Scaling laws persist at tiny compute: in the one-GPU-one-day "cramming" setting, "per-token efficiency of training depends strongly on model size, but not transformer type" and "smaller models learn less efficiently" — [Geiping and Goldstein 2022, Cramming](https://arxiv.org/abs/2212.14034)
- Data format can matter more than data amount for a 10.6M-parameter NanoGPT trained from random initialisation on addition: the simplified-scratchpad format reaches 100% accuracy "with only 2000 samples, whereas the Reverse format requires more than double", and the detailed scratchpad needs "just 1000 samples"; balanced sampling of operand lengths was also necessary — [Lee et al. 2023, Teaching Arithmetic to Small Transformers](https://arxiv.org/abs/2307.03381)
- Training-efficiency recipes can cut the token budget by an order of magnitude at fixed target loss: the NanoGPT speedrun reaches the GPT-2-small target (3.28 validation loss on FineWeb) with "under 330M tokens (the llm.c GPT-2 replication needed 10B)", using the Muon optimizer, rotary embeddings, QK-norm, ReLU-squared, zero-initialised projections, untied embedding and head, and skip connections — [modded-nanogpt README](https://github.com/KellerJordan/modded-nanogpt)
- The compute-optimal ratio cited for large models is about 20 training tokens per parameter (Chinchilla), and BabyLM-scale work operates far below it, "in the regime where the number of parameters significantly exceeds the number of training tokens" — [Timiryasov and Tastet 2023, Baby Llama](https://arxiv.org/abs/2308.02019)

### Inferences
- Scale placement: a 120-minute run of the 12.4M model processes about 58M tokens, which is the BabyLM Strict-Small regime (10M words seen a few times) and about a tenth of one pass over TinyStories (373M words). At that scale the literature shows grammar-level regularities are learnable, while lexical relations (hypernyms) and world knowledge are at chance. A tiny coder therefore cannot be expected to know that two different words mean the same operator unless both appear in its training data attached to that operator.
- The TinyStories lesson transfers only if the language side is as closed as the program side. The program side of the target system is closed (about 780 operators); the description side is open English. The cheapest way to close it is to make the teacher cover the description vocabulary systematically (forced-word prompts in the TinyStories style) rather than to add more tasks.
- BabyLM winners needed hundreds to thousands of epochs and performance tracked FLOPs in 2024; under a fixed 40-120 minute CPU budget the equivalent lever is regularisation and augmentation, not more passes. This is consistent with the observed memorisation of the natural-language data within 30 minutes.
- Self-generated text from a small generator did not help in BabyLM (BERTtime Stories), whereas text written by a strong teacher did (TinyStories itself, variation sets). New lexical knowledge has to come from outside the tiny model.
- The speedrun result (30 times fewer tokens for the same loss) suggests optimizer and architecture choices are worth testing at 12M parameters, but all of that evidence is for a GPT-2-small-sized model on GPUs with a loss target, not for generalisation from small data.

### Gaps
- No study was found that directly measures lexical-semantic generalisation (for example synonym transfer) in from-scratch models of 1-50M parameters trained on 10-100M words, beyond the BLiMP-supplement hypernym suite and EWoK.
- The TinyStories paper does not state the corpus token count; the 373M-word figure comes from a later paper.
- The 2025 BabyLM findings were read at abstract level only; the track winners reported by a search snippet (a diffusion language model, a mixture-of-experts model, a reinforcement-learning interactive approach) were not verified against the PDF.
- The model size used for the Python-Edu "16% pass@1 after 12B tokens" ablation is not stated in the blog text.

## Q3. LLM-teacher synthetic data pipelines for code: how do they induce diversity, verify by execution, what do they cost, and what do error-driven (targeted) variants gain per teacher token?

### Takeaway
Every successful pipeline anchors generation on an external source of diversity (random word or name constraints, seed code snippets, extracted "concepts") and the ones that verify by execution gain measurably from it (3-17 points in controlled ablations). Error-driven loops (S3, LLM2LLM, PERsD) beat untargeted generation at equal sample counts, but all published gains are for pretrained students and for 10^4-10^6 generated samples; nothing shows transfer for a from-scratch model trained on a few thousand teacher tasks.

### Cited Findings

**Untargeted pipelines (teacher invents the task and the solution)**
- CodeExercises (phi-1): less than 180M tokens of GPT-3.5 Python exercises (docstring to be completed + solution), about 880K exercises; "the main means of eliciting diversity is by constraining the function names"; phi-1's synthetic textbooks (less than 1B tokens) get diversity "by providing constraints on topics and target audience". Effect: HumanEval 29% -> 50.6% from the exercise fine-tune. No execution check of the exercises is described — [Gunasekar et al. 2023](https://arxiv.org/abs/2306.11644)
- TinyStories: three random required words per story from a 1,500-word list plus random story features; TinyStories-Instruct adds GPT-3.5 summaries and a random sentence as conditioning — [Eldan and Li 2023](https://arxiv.org/abs/2305.07759)
- Self-Instruct: bootstraps from 175 seed tasks to about 52K instructions and 82K instances; a new instruction is kept only if its ROUGE-L similarity with every existing instruction is below 0.7 — [Wang et al. 2022, Self-Instruct](https://arxiv.org/abs/2212.10560)
- Code Alpaca: 20K instruction-following examples produced with the Self-Instruct recipe and `text-davinci-003`; around 40% of examples have an input field — [Code Alpaca repository](https://github.com/sahil280114/codealpaca); it "only relies on 21 seed tasks", and Code Evol-Instruct "merely depends on 5 heuristics to evolve the dataset" — [Wei et al. 2023, Magicoder](https://arxiv.org/abs/2312.02120)
- Code Evol-Instruct (WizardCoder): iteratively rewrites the roughly 20K Code Alpaca instructions into harder ones (LeetCode-style constraints, time/space complexity requirements), merges each round with all earlier rounds, and stops when an external dev set gets worse — [Luo et al. 2023, WizardCoder](https://arxiv.org/abs/2306.08568); WizardCoder (16B) is listed at 57.3% HumanEval / 51.8% MBPP — [Gunasekar et al. 2023, Table 1](https://arxiv.org/abs/2306.11644)
- OSS-Instruct (Magicoder): 80K seed snippets (1-15 consecutive lines from 80K starcoderdata documents; 40K Python and 5K each from 8 other languages) are each given to gpt-3.5-turbo, which writes a problem and its solution in one shot; 75K samples remain after removing duplicates; noisy samples (for example incomplete solutions) are deliberately not removed and there is no execution filter. CodeLlama-Python-7B: HumanEval+ 34.1 -> 55.5 with the 75K; MagicoderS-CL (plus about 110K Evol-Instruct samples) 66.5 HumanEval+ versus ChatGPT 65.9 — [Wei et al. 2023, Magicoder](https://arxiv.org/abs/2312.02120)
- Magicoder controls: fine-tuning on 75K mined comment-function pairs from the same seed corpus leaves HumanEval+ at 34.1 and lowers MultiPL-E from 29.6 to 24.1 ("data factuality, rather than the format, is essential"); 20K OSS-Instruct samples written by Mixtral-8x7B give HumanEval+ 55.5 / MBPP+ 50.4, above the Mixtral teacher itself (39.6 / 47.4) and the base model (34.1 / 45.4) — [Wei et al. 2023, Tables 6-7](https://arxiv.org/abs/2312.02120)
- Quality audit of OSS-Instruct: "out of 43.1k Python solutions ... about 11.6k (26.9%) are inexecutable"; SemCoder's PyX keeps only executable samples with tests and adds execution "monologue" reasoning; SemCoder (6.7B) reaches 79.3% HumanEval — [Ding et al. 2024, SemCoder](https://arxiv.org/abs/2406.01006)
- WaveCoder: raw code is selected from CodeSearchNet (2M comment-code pairs) by hand rules plus KCenterGreedy core-set selection on code embeddings; GPT-3.5 generates instruction data with examples drawn from an example database, GPT-4 acts as a rule-based discriminator; 20K instances over four task types. WaveCoder-DS-6.7B: 64.0 HumanEval (+14.6) and 62.8 MBPP (+2.2); WaveCoder-SC-15B: 50.5 (+16.9) and 51.0 (+7.4) — [Yu et al. 2023, WaveCoder](https://arxiv.org/abs/2312.14187)
- KodCode: 447K question-solution-test triplets from 12 sources and five synthesis methods; GPT-4o-0513 writes solution and tests, which are executed; each question gets up to 10 attempts, each regenerating both solution and tests, so hard questions are kept rather than filtered out (279K verified triplets after this step); checked against human MBPP validation tests the error rate stays below 2.5% — [Xu et al. 2025, KodCode](https://arxiv.org/abs/2503.02951)
- A 2025 pipeline with about 800K instruction-reasoning-code-test quadruplets uses relevance classifiers on web-mined content, multi-stage execution validation and "a genetic mutation algorithm" to increase task diversity — [Increasing LLM Coding Capabilities through Diverse Synthetic Coding Tasks, 2025](https://arxiv.org/abs/2510.23208)

**Pipelines without a stronger teacher (self-alignment, inverse generation, execution-grounded data)**
- SelfCodeAlign (Self-OSS-Instruct): 250K seed Python functions are selected from 5M docstring functions (type checker, benchmark removal, docstring-quality filter, near-duplicate removal); the base model extracts "concepts" from a seed and writes a task conditioned on the concepts plus a randomly sampled difficulty (easy/medium/hard) and category (function/class/program); it then samples several (response, tests) pairs per task, executes them in a sandbox and keeps one passing response. 74K pairs generated with CodeQwen1.5-7B give 67.1 HumanEval+ — [Wei et al. 2024, SelfCodeAlign](https://arxiv.org/abs/2410.24198)
- SelfCodeAlign ablations (HumanEval+ pass@1): execution pass rate of sampled responses 24.1%; passes only 65.2 versus random selection 61.6 versus failures only 57.9 (15.6K samples each); seed -> instruction directly 59.8 versus seed -> concepts -> instruction 65.2; random snippets as seeds 64.0; at 74K samples, Evol-Instruct (GPT-3.5) 59.1, OSS-Instruct (GPT-3.5) 61.6, direct GPT-4o distillation 65.9, SelfCodeAlign 67.1; the authors conclude "a base LLM could learn more effectively from data within its own distribution than a shifted distribution from a teacher LLM" — [Wei et al. 2024, Tables 9-11](https://arxiv.org/abs/2410.24198)
- Inverse-Instruct: instruction-tuned code LLMs "perform better at translating code into instructions than the reverse"; the model summarises code from its own training set into new instructions, self-evaluates and adds the selected pairs. InverseCoder-CL-7B: 76.2 (72.0) HumanEval(+) and 70.6 (60.1) MBPP(+), versus 72.6 (68.9) and 69.3 (59.3) for the same model without the inverse data — [Wu et al. 2024, InverseCoder](https://arxiv.org/abs/2407.05700)
- Case2Code: 2.3M functions sampled from The Stack; a 7B model (InternLM2-7B) only writes example inputs, the functions are executed, and 1.3M functions with input-output pairs remain ("the correctness of our synthetic data does not depend on the capabilities of the used LLMs"); cost about 500 A800 GPU-hours for generation and 1 hour on 64 CPUs for execution. Training the model to infer the program from the cases raises InternLM2-7B-Base from 31.1 to 44.5 HumanEval and 51.4 to 56.0 MBPP — [Shao et al. 2024, Case2Code](https://arxiv.org/abs/2407.12504)

**Targeted distillation driven by student errors**
- PERsD: a standard set is built first (374 MBPP tasks, ids 601-974, as in-context seeds -> 20K ChatGPT tasks -> 14,880 with five parsed test inputs -> 10,172 whose code executes on all five). The student then attempts each task; only failures (4.3K-6.5K) are sent back with the student's code and execution feedback, the teacher is asked for a fix "closest in semantics to the student's code", and only refinements that pass the tests are kept (2.5K-3.25K). Reported cost: $5.5 (CodeGen-mono-6B), $6.5 (CodeGen-mono-16B), $4.3 (StarCoder). Results: CodeGen-mono-16B +7 points to 36.4% and StarCoder +12.2 points to 45.8% HumanEval pass@1; "personalised distillation consistently outperforms standard distillation with only one third of the data" — [Chen et al. 2023, Personalised Distillation](https://arxiv.org/abs/2310.18628)
- S3 (Wang, Zhou, Sachan 2023): a DistilBERT student is trained on a seed synthetic set; its errors on a small real validation set are given to the LLM, which "extrapolates" them into new training data, for typically 2 rounds. Average score over four tasks 55.73 versus 46.34 for ZeroGen and 53.09 for GoldGen (the paper states an average improvement of 9.48% over ZeroGen and 2.73% over GoldGen) while using on average 30.43% of ZeroGen's data volume; without the error-extrapolation step and with the same amount of data: IMDb 86.86 vs 89.00, QNLI 73.70 vs 79.92, RTE 65.71 vs 73.29. Motivating observation: a student trained on 200K zero-shot synthetic IMDb examples reaches nearly 100% training accuracy while test accuracy stays low. Stated limitation: "a tiny change in the synthesis prompts can lead to a significant performance drop" — [Wang et al. 2023, S3](https://arxiv.org/abs/2310.13671)
- LLM2LLM (Llama-2-7B student, GPT-3.5 teacher): with 100 GSM8K seed examples, fine-tuning alone gives 1.59%, EDA 15.16%, AugGPT (untargeted LLM rephrasing) 18.12%, adding 471 more real examples 19.86%, LLM2LLM with 471 targeted augmentations 23.73%. Ablations: one-shot augmentation (490 samples) 16.30% versus 10 iterative rounds (471 samples) 23.73%; generating from previously augmented data 18.32% (4,302 samples) versus from seed data only 23.75%; continuing fine-tuning across rounds 14.71% versus re-fine-tuning from the pretrained checkpoint each round 23.75%. Teacher cost on GSM8K: $0.35 / $1.48 / $3.64 for 1% / 5% / 10% seed data — [Lee et al. 2024, LLM2LLM](https://arxiv.org/abs/2403.15042)
- Verified versus unverified teacher data: fine-tuning GPT-Neo-2.7B on 1M Codex-generated puzzle-solution pairs gives Pass@100 21.5% when unverified and 38.2% when filtered by the Python interpreter (baseline 7.5%) — [Haluptzok, Bowers, Kalai 2022](https://arxiv.org/abs/2207.14502)

### Inferences
- Per-sample size and yield, derived from the figures above: a phi-1 exercise is about 200 tokens (180M / 880K); a TinyStories story about 175 words (373M / 2.12M); PERsD's validated personalised example cost about $0.002; yields are 51% (PERsD standard set, 10,172 of 20K), 45-58% (PERsD refinements), 24% (SelfCodeAlign responses passing their tests), 57% (Case2Code), 73% executable (OSS-Instruct audit). The stated cost of the target project, 1,000-1,500 teacher tokens per verified task, is 5-7 times the size of a phi-1 exercise, which is what one expects when the teacher must invent, solve and survive verification.
- Describing is cheaper and more reliable than inventing: InverseCoder's observation (code -> instruction is easier than instruction -> code) and Case2Code's design (correctness comes from execution, the LLM writes only the cheap part) both suggest using the teacher to write one-sentence descriptions for programs that the system has already sampled and executed. The teacher output is then a sentence rather than a task plus solution, so the cost per verified example should fall by roughly an order of magnitude (my estimate; no paper measures this for a setting like this one).
- Diversity must be injected from outside the teacher: required words (TinyStories), constrained function names (phi-1), seed snippets (OSS-Instruct), extracted concepts plus random difficulty and category (SelfCodeAlign), core-set selection (WaveCoder), similarity-threshold de-duplication (Self-Instruct). For the target system the natural seeds are sampled operator compositions and a list of required description words or synonyms.
- Targeted loops give about 1.2-1.5 times the effect of untargeted augmentation at equal sample counts (LLM2LLM 23.73 vs 16.30-19.86; S3 with vs without error extrapolation), and three design rules recur: drive the loop with errors on real held-out data, generate only from real seeds (not from earlier synthetic data), and retrain from the starting checkpoint each round. The third rule matches the reported failure mode in which newly added tasks are memorised pair by pair.
- All of these gains were measured on pretrained students (Llama-2-7B, CodeGen-16B, StarCoder, DistilBERT). The from-scratch successes (TinyStories, phi-1, self-play puzzles) used 10^5-10^6 teacher samples. A few thousand teacher tasks for a from-scratch 12M model is one and a half to two and a half orders of magnitude below any setting where transfer has been demonstrated.

### Gaps
- No dollar or token cost is reported for OSS-Instruct, Evol-Instruct, WaveCoder, SelfCodeAlign or KodCode; "gain per teacher token" can only be approximated from sample counts.
- No paper was found that applies error-driven distillation (S3, LLM2LLM, PERsD) to a from-scratch student under 100M parameters.
- InverseCoder's Table 1 (code-to-NL versus NL-to-code accuracy on MBPP+) was not captured numerically.
- The size of the final WizardCoder evolved dataset was not verified in the paper text (the open reproduction `evol-codealpaca-v1` has about 110K samples according to Magicoder).

## Q4. Self-training without a teacher: back-translation, hindsight relabeling, self-play puzzles, wake-sleep, self-sampled programs. Do noisy machine-generated descriptions help a small model generalize?

### Takeaway
Teacher-free methods reliably add program-side knowledge when correctness comes from execution (hindsight relabeling, dreaming, verified self-play): CodeIt goes from 42 to 59 solved ARC tasks with relabeling and still learns from random initialisation. Machine-generated descriptions help when the generator is reasonably good (and filtering by cycle consistency made the difference in the one study that ablated it); with a weak generator they are neutral or harmful, and they cannot add vocabulary the generator has never seen.

### Cited Findings

**Back-translation and machine-written descriptions**
- Back-translation (target-side monolingual text paired with an automatic translation into the source language) gives +2.8-3.7 BLEU on WMT15 English<->German and +2.1-3.4 BLEU on low-resource IWSLT14 Turkish->English (320K parallel sentence pairs, 3.2M back-translated sentences); a synthetic source is more effective than a dummy source token; only the source side is synthetic — [Sennrich, Haddow, Birch 2016](https://arxiv.org/abs/1511.06709)
- Sampling or noised-beam back-translations are better than beam/greedy "in all but resource poor settings"; with 80K sentence pairs (back-translation system at 13.5 BLEU) beam is better because the sampled back-translations "are of very poor quality and the noise ... is too detrimental for this brittle low-resource setting". The noise recipe is word deletion with probability 0.1, replacement by a filler token with probability 0.1, and local word swaps — [Edunov et al. 2018](https://arxiv.org/abs/1808.09381)
- NL-to-code with little data: copying monolingual code to both source and target with a frozen encoder ("target autoencoding") "outperforms all those approaches [fusion and back-translation] by a large margin", reaching 81.03% exact match on Django and 32.57 BLEU on CoNaLa with a BERT encoder and a 4-layer decoder and 100K-600K mined Python snippets — [Norouzi, Tang, Cao 2021](https://arxiv.org/abs/2101.00259)
- A learned question generator applied to sampled SQL queries improves a WikiSQL parser: with 30% of the training data, test logical-form accuracy 53.7% -> 61.2% (equal to the parser trained on 100%: 60.7%); with 100%, 60.7% -> 63.7%; accuracy grows logarithmically with data — [Guo et al. 2018, Question Generation from SQL Queries](https://arxiv.org/abs/1808.06304)
- GAZP: sample logical forms from a grammar in the new environment, generate utterances with a backward model, parse them back and keep only cycle-consistent pairs. Spider dev: exact match 56.8 -> 59.1 and execution 55.4 -> 59.2; without the cycle-consistency filter 55.6 / 52.3 even with 2.4 times more synthetic data (97,655 vs 40,557 examples); synthesising in the training environments instead 54.8 / 52.1 — [Zhong et al. 2020, GAZP, Table 3](https://arxiv.org/abs/2009.07396)
- Grammar-generated pseudo-language plus paraphrasing (the "Overnight" recipe) yields 51.3 average accuracy on the true utterance distribution versus 70.6 for an approach that labels real unlabeled utterances; the two causes are mismatch of the logical-form distribution and of the language — [Herzig and Berant 2019](https://arxiv.org/abs/1908.09940)
- AutoQA: training only on template-generated questions plus filtered automatic paraphrases gives 55.6% logical-form and 69.8% answer accuracy on Overnight, "only 5.2% lower than the same parser trained with human paraphrases" — [Xu et al. 2020, AutoQA](https://arxiv.org/abs/2010.04806)
- Sim-to-real for language: train only on grammar-generated utterances and, at test time, project a natural utterance onto the nearest synthetic one using pretrained sentence embeddings; this "matches or outperforms state-of-the-art models trained on natural language data in several domains" — [Marzoev et al. 2020, Unnatural Language Processing](https://arxiv.org/abs/2004.13645)
- Self-generated text from a small generator did not help a small learner: story completions sampled from a TinyStories-trained GPT-Neo had "overall ... a negative influence on linguistic understanding" of LTG-BERT in BabyLM — [Theodoropoulos et al. 2024](https://arxiv.org/abs/2410.15365)

**Recombination and structure coverage (small from-scratch sequence models)**
- Data recombination from an induced synchronous grammar, with a small attention-copy RNN trained from random initialisation (200 hidden units, 100-dimensional word vectors): GeoQuery (600 training examples) 85.0 -> 89.3, ATIS 76.3 -> 83.3, Overnight +1.7 on average; the copy mechanism alone adds 10.4 points on GeoQuery and 6.4 on ATIS — [Jia and Liang 2016](https://arxiv.org/abs/1606.03622)
- GECA (swap fragments that occur in a shared environment): SCAN "jump" split 0.00 -> 0.87 and "around right" 0.00 -> 0.82 accuracy, 16% error reduction on a semantic parsing task, about 1% perplexity reduction for n-gram LMs on small corpora — [Andreas 2019, GECA](https://arxiv.org/abs/1904.09545)
- "A test instance is hard if it contains a local structure that was not observed at training time" (local structures are connected sub-graphs of 2-4 nodes over parent-child and sibling edges of the program tree); this rule predicts instance-level success with AUC 78.4-93.3 across five datasets, and choosing a training set that maximises the number of observed local structures improves compositional generalisation for a fixed budget — [Bogin, Gupta, Berant 2022](https://arxiv.org/abs/2201.05899)
- Structurally-diverse sampling from a pool of synthetic utterance-program pairs reaches with 5K examples what uniform sampling needs 1M for ("a 200x improvement in data efficiency"); compositional exact match 20.1 -> 27.8 with 2K and 41.4 with 5K sampled examples — [Oren, Herzig, Berant 2021](https://arxiv.org/abs/2109.02575)
- Synthetic program distributions bias what is learned: models trained on standard synthetic distributions "often [achieve] less than 5% generalization accuracy" on other program/input distributions; making salient variables (length, nesting, input features) uniform improves cross-distribution generalisation — [Shin et al. 2019, Synthetic Datasets for Neural Program Synthesis](https://arxiv.org/abs/1912.12345)
- Purely synthetic training can transfer to real tasks when the language covers them: RobustFill, trained only on sampled programs, reaches 92% on 205 real FlashFill instances (beam 1000) versus 34% for the previous best neural approach — [Devlin et al. 2017, RobustFill](https://arxiv.org/abs/1703.07469)
- ExeDec: small Transformers trained from scratch (embedding 512, hidden 1024, 3 layers, 4 heads; 500K steps of fresh synthetic data) that predict execution subgoals step by step achieve "+44% higher average compositional generalization than the Transformer baseline on RobustFill and +18% on DeepCoder, a 4.4x higher success rate" — [Shi et al. 2023, ExeDec](https://arxiv.org/abs/2307.13883)

**Hindsight relabeling, wake-sleep, self-play and self-sampling**
- CodeIt (CodeT5+ 220M on ARC): sample programs, execute them and relabel the task with the realised outputs, then learn from a prioritised replay buffer; 59/400 evaluation tasks (15%). Ablations (policy-only / cumulative solved): full 49 / 59; no hindsight relabeling 24 / 42; no prioritised sampling 38 / 58; random initialisation instead of pretrained weights 9 / 35 ("CodeIt does seem to be able to bootstrap from random weights", but generalisation starts only after about 50 meta-iterations); one demonstration example instead of up to ten 34 / 51; no mutation-based augmentation of the initial set 17 / 20; no policy feedback 13 / 45. Model size matters: a large gain from 60M to 220M and a small one from 220M to 770M — [Butt et al. 2024, CodeIt, Table 2 and App. D](https://arxiv.org/abs/2402.04858)
- Hindsight Instruction Relabeling: relabel the instruction with what the model actually did and train supervised; on 12 BigBench reasoning tasks it "outperforms the baseline algorithms and is comparable to or even surpasses supervised finetuning" — [Zhang et al. 2023, HIR (abstract)](https://arxiv.org/abs/2302.05206)
- DreamCoder: the recognition network is trained "on a 50/50 mix of replays and fantasies" (replays are programs found for real tasks; fantasies are programs sampled from the learned library and executed on inputs taken from the training tasks). The authors "typically train DreamCoder on 100-200 tasks, which is too few examples for a high-capacity neural network", and note that early dreams from the initial library are "simple and largely unstructured ... offering limited value", becoming useful as the library is fitted to the domain — [Ellis et al. 2020, DreamCoder](https://arxiv.org/abs/2006.08381)
- LAPS: adding natural-language annotations to DreamCoder training "produces higher-quality libraries and improves search efficiency and generalization ... even when no natural language hints are available at test time" — [Wong et al. 2021, LAPS (abstract)](https://arxiv.org/abs/2106.11053)
- Self-play with verified puzzles: GPT-Neo-2.7B Pass@100 on 228 held-out puzzles is 7.5% at baseline; 10.5% after fine-tuning on 635 verified solutions to 95 human puzzles (74K tokens); 15.4% / 18.9% / 20.6% after 1M verified puzzle-solution pairs generated by Neo-125M / 1.3B / 2.7B (65-74M tokens each); 38.2% with Codex-generated verified pairs. About half of generated puzzles were removed by pre-filters, 128 solution attempts were sampled per puzzle, and a second generate-and-fine-tune iteration gave only a modest further gain. The authors add that "hard" generated problems "may not be useful if they are from a very different distribution" — [Haluptzok, Bowers, Kalai 2022](https://arxiv.org/abs/2207.14502)
- Self-sampled correct and partially-correct programs kept in a per-task buffer: GSM8K pass@100 35.5% -> 44.5% and MathQA pass@80 27.6% -> 36.2% for fine-tuned GPT-Neo models, with the choice of multi-target objective (MLE, MML, beta-MML) strongly affecting results — [Ni et al. 2022](https://arxiv.org/abs/2205.14318)

### Inferences
- Program-side knowledge is the part that can be supplied for free: sample programs from the operator library, execute them on inputs and keep (program, example) pairs that are correct by construction. Three findings say how to sample: cover local structures (parent->child and sibling pairs) as uniformly as possible rather than following a naive prior (Bogin; Oren; Shin), mix real-task replays with fantasies about half and half (DreamCoder), and prefer programs proposed by the current model over random mutations (CodeIt: 59 vs 45 solved without policy feedback). This targets the failure mode in which the coder only writes parent->child combinations it has seen.
- Language-side knowledge cannot be created this way. A describer trained on a few thousand descriptions is in Edunov's "resource poor" regime; GAZP shows unfiltered generated utterances hurt (-1.2 exact match) while cycle-consistent ones help (+2.3); BERTtime Stories shows self-generated text from a small model is on balance harmful. A tiny describer can at best re-attach words it already knows to new program structures; it cannot introduce new words or new task concepts.
- The cycle-consistency filter has a cheap analogue in the target system: keep a machine-written (description, program) pair only if the forward system, given the description and the example, recovers a behaviourally equivalent program.
- Evidence that machine-generated descriptions help a small from-scratch model exists for semantic parsing (Guo et al.: +7.5 points when generator and parser both use 30% of WikiSQL) and for translation at 320K pairs (Sennrich). It turns weak or negative when the generator is weak and its output is noisy or unfiltered (Edunov at 80K pairs: sampled back-translations do worse than beam ones; GAZP without the cycle filter; BERTtime Stories). In every positive case the generator had far more than a few thousand real pairs to learn from. For the target system this ranks a tiny self-trained describer low and a teacher-written description of sampled programs high.
- Template-only language transfers poorly to real phrasing (51.3 vs 70.6 in Herzig and Berant; AutoQA closes the gap to about 5 points with an automatic paraphraser plus filtering). The 300K templated descriptions in the target system should be expected to teach structure, not natural phrasing.

### Gaps
- No study isolates the effect of machine-written natural-language descriptions on a from-scratch NL-to-program model under 20M parameters.
- LAPS and HIR were read at abstract level only (the LAPS main results table and the HIR numbers were not retrieved); DreamCoder's ablation results are in figures only.
- CodeIt's "no pretraining" ablation still uses the 220M architecture; there is no hindsight-relabeling result for a model near 12M parameters.

## Q5. Mining (docstring, code) pairs and pretraining from scratch on modest corpora: what can a 10-100M-token run buy, and is there CPU-scale evidence?

### Takeaway
Mined docstring-code pairs are plentiful (about 0.5M Python pairs in CodeSearchNet) but noisy: models pre-trained from scratch on that scale score 0% on HumanEval and only help when fine-tuned in-domain, and fine-tuning a strong model on 75K mined comment-function pairs gave no gain. No published result shows a 10-100M-token from-scratch code pre-training run producing transferable synthesis ability, and no CPU-scale training evidence was found.

### Cited Findings
- CodeSearchNet: about 2M function-documentation pairs and 6.45M functions over six languages; Python has 503,502 documented functions and 1,156,085 functions in total. Construction rules: documentation truncated to its first paragraph, documentation shorter than three tokens removed, functions shorter than three lines removed, functions with "test" in the name and constructors removed, near-duplicates removed — [Husain et al. 2019, CodeSearchNet](https://arxiv.org/abs/1909.09436)
- CodeGPT (GPT-2 architecture, 124M) pre-trained from scratch on CodeSearchNet (1.1M Python functions or 1.6M Java methods) versus CodeGPT-adapted (initialised from GPT-2): on CONCODE text-to-code (100K training examples) exact match / BLEU / CodeBLEU are 18.25 / 28.69 / 32.71 versus 20.10 / 32.79 / 35.98; GPT-2 without code pre-training 17.35 / 25.37 / 29.69; a plain Seq2Seq RNN 3.05 / 21.31 / 26.39 — [Lu et al. 2021, CodeXGLUE, Table 10](https://arxiv.org/abs/2102.04664)
- CodeT5-small (60M) and CodeT5-base (220M), pre-trained on CodeSearchNet plus C/C# with identifier-aware denoising and a bimodal docstring<->code dual-generation task: CONCODE 21.55 / 38.13 / 41.39 (small) and 22.30 / 40.73 / 43.20 (base); the bimodal dual generation "brings consistent improvements for code summarization and generation tasks" — [Wang et al. 2021, CodeT5](https://arxiv.org/abs/2109.00859)
- Outside their fine-tuning distribution these CodeSearchNet-scale models do not synthesise: CodeT5 (220M) and CodeGPT-adapted (124M) get pass@1 = 0 on HumanEval — [Zan et al. 2022, CERT](https://arxiv.org/abs/2206.06888)
- PyMT5 (374M encoder-decoder) trained on 26M Python methods and 7.7M method-docstring pairs: on CodeSearchNet test it generates 92.1% syntactically correct method bodies with BLEU 8.59; on its own test set PyMT5 gets BLEU 10.6 versus 5.60 for GPT2-medium trained from random initialisation and 5.63 for English-pretrained GPT2-medium, i.e. "the English pre-trained initialization of GPT2 only slightly beats the random initialization" — [Clement et al. 2020, PyMT5](https://arxiv.org/abs/2010.03150)
- With very large code corpora, natural-language pre-training adds nothing: Codex saw no improvement from starting at a pretrained GPT checkpoint — [Chen et al. 2021](https://arxiv.org/abs/2107.03374)
- Mined pairs as direct supervision can fail even for a strong pretrained model: 75K comment-function pairs mined in the CodeSearchNet style leave CodeLlama-Python-7B at 34.1 HumanEval+ and reduce MultiPL-E from 29.6 to 24.1, while 75K teacher-written OSS-Instruct samples from the same seed corpus give 55.5; the authors attribute this to "substantial noise and inconsistency that exists intrinsically in the data pairs" — [Wei et al. 2023, Magicoder, Table 6](https://arxiv.org/abs/2312.02120)
- Heavy filtering is normal when mining seeds: SelfCodeAlign keeps 250K of 5M docstring functions (5%) after type-checking, docstring-quality filtering and de-duplication — [Wei et al. 2024, SelfCodeAlign](https://arxiv.org/abs/2410.24198)
- Mined StackOverflow pairs help small NL-to-code models modestly as pre-training: pre-training TranX on mined NL-code pairs and API documentation, then fine-tuning on CoNaLa, raises BLEU from 30.1 to 32.3 — [Xu et al. 2020](https://arxiv.org/abs/2004.09015); using only the code side of 100K-600K mined snippets as an autoencoding target does better (32.57 BLEU on CoNaLa, 81.03% exact match on Django) than using the noisy mined intents or back-translation — [Norouzi et al. 2021](https://arxiv.org/abs/2101.00259)
- Execution can replace the docstring: Case2Code turns 2.3M mined functions into 1.3M (input-output cases -> program) training examples whose labels are correct by construction — [Shao et al. 2024, Case2Code](https://arxiv.org/abs/2407.12504)
- What small budgets buy in natural language: going from 5M to 100M words of TinyStories takes a GPT-Neo with the 33M-parameter TinyStories configuration from 55.5 to 64.8 on BLiMP — [Theodoropoulos et al. 2024](https://arxiv.org/abs/2410.15365); 10M words give about 80% BLiMP for 24-30M models only with hundreds to thousands of epochs — [Warstadt et al. 2023 findings](https://arxiv.org/abs/2504.08165)
- Compute scale of the smallest published from-scratch runs: TinyStories models (1M-35M) on a single V100 in at most 30 hours — [Eldan and Li 2023](https://arxiv.org/abs/2305.07759); a 58M student distilled for 6 epochs over 10M words in under 3 hours on one RTX 3090 — [Timiryasov and Tastet 2023](https://arxiv.org/abs/2308.02019); BERT-like models "crammed" in one day on one consumer GPU — [Geiping and Goldstein 2022](https://arxiv.org/abs/2212.14034); llama2.c 15M-110M models in hours on 4 A100 — [llama2.c README](https://github.com/karpathy/llama2.c)
- In data-constrained training, "training for more than 4 epochs leads to diminishing returns" (Muennighoff et al. 2023, as summarised by the BabyLlama-2 authors) — [Tastet and Timiryasov 2024, BabyLlama-2](https://arxiv.org/abs/2409.17312)

### Inferences
- Budget check: one pass over 100M tokens takes about 3.5 hours at 8k tokens/s, so a 40-120 minute run covers 19-58M tokens, i.e. less than one pass over a CodeSearchNet-Python-sized corpus (its token count was not verified; 0.5M function-docstring pairs is of the order of 10^8 tokens).
- The evidence does not support mined docstring-code pre-training as a source of synthesis ability at this scale: 124M-220M models with that pre-training score 0% on HumanEval, and CodeSearchNet removes functions shorter than three lines, so its code looks nothing like one-line operator compositions. What such a corpus could still supply is word-level association between description vocabulary and code identifiers (an auxiliary objective for the description encoder). That is plausible but untested for models this small, and Magicoder's negative result is a warning against using the pairs as direct supervision.
- The Case2Code and Norouzi results point the same way as Q4: the reliable part of mined data is the code (executable, or usable as a decoder-side target); the natural-language side is the noisy part.
- No CPU-only training result was found in this literature; the nearest are single-GPU runs of hours to a day for 10-60M models, which is one to two orders of magnitude more compute than a 2-hour 4-core run.

### Gaps
- No paper reports what a 10-100M-token from-scratch code pre-training run buys on an execution-based benchmark; the smallest budgets with HumanEval numbers are about 29B tokens (CodeParrot-small).
- No CPU-scale (no GPU) language-model training study was found.
- Token counts for CodeSearchNet-Python were not found in the paper; the order-of-magnitude figure above is my estimate.
- CodeT5-small has no HumanEval or MBPP result in the sources read.

## Q6. Techniques against memorization of small natural-language data in tiny models: what is proven at the under-20M-parameter scale?

### Takeaway
For small models on small data the proven levers are, in order of evidence: more and more varied dropout (including word and layer dropout), smaller models and vocabularies, weight averaging, and ensembling followed by distillation; each has measured gains on small corpora (5K-165K sentence pairs, Penn Treebank, the 10M-word BabyLM corpus). Curricula have consistently failed. R-Drop, SeqMix and BPE-dropout have gains in low-resource translation but at roughly twice the model size and, for R-Drop, twice the compute per step.

### Cited Findings

**Low-resource sequence-to-sequence (5K-160K sentence pairs, models trained from scratch)**
- Transformer on IWSLT14 German->English subsets of 5K / 10K / 20K / 40K / 80K / 165K sentence pairs (BLEU): Transformer-big 3.3 / 3.4 / 4.3 / 4.7 / 5.1 / 5.5; Transformer-base 8.3 / 11.9 / 16.8 / 23.2 / 28.0 / 32.1; then cumulatively: feed-forward 2048 -> 512: 8.8 / 12.0 / 16.7 / 22.3 / 27.7 / 31.7; attention heads 8 -> 2: 9.2 / 12.7 / 19.0 / 23.6 / 28.7 / 32.3; dropout 0.1 -> 0.3: 10.6 / 17.0 / 21.9 / 26.7 / 31.0 / 33.4; layers 6 -> 5: 10.9 / 16.9 / 21.9 / 26.0 / 30.2 / 33.0; label smoothing 0.1 -> 0.6: 11.3 / 16.5 / 22.0 / 26.9 / 30.4 / 33.3; decoder LayerDrop 0 -> 0.3: 12.9 / 17.3 / 22.5 / 26.9 / 30.3 / 33.1; target word dropout 0 -> 0.1: 13.7 / 18.1 / 23.1 / 27.0 / 30.7 / 33.0; activation dropout 0 -> 0.3: 14.3 / 18.3 / 23.6 / 27.4 / 30.4 / 32.6 (settings tuned on the 5K subset; up to +7.3 BLEU over defaults) — [Araabi and Monz 2020, Table 2](https://arxiv.org/abs/2011.02266)
- RNN NMT with 100K words of training text (5,000 sentences): baseline 0.00 BLEU; + dropout, tied embeddings, layer normalisation, deeper RNN, label smoothing 7.20; + BPE vocabulary reduced from 14K to 2K symbols 12.10; + batch size 4K -> 1K tokens 12.40; + aggressive word dropout 15.87; + further tuning (learning rate, depth, label-smoothing rate) 16.57; phrase-based SMT 15.87. On the full 3.2M words word dropout takes 31.97 to 33.60 — [Sennrich and Zhang 2019, Table 2](https://arxiv.org/abs/1905.11901)
- R-Drop (two dropout passes per example with a symmetric KL consistency loss): IWSLT14 German->English 34.64 -> 37.25 BLEU and the average over eight IWSLT tasks 32.44 -> 34.68, with the `transformer_iwslt_de_en` configuration and weight 5; the authors note "the computational cost of R-Drop increases at each step" (the batch is duplicated) and that it "needs more training to converge" — [Liang et al. 2021, R-Drop](https://arxiv.org/abs/2106.14448)
- SeqMix (soft mixing of pairs of training sequences) "consistently yields approximately 1.0 BLEU improvement on five different translation datasets" and helps on SCAN and semantic parsing; word dropout and SwitchOut are shown to be variants of the same objective — [Guo, Kim, Rush 2020, SeqMix](https://arxiv.org/abs/2011.09039)
- BPE-dropout (random segmentation during training) improves translation by "up to 2.3 BLEU compared to BPE" — [Provilkov et al. 2019, BPE-dropout](https://arxiv.org/abs/1910.13267)
- Rule-based text augmentation (EDA: synonym replacement, random insertion, swap, deletion) gives +3.0% average accuracy with 500 training examples and +0.8% with full data for CNN/RNN classifiers — [Wei and Zou 2019, EDA](https://arxiv.org/abs/1901.11196); as a baseline for a 7B pretrained student with 100 GSM8K seed examples it gives 15.16% versus 1.59% without augmentation and 23.73% for targeted LLM augmentation — [Lee et al. 2024, LLM2LLM](https://arxiv.org/abs/2403.15042)

**Small language models on small corpora (10-60M parameters)**
- AWD-LSTM (24M parameters on Penn Treebank; 33M on WikiText-2), test perplexity 57.3 (PTB) and 65.8 (WT2); removing one component at a time (PTB / WT2 test): no NT-ASGD weight averaging 63.7 / 69.7; no weight-dropping (DropConnect on recurrent weights) 68.9 / 74.9; no embedding (word) dropout 62.7 / 68.1; no weight decay 61.0 / 68.7; no activation regularisation 60.3 / 70.1; no variable sequence lengths 58.9 / 66.2; no final fine-tuning 58.8 / 66.0 — [Merity, Keskar, Socher 2017, Table 4](https://arxiv.org/abs/1708.02182)
- Born-again self-distillation (student identical to teacher) on Penn Treebank: ConvLSTM with 19M parameters, test perplexity 80.05 -> 76.97; LSTM with 52M parameters, 71.87 -> 68.56 — [Furlanello et al. 2018, Born-Again Networks, Table 6](https://arxiv.org/abs/1805.04770)
- Baby Llama: a 58M student distilled (loss weight 0.5, temperature 2, distillation from the first step) from a 705M GPT-2 and a 360M LLaMA, all trained only on the 10M-word BabyLM corpus, "exceeds in performance both of its teachers as well as a similar model trained without distillation" — [Timiryasov and Tastet 2023](https://arxiv.org/abs/2308.02019)
- Same paper, experiments with a 10M-parameter GPT-2 (8 layers, width 256, vocabulary 16,000): averaging the logits of 4 independently initialised models lowers eval loss from 3.77 (individual average) to 3.66 and adds 1-2 points of BLiMP; a readability-ordered curriculum ends at 3.75 versus 3.74 without it; sharpness-aware minimisation gave no improvement; a mixture-of-experts (Switch) variant got worse as experts were added; the ensemble gain "do[es] not sum with" the distillation gain — [Timiryasov and Tastet 2023, Appendix B](https://arxiv.org/abs/2308.02019)
- BabyLlama-2: the distillation advantage persists after "an extensive hyperparameter sweep", so it "cannot be attributed to suboptimal hyperparameter selection of the teachers" — [Tastet and Timiryasov 2024](https://arxiv.org/abs/2409.17312)
- Curriculum learning: "largely unsuccessful" in BabyLM 2023 — [Warstadt et al. 2023 findings](https://arxiv.org/abs/2504.08165); a negative trend (beta = -3.6) in 2024 — [Hu et al. 2024 findings](https://arxiv.org/abs/2412.05149); a systematic study of vocabulary, data-order and objective curricula "did not yield consistent improvements" — [Martinez et al. 2023, CLIMB](https://arxiv.org/abs/2311.08886)
- Augmentation by recombining context beats repetition: creating 40 re-contextualised variants of each text chunk "outperforms training for 40 epochs using the same training samples" — [Warstadt et al. 2023 findings, on Contextualizer](https://arxiv.org/abs/2504.08165)
- Retraining instead of continuing: when new teacher data is added over rounds, restarting fine-tuning each round gives 23.75% versus 14.71% for continuing from the last round's weights, which the authors attribute to "overfitting to small seed data over multiple iterations" — [Lee et al. 2024, LLM2LLM](https://arxiv.org/abs/2403.15042)
- Checkpoint averaging along the training trajectory, combined with high learning rates, improves convergence and generalisation early in training (tested on 125M-770M nanoGPT-2 models on 9B tokens and Pythia 1B-12B) — [Sanyal et al. 2023, Early Weight Averaging](https://arxiv.org/abs/2306.03241)
- Small TinyStories models are reported not to memorise: generated stories "have a very low overlap with the dataset" by n-gram measures, with a 2.12M-story corpus — [Eldan and Li 2023](https://arxiv.org/abs/2305.07759)

### Inferences
- Proven at or near the under-20M scale: the dropout family including word/embedding dropout and weight-dropping (AWD-LSTM at 24M; Sennrich and Zhang's RNNs; Araabi and Monz's reduced Transformers), weight averaging (6.4 perplexity points on PTB), smaller vocabularies and smaller models for small data (Transformer-big collapses to 3-5 BLEU), self-distillation (19M ConvLSTM), and ensembling (four 10M GPT-2 models). Shown only at about 40M parameters or more: R-Drop, SeqMix, BPE-dropout, trajectory checkpoint averaging for Transformers. Shown not to help: data-order curricula, sharpness-aware minimisation as tried in Baby Llama, mixture-of-experts at 10M.
- Gains concentrate where data is smallest: in Araabi and Monz the full stack adds +6.0 BLEU at 5K pairs but only +0.5 at 165K, and at 80K-165K pairs several steps are neutral or negative (fewer layers, LayerDrop, activation dropout): the best 80K and 165K results (31.0 and 33.4) are reached right after the dropout 0.1 -> 0.3 step. For the target system this argues for applying the strong settings to the natural-language part of the batch (a few thousand items) rather than to the 300K synthetic programs.
- Cost under a fixed CPU budget: word dropout, label smoothing, LayerDrop, weight decay and weight averaging are free; R-Drop doubles the cost per step, so in a fixed 40-120 minute run it halves the number of updates and must beat that handicap; an ensemble of k models costs k runs (the 4 cores allow little parallelism at 8k tokens/s total), while distilling the ensemble into one model costs one more run.
- The description side of the input is the natural place for noise: Edunov's recipe (delete a word with probability 0.1, replace with a filler with probability 0.1, swap neighbours) and Araabi and Monz's word dropout are direct fits; they make exact memorisation of a sentence harder without changing the program target.
- Restarting from scratch on each enlarged dataset (LLM2LLM) and distilling from an ensemble (Baby Llama) both address the reported pattern of memorising newly added tasks pair by pair; neither has been tested in a setting with a 12M model and a few thousand tasks.

### Gaps
- Parameter counts for the IWSLT configurations used by Araabi and Monz, R-Drop and SeqMix were not stated in the text read; "about 40M" for the standard IWSLT Transformer is from memory (unverified).
- No study measures these regularisers for NL-to-program generation with a from-scratch model under 20M parameters and a few thousand NL examples; the closest task-type evidence is semantic parsing with data recombination (Q4).
- Label smoothing was not isolated at small scale beyond Araabi and Monz's single step (+0.4 BLEU at 5K, mixed elsewhere).

## Q7. Bottom line: what data scale would a 10-50M-parameter from-scratch model need to gain MBPP-level task knowledge, and what is the cheapest credible route?

### Takeaway
As a general Python generator, a 10-50M model cannot reach MBPP-level knowledge at any data scale shown in the literature (about 2-5% HumanEval after 100B tokens; the smallest from-scratch models I found at 50% MBPP or above have 1.3B parameters). As the language front-end of a fixed operator library it plausibly needs of the order of 10^5-10^6 distinct (description, program) pairs, roughly 20 to 170 times the current natural-language data, and the cheapest credible way to get them is to let execution supply the programs for free and spend teacher tokens only on short, diversity-constrained descriptions, combined with free regularisation and retraining from scratch.

### Cited Findings
- Size floor for open-domain synthesis: Codex-12M / 25M / 42M reach 2.00% / 3.21% / 5.06% HumanEval pass@1 after 100B tokens — [Chen et al. 2021](https://arxiv.org/abs/2107.03374); TinyCodeLM-150M / 400M reach 13.6 / 19.4 MBPP(+) after 72B-token pre-training plus 88.9K instruction pairs — [Piterbarg et al. 2024](https://arxiv.org/abs/2410.02749); the smallest from-scratch models found at or above 50% MBPP are 1.3-1.5B (phi-1 55.5% MBPP with 7B tokens of curated data; OpenCoder-1.5B-Base 58.7 MBPP+ with 2T tokens) — [Gunasekar et al. 2023](https://arxiv.org/abs/2306.11644), [Huang et al. 2024](https://arxiv.org/abs/2411.04905)
- Small models solve what has near neighbours in their training data: phi-1 solves 81.7% of the 71 HumanEval problems that have a close match in its 880K-exercise fine-tuning set (AST match rate at least 0.95) but 26.9% of the 93 that do not; at a looser threshold (0.8) 116 of 164 problems have a match, with 59.5% versus 29.2% solved — [Gunasekar et al. 2023, Table 3](https://arxiv.org/abs/2306.11644)
- From-scratch models that generalised to unseen prompts inside a narrow domain were trained on 10^5-10^6 or more teacher-written samples: 2.12M TinyStories — [TinyStories dataset card](https://huggingface.co/datasets/roneneldan/TinyStories); about 880K CodeExercises on top of pre-training — [Gunasekar et al. 2023](https://arxiv.org/abs/2306.11644); 1M verified puzzles — [Haluptzok et al. 2022](https://arxiv.org/abs/2207.14502)
- Pretrained students needed 10^4-10^5 teacher samples for measurable transfer: 10K standard + 2.5-3K personalised (PERsD) — [Chen et al. 2023](https://arxiv.org/abs/2310.18628); 20K (WaveCoder) — [Yu et al. 2023](https://arxiv.org/abs/2312.14187); 75K (OSS-Instruct) — [Wei et al. 2023](https://arxiv.org/abs/2312.02120); 50-74K (SelfCodeAlign) — [Wei et al. 2024](https://arxiv.org/abs/2410.24198)
- Small NL-to-program models do well only when test language resembles training language: 85-89% on GeoQuery from 600 training examples with copying and recombination (randomly initialised RNN) — [Jia and Liang 2016](https://arxiv.org/abs/1606.03622); 51.3% on real utterances after template-plus-paraphrase training versus 70.6% with real-utterance detection — [Herzig and Berant 2019](https://arxiv.org/abs/1908.09940); 18-22% exact match on open-ended CONCODE with 100K examples for 60-124M code-pre-trained models — [Lu et al. 2021](https://arxiv.org/abs/2102.04664), [Wang et al. 2021](https://arxiv.org/abs/2109.00859)
- Lexical and world knowledge does not appear on its own at this scale: BabyLM models are near chance on EWoK and hypernym tests with up to 100M words — [Hu et al. 2024 findings](https://arxiv.org/abs/2412.05149)
- Structure coverage is data-efficient when sampled deliberately: 5K structurally diverse synthetic examples match 1M uniform ones — [Oren et al. 2021](https://arxiv.org/abs/2109.02575); unseen local structures predict failure — [Bogin et al. 2022](https://arxiv.org/abs/2201.05899)
- Execution-verified and cycle-consistent synthetic data beats unverified data: 38.2% vs 21.5% (self-play puzzles) — [Haluptzok et al. 2022](https://arxiv.org/abs/2207.14502); 65.2 vs 61.6 HumanEval+ (SelfCodeAlign) — [Wei et al. 2024](https://arxiv.org/abs/2410.24198); 59.1 vs 55.6 exact match (GAZP) — [Zhong et al. 2020](https://arxiv.org/abs/2009.07396)
- Targeted, iterative, seed-anchored teacher augmentation with retraining from the start beats one-shot augmentation at equal volume: 23.73% vs 16.30% — [Lee et al. 2024](https://arxiv.org/abs/2403.15042)
- Regularisation is worth several points at 5K-10K examples: +6.0 BLEU at 5K sentence pairs from dropout variants, smaller layers and word dropout — [Araabi and Monz 2020](https://arxiv.org/abs/2011.02266); weight averaging is worth 6.4 perplexity points for a 24M LSTM — [Merity et al. 2017](https://arxiv.org/abs/1708.02182); ensembles of four 10M models add 1-2 points and distil into one model — [Timiryasov and Tastet 2023](https://arxiv.org/abs/2308.02019)

### Inferences

**Data-scale estimate (my estimate by analogy; no source measures this setting directly)**
- Route A, general Python knowledge: infeasible. The literature's floor is about 100B tokens for 2-5% HumanEval at 12-42M parameters, and the machine processes about 58M tokens per 120-minute run.
- Route B, language front-end for the fixed operator library: the coder needs (i) each operator and each common parent->child structure in training, and (ii) each of them described in many surface forms, because lexical equivalence will not be inferred at this scale. If each of about 780 operators needs of the order of 100 distinct phrasings and each frequent depth-2 structure a handful, the requirement is 10^5 to 10^6 (description, program) pairs, or very roughly 10-100M tokens of description-bearing data. This matches the scale at which from-scratch models have generalised inside narrow domains (TinyStories, CodeExercises, self-play puzzles) and is roughly 17 to 170 times the present 5.9K natural-language items (3,000 teacher tasks + 525 real + 2,400 paraphrases).
- Compute caps the useful size at about the same point: at an assumed 80 tokens per training example, a 120-minute run presents about 720K examples, so a natural-language set of 10^5-3x10^5 items is the most that can be seen two or more times alongside structural data. Beyond that, compute rather than data is the binding constraint.
- Teacher cost: invent-solve-verify at 1,000-1,500 tokens per task means 100-150M teacher tokens for 10^5 tasks and 1-1.5B for 10^6. Describe-only (the teacher writes one sentence for a program the system has already sampled and executed), at an assumed 100-200 teacher tokens per pair including prompt overhead, means 10-20M tokens for 10^5 pairs. The assumption is untested for this system.
- What data cannot fix: tasks whose solution needs a concept absent from the operator library. phi-1's near-neighbour result (81.7% vs 26.9%) suggests small models answer benchmark tasks largely through close training matches; MBPP's one-off concepts will not have matches unless the library and the data both contain them. This ceiling is set by the library, not by the coder's training data.

**Feasibility under the stated constraints (my judgment)**

| Technique | Evidence | Cost here | Judgment |
|---|---|---|---|
| General Python pre-training from scratch | 2-5% HumanEval at 12-42M after 100B tokens (Q1) | 145 CPU-days per 100B tokens | Not feasible |
| Pre-training on mined docstring-code pairs | 0% HumanEval at 124-220M; mined pairs gave no gain for a 7B model (Q5) | Under one pass over 10^8 tokens per run | Low value; at most an auxiliary word-association objective |
| Teacher invents and solves tasks at scale (phi-1 / OSS-Instruct style) | Works at 75K-880K samples, mostly for pretrained students (Q3) | 100-150M teacher tokens per 10^5 tasks | Too expensive for the gain shown so far |
| Teacher describes sampled, executed programs with forced-word and seed constraints | Indirect: InverseCoder, Case2Code, TinyStories diversity, SelfCodeAlign concepts (Q3) | Roughly 10-20M teacher tokens per 10^5 pairs (assumed) | Most credible source of language knowledge |
| Round-trip (cycle-consistency) filter on generated pairs | GAZP +2.3 with filter, -1.2 without (Q4) | CPU only | Feasible and cheap |
| Error-driven teacher top-up from real failures, seeds only, retrain from scratch | LLM2LLM, S3, PERsD; pretrained students only (Q3) | Small: tens to hundreds of failures per round | Feasible; effect on a from-scratch 12M model unproven |
| Dreaming with hindsight relabeling, uniform over local structures, mixed with real-task replays | CodeIt 42 -> 59 tasks; DreamCoder; Oren 200x; Bogin (Q4) | CPU sampling and execution only | Feasible; addresses unseen structure combinations, not vocabulary |
| Tiny self-trained describer (back-translation) | Harmful or neutral with weak generators (Edunov 80K; GAZP no-cycle; BERTtime Stories) | One extra small model | Low value |
| Dropout variants, word dropout, label smoothing, smaller vocabulary | +6 BLEU at 5K pairs; 0 -> 16.6 BLEU at 100K words (Q6) | Free | Do first |
| Weight averaging | 6.4 perplexity points at 24M (Q6) | Free | Do first |
| Ensemble then distil | +1-2 points with four 10M models; student beats teachers (Q6) | k extra runs | Feasible if wall-clock allows |
| R-Drop | +2.2 BLEU average on IWSLT (Q6) | Doubles cost per step | Uncertain under a fixed time budget |
| Curriculum ordering | No gain or negative in BabyLM 2023 and 2024, CLIMB, Baby Llama (Q6) | Free | Skip |
| Optimizer and architecture tweaks from the NanoGPT speedrun | 30x fewer tokens to a fixed loss for a GPT-2-small-sized model on GPUs (Q2) | Free to try | Unproven at 12M on CPU and for generalisation |

**Cheapest credible route (ordered by cost)**
1. Free: apply the low-resource regularisation stack to the natural-language part of training (word dropout and noising of descriptions, higher dropout, label smoothing, weight averaging) and retrain from scratch whenever data is added.
2. Free: replace naive program sampling with structure-balanced dreaming: programs proposed by the current coder and by enumeration, executed for correct-by-construction examples, sampled to cover parent->child pairs uniformly, mixed about half and half with real-task replays.
3. Cheap teacher use: have the teacher write one-sentence descriptions (and paraphrases with required words) for those sampled programs rather than invent tasks; keep a pair only if the system recovers an equivalent program from the description; aim for the order of 10^5 pairs.
4. Targeted top-up: after each retraining, collect failures on held-out real tasks and ask the teacher for a few variants of each, always anchored on the real task, never on earlier synthetic items.
5. If wall-clock allows: train several coders and distil them into one.

### Gaps
- No experiment in the literature matches this setting (a model of about 12M parameters trained from scratch on CPU as the language front-end of a hand-written operator library), so the 10^5-10^6 pair estimate and the describe-only cost estimate are extrapolations and should be treated as hypotheses to test with a small pilot (for example 5K, 20K and 80K described programs) before committing teacher budget.
- No source quantifies how many distinct phrasings per operator a small model needs before it generalises to an unseen phrasing.
- Work from 2026 is thinly covered: searches surfaced little directly relevant new work on sub-50M code models, and items seen only in search snippets were not verified.
- Adjacent topics (compositional-generalisation architectures, library learning, neural-guided search, weight-space methods) were only touched where they bear on data scale; they appear to be assigned to other researchers (the folder also contains notes named `compositional_generalization.md` and `weight_space_methods.md`, which I did not read).
