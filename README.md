# MyLittleLLM

Qwen3-4B를 활용해 한국 대학 입시·장학 정보 접근 격차를 줄일 수 있는지 검증하는 프로젝트.

**우선순위 1: 근거를 제시하는 입시 상담. 우선순위 2: 장학금·주거·실부담 비용 안내.** 공식 문서 검색(RAG), 검증 가능한 조건·계산 코드, LLM의 설명을 결합한다.

## 2026-11-18 규칙 증류 실험 (별도 트랙)

입시 상담과 별개로, "큰 생성형 모델이 쓴 규칙으로 CPU의 작은 코딩 모델을 끌어올릴 수 있는가"를 검토했다. 결론과 근거는 [가능성 검토](docs/rule_distillation_feasibility.md)에 있다.

- 규칙을 모델에게 **읽히는** 방식(프롬프트 규칙, 오류 피드백 수리)은 1.5B 학생에게 통하지 않았다.
- 규칙을 **실행해서 확인하는** 방식은 통했다. 규칙을 쓴 답과 안 쓴 답 중 보이는 예시를 재현하는 쪽을 고르고(분기-선택), 둘 다 틀리면 예시의 기대 출력에서 거꾸로 계산을 찾는다(예시 역추론, 모델 호출 없음).

잠가 둔 시험 분할(MBPP+ 151문제, 숨은 테스트까지 통과 기준):

| | 규칙 없음 | 분기-선택 + 예시 역추론 | 고침 / 깨뜨림 |
|---|---|---|---|
| Qwen2.5-Coder-1.5B (4비트, CPU) | 89 (58.9%) | 97 (64.2%) | 8 / 0 |
| Qwen2.5-Coder-0.5B (4비트, CPU) | 56 (37.1%) | 80 (53.0%) | 24 / 0 |
| 모델 없이 규칙 엔진만 | — | 57 (37.7%) | — |

"모든 코딩 기능에서 최상위 수준"은 성립하지 않는다. 이득은 보이는 예시가 있고 답이 연산 두 단계로 표현되는 과제에 한정된다. 151문제 표본이라 신뢰구간이 넓다.

**3차 교사 라운드(분산).** 규칙 엔진이 못 푸는 과제 489건을 다섯 범주로 나눠 교사 서브에이전트 다섯이 연산을 썼고, 자동 검사와 데이터 선별로 452개를 남겼다. 절차와 수치는 [3차 라운드 문서](docs/rule_round3.md)에 있다.

- 모델 없이 규칙 엔진만: 시험 분할 57 → 68문제(37.7% → 45.0%), 고침 11 / 깨뜨림 0.
- 학생과 합친 파이프라인: 1.5B 97 → 98, 0.5B 80 → 80. 남은 실패의 70% 이상이 보이는 예시는 통과하는 오답이라, 규칙을 늘려도 닿지 않는다.

**처음부터 만든 모델(SeedLM).** 사전학습 가중치 없이 142만 파라미터 트랜스포머를 CPU 4코어에서 20분 학습했다. 예시의 입력과 출력을 보고 연산 프로그램을 제안하고, 제안은 실행으로 검증한다. 설계와 측정은 [SeedLM 문서](docs/seed_lm.md)에 있다.

- 같은 6분 학습에서 직교 초기화와 직교화 갱신(Muon)이 손실을 1.72 → 1.56 → 1.22로 낮췄다(시드 하나, 학습률 미조정).
- 혼자서 시험 분할 151문제 중 43문제(28.5%)를 푼다. 같은 규칙을 전수 탐색하는 엔진을 넘지는 못했고, 파이프라인에 가지로 붙여도 위 표의 수치는 달라지지 않았다.
- 모델이 탐색보다 많이 찾은 것은 연산 세 개짜리 합성 프로그램에서다(100개 중 65 대 55).
- 범용 코딩 LLM이 아니다. 자연어를 이해하지 못하고 교사가 만든 연산 328개의 조합만 출력한다.

```bash
python -m venv .venv && . .venv/bin/activate
pip install --no-deps evalplus==0.3.1 && pip install -r requirements-rule-pilot.txt
python scripts/rule_pilot_install.py --models coder-1.5b
bash scripts/rule_pilot_serve.sh coder-1.5b 8081 &
python scripts/rule_pilot.py generate --name demo --condition branch --split test --max-rules 2
python scripts/rule_pilot.py score --name demo
```

코드는 `mylittlellm/rulecoder/`(규칙 은행, 분기-선택, 예시 역추론)와 `mylittlellm/seedlm/`(처음부터 학습한 소형 모델)에 있고, 규칙 은행은 `data/rule_pilot/rule_bank.json`, 채점 결과는 `reports/rule_pilot/`, 처음부터 만든 모델의 실행 기록은 `reports/seedlm/`에 있다.

## 2026-11-02 현재 상태

- 서울대·부산대·경희대의 2025·2026학년도 **수시 모집요강 6개 + 공식 안내서 6개** 수집. 서울대 안내서는 교육청 학교 홈페이지 배포본을 사용했다.
- 장학금 자료를 포함한 URL 레코드 26개 중 18개 다운로드 성공: PDF 14개(1,075페이지), HWPX 1개, HTML 3개. 8개 접근 실패도 목록에 기록했다. 게시물/첨부가 별도 레코드이므로 고유 문서 수와 다를 수 있다.
- 수집기, 페이지별 PDF 추출, SHA-256 스냅샷, 그룹 단위 분할 코드, QA 초안 5개 작성.
- **후속 작업에서 Qwen3-4B Q4_K_M과 llama.cpp를 직접 설치하고 CPU 서버 및 RAG CLI를 실행했다.** 공식 원문 8개에서 비교표 검수 보류 후 1,295개 검색 구간을 사용한다.
- 주거비 지원과 실부담 비용 계산기를 구현했다. 지원 조건과 기간은 명시적으로 확인하며 대출을 장학금으로 차감하지 않는다.
- 공개 개발 예시 5개에 대해 문서 없는 모델/RAG 10회 추론을 완료했다. RAG에서도 전년도 규정 오독과 지급액 오류를 관찰했으며 실패를 포함해 결과를 기록했다.
- **사람이 승인한 gold 데이터, 미세조정 모델, 잠근 시험셋의 정확도 측정 결과는 아직 없다.** 공개 예시는 전부 `pending`이고 최종 시험셋으로 재사용하지 않는다. 실제 추론 비교는 개발용 예비 실험이다.

## 제안한 학습 방식의 수정

모집요강은 근거 문서이고 해설은 정답 후보 자료다. 질문마다 적용 학년도·전형·조건·예외·근거 페이지를 연결하고 검수해야 정답셋이 된다.

60:40은 **개발 60% / 잠근 시험 40%**로 유지하되, 개발용을 나누어 전체 기준 **학습 48% / 검증 12% / 시험 40%**로 시작한다. 같은 규칙의 연도별 버전·바꿔 쓴 질문·문서 복사본은 한 그룹으로 묶는다. 그룹 크기 때문에 실제 문항 비율은 달라질 수 있다.

현재 GGUF로 RAG 기준선을 구현하고 개발 예시를 실행했다. 다음에는 검수된 시험셋에서 오류를 평가한 후 LoRA의 추가 효과를 비교한다. 미세조정으로 매년 바뀌는 요강을 암기시키는 것만으로는 최신 상담 정확도를 보장할 수 없다.

## 데이터 수집

Python 3.10 이상. PDF 추출에는 pypdf를 사용한다.

```bash
python -m pip install -r requirements-data.txt
python scripts/collect_sources.py
```

일부 자료만 다시 받을 때:

```bash
python scripts/collect_sources.py --ids snu-2026-susi khu-2026-guide --output outputs/retry.jsonl
```

- 입력 목록: `data/sources.jsonl`
- 이번 수집 결과: `data/retrieval_snapshot.jsonl`
- 원문: `data/raw/` (Git 제외)
- PDF 페이지별 추출: `data/extracted/` (Git 제외)
- 새 실행 결과: `outputs/retrieval.jsonl` (Git 제외)

표·각주의 자동 추출 오류는 별도 검수한다. 부산대 2025 가이드북 31페이지는 OCR이 필요하다. HWPX와 HTML은 원본을 수집하며 현재 수집기에서 본문을 추출하지 않는다. 파일의 다운로드 성공은 정답 승인이나 학습 이용 허가를 의미하지 않는다.

## 검수 후 분할

```bash
python scripts/split_dataset.py data/private/reviewed_qa.jsonl --output outputs/frozen-v1
```

`review_status=approved`인 QA만 받는다. 실제 검수자·근거를 남긴 후 사용한다. 입력에 동일 질문이 다른 그룹으로 나타나면 중단하고, 이미 존재하는 출력 폴더에는 시험셋을 덮어쓰지 않는다. 의미가 같은 규칙의 자동 탐지는 구현하지 않았으므로 `leakage_group` 검수는 필수다.

새 대학 일반화 실험은 대학 수를 확대한 뒤 `--group-key institution_group`으로 별도로 분할한다. 연도 갱신 실험은 이 그룹 분할과 다른 평가 프로토콜이다.

## 코드 검증과 모델 연결 확인

```bash
python -m unittest discover -s tests -v
python scripts/probe_model.py --base-url http://127.0.0.1:8080/v1
```

테스트는 그룹 누출 방지, 미검수 답안 거부, 범위별 검색, 인용 ID 검증, 주거비 상한과 첫 달 예외, 대출과 비용의 구분을 검사한다. 코드 테스트 통과는 모델 답변의 정확도를 보장하지 않는다.

원문 저작물은 저장소에 재배포하지 않는다. URL·해시·수집 상태와 자체 작성한 문서/QA 초안만 공개한다. 원문별 이용 조건은 목록의 `license_note`에 기록한다.
