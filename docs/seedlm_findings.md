# 처음부터 만든 코더에 관해 지금까지 확인한 것 (SeedLM-4~25, 4차 교사 라운드)

작성일: 2026-11-20(SeedLM-12 반영), 2026-11-21(SeedLM-24까지 반영). 개별 실험은 [SeedLM-4](seed_lm4.md)부터 [SeedLM-12](seed_lm12.md), [SeedLM-13~20](seed_lm13.md), [SeedLM-21~24](seed_lm21.md)의 문서에 있다. 여기서는 실험들을 가로질러 남은 결론만 모은다. 모든 코더는 사전학습 가중치 없이 CPU 4코어에서 2시간 안팎 학습한 1,200만 파라미터 모델이고, 모든 판정은 측정 전에 등록한 기준을 따랐다.

## 지금 쓰는 시스템

- 모델 없이 도는 최선은 규칙 엔진 + s5-var(pyx_override)다. 보류 개발 과제 94개 중 69개, 잠근 MBPP+ 시험 151개 중 72개(엔진 혼자 68, 한 번만 평가).
- 코더만으로는 여러 구조의 코더 합의가 가장 강하다(동점은 가장 짧은 프로그램). 교사 보류 과제 139개 중 72.9개(후위 코더 13, s5-var 혼자 52), 보류 개발 과제 94개 중 64.6개(전위 코더 5를 더한 18, s5-var 혼자 57, 엔진 65).
- 1.5B 언어 모델 파이프라인에는 코더가 더하는 것이 없다(시험 98, HumanEval+ 110 그대로).

## 1. 코더는 본 적 있는 조합만 만든다

프로그램을 연결(부모 → 자식)과 잔가지(노드와 자식들의 조합)로 나눠 보면, 코더는 통째로 본 구조는 78% 맞히지만 처음 보는 조합이 하나라도 있으면 22%로 떨어진다(교사 보류 과제, s5-var). 엔진이 못 푸는 실제 과제에서 처음 보는 연결을 만드는 토큰은 24개 중 하나도 코더의 1순위가 아니었다. 학습 프로그램을 그대로 써서는 엔진 실패 29개 중 4개만 풀리므로, 엔진 너머의 정답은 대부분 새 조합이다([SeedLM-5](seed_lm5.md) 7~8절).

## 2. 새 조합을 가르치는 데이터는 아직 찾지 못했다

- 엔진 실패의 이웃 과제(SeedLM-5, 새 연결 504개)는 같은 과제를 더 자주 맞히게 했을 뿐 새 과제를 열지 못했다.
- 학습 프로그램을 처음 보는 연결로 이은 접붙이기(SeedLM-6, 새 연결 6,723개)는 한 번의 실행에서 교사 보류 과제의 새 조합 17 → 24개를 보였지만, 시드 셋으로 반복하자 효과가 사라졌다(SeedLM-12: 접붙이기 유무의 차이 +1, +1, −8, 새 조합 평균은 21.3으로 같음). 이 주장은 철회한다.
- 파이썬 노드와 라이브러리 연산을 섞은 생성 프로그램 3만 개(SeedLM-21)는 보류 과제의 새 연결을 3분의 1 덮었고 정답 프로그램의 손실도 낮췄지만, 정답을 쓴 과제는 오히려 줄었다(새 조합 21.3 → 20.3, 조각을 다 본 과제 38.7 → 35.0). 예시를 우연히 맞히는 틀린 프로그램이 빔에 더 많이 들어왔다(7절).
- 실제 개발 과제로는 어떤 데이터도 옮겨지지 않았다. 엔진 실패 29개 중 22개는 일곱 코더 누구도 못 풀고, 코더가 풀 때는 대개 일곱이 함께 푼다. 일곱 코더가 엔진 너머로 맞힌 과제는 모두 같은 6개 안에 있다.

## 3. 학습은 30분쯤 지나면 작은 데이터를 외운다

모든 코더에서 보류 교사 과제와 실제 보류 프로그램의 성능은 학습 30분 무렵에 가장 높고, 합성 과제만 계속 오른다(SeedLM-8). 40분만 학습한 코더 여섯은 교사 보류 과제에서 평균 59개로, 120분 학습한 s5-var(52)보다 높았다(SeedLM-12). 학습 데이터에서 떼어 둔 행으로 고른 30분 시점은 코더 자신의 지표에서 모두 나았지만(실제 보류 프로그램 60.0% → 74.7%), 세 경우 모두 맞는지로 따지면 +4, 실제 개발 과제에서는 차이가 없었다(SeedLM-9). 예시를 재현하는 것과 맞는 것은 다르다.

## 4. 합의는 오류가 독립인 출처 사이에서만 증거다

| 합의의 출처 | 결과 |
|---|---|
| 한 코더의 빔 안 (SeedLM-7) | 교사 보류 52 → 48, 해로움 |
| 따로 학습한 코더 일곱 (SeedLM-10) | 가장 좋은 단일 62 → 70, 이로움 |
| 다른 40분 코더 여섯 (SeedLM-12) | 가장 좋은 단일 62 → 71, 재현 |
| 코더 열셋, 동점은 가장 짧은 프로그램 (SeedLM-15, 16) | 단일 평균 57.8 → 72.9 |
| 구조가 다른 전위 코더 둘을 더함 (SeedLM-17) | 교사 과제 72.9 → 72.8, 실제 개발 과제 61.4 → 63.6 |
| 전위 코더 셋을 더 (SeedLM-18) | 실제 개발 과제 63.6 → 64.6 (엔진 65) |
| 나중 데이터로 학습한 전위 코더 셋을 더 (SeedLM-20) | 실제 개발 과제 64.6 → 64.6, 교사 보류 72.3 → 71.2 |
| 엔진과 코더 열여덟을 같은 무게로 (SeedLM-19) | 68 → 69 (고침 1, 깨뜨림 0), 엔진 쪽이나 코더 중 누군가 맞힘 73 |
| 실제 과제에서 엔진과 코더 다수 (SeedLM-11) | 바뀐 3개 중 고침 1, 깨뜨림 1 |
| 1.5B 학생 샘플과 엔진 (합의 라운드) | 확증된 답 84% 대 반박된 답 66% 정답 |

합의의 이득은 처음 다섯 코더에서 대부분 나오고(57.8 → 68.3), 동점을 가장 짧은 프로그램으로 깨면 코더 순서에 따른 흔들림이 사라지며 조금 더 오른다(SeedLM-15, 16). 한 출처 안의 다수는 그 출처의 편향을 두 번 센다. 같은 데이터에서 배운 출처들은 같은 곳에서 틀린다. 구조가 달라도 같은 데이터를 먹으면 마찬가지다. 전위 코더는 SeedLM-3의 데이터로 배웠을 때 실제 과제의 합의를 올렸지만, 후위 코더와 같은 나중 데이터로 배우자 아무것도 보태지 못했다(SeedLM-20). 실제 과제에서 코더들은 엔진의 프로그램과 엔진의 연산으로 만든 합성 데이터에서 배웠기 때문에 엔진의 맹점을 함께 가진다.

## 5. 측정에 관해

- 같은 데이터 구성의 두 120분 실행이 교사 보류 과제에서 62 대 53으로 갈렸다(SeedLM-9). 코더 사이의 차이 +4~+10은 대부분 이 흔들림 안에 있고, 단일 실행 비교로는 가를 수 없다. 40분 실행에서는 같은 구성의 시드 사이 폭이 3~6으로 줄었다(SeedLM-12).
- 보류 개발 과제의 엔진 실패 29개는 엇갈림이 15개일 때 11 대 4도 유의하지 않을 만큼 작다. 여섯 코더 모두 4~5개를 고친다.
- 설명을 MBPP처럼 짧게 바꿔도 코더는 똑같이 잘 푼다(52 → 54). 실제 과제가 어려운 것은 문체가 아니라 엔진이 쉬운 과제를 다 가져간 뒤의 나머지라는 선택 효과다.

## 6. 엔진이 못 푸는 실제 과제는 데이터 어디에도 그대로 있지 않다

학습 풀의 사람이 쓴 MBPP 참조 해답 616개(지금까지 어떤 SeedLM 데이터에도 쓰지 않은 것)를 보류 개발 과제마다 그대로 돌려 봤다(`scripts/seedlm14_reference_coverage.py`, `reports/seedlm/reference_coverage.json`, 개수만). 보이는 예시를 맞히는 참조 해답이 있는 과제는 엔진 실패 29개 중 9개였지만, 모든 테스트를 통과하는 것은 0개였다(엔진이 푸는 과제에서는 16개). 코더의 학습 프로그램(4개, SeedLM-5)과 합쳐도 결론은 같다. 엔진이 못 푸는 실제 과제는 기억이나 검색으로는 닿지 않는, 학습 풀에 없는 과제다.

## 7. 예시 하나로는 고르지 못한다

코더의 빔은 첫 후보가 맞히는 것보다 15~20개 많은 과제에서 맞는 프로그램을 이미 갖고 있다(교사 보류 과제, 폭 32: 첫 후보 59~62, 어딘가에 맞는 것 74~80). 실제 개발 과제에서도 엔진 쪽이나 코더 중 누군가 맞히는 것은 73개인데 시스템은 69개다. 남은 문제의 상당 부분은 순위, 즉 보이는 예시 하나를 똑같이 재현하는 프로그램들 사이에서 고르는 일이다.

| 고르는 방법 | 결과 |
|---|---|
| 설명이 프로그램에서 나올 확률로 재정렬 (SeedLM-3) | 개발 과제 67, 기준과 같음 |
| 한 코더의 빔 안 탐침 행동 합의 (SeedLM-7) | 교사 보류 52 → 48, 해로움 |
| 따로 학습한 코더들의 합의, 동점은 가장 짧은 프로그램 (SeedLM-10~16) | 단일 평균 57.8 → 72.9, 이로움 |
| 새 조합을 넓게 가르침 (SeedLM-12, 21) | 정답의 손실은 내려가고 틀린 이웃이 늘어 정답 수 그대로이거나 감소 |
| 코더 자신의 틀린 검증 프로그램을 밀어냄 (SeedLM-23) | 교사 보류 +2.3, 판단 보류. 보류 빔의 틀린 프로그램 수는 거의 그대로 |
| 실행 결과를 읽는 검증기 (SeedLM-24) | 교사 보류 −7.3, 개발 −13.3 |
| 자기 출력으로 만든 예시까지 설명하는 확률 (SeedLM-25) | 교사 보류 +0.3, 개발 −0.7. 선택이 거의 바뀌지 않음 |

지금까지의 결과를 하나로 읽으면 이렇다. 예시 하나만 보이는 과제에서 코더 자신의 확률은 이미 가장 좋은 단일 순위 신호다. 확률을 넓게 퍼뜨리는 데이터는 맞는 프로그램과 함께 틀린 이웃도 올린다. 코더 안에서 틀린 이웃을 깎는 일은 본 짝에만 머물렀고, 행동을 읽는 작은 판정자는 코더보다 못했다. 코더가 첫째로 고른 오답은 자기 출력으로 만든 다른 예시에서도 첫째였다. 오답은 예시의 우연이 아니라 설명을 그렇게 읽은 결과다. 순위를 실제로 바꾼 것은 서로 다른 데이터와 구조에서 따로 배운 코더들의 합의뿐이었다. 틀린 이웃은 코더마다 다르고, 맞는 프로그램은 함께 고르기 때문이다.

## 남은 길

1. 실제 과제에서 엔진 너머를 열려면, 엔진과 같은 데서 배우지 않은 출처가 필요하다. 지금의 코더는 모두 엔진의 연산 위에서 배웠다. 엔진과 코더 열여덟 중 누군가는 개발 과제 73개를 맞히지만, 시도한 결합 규칙은 모두 66~69에서 멈췄다(SeedLM-11, 13, 19).
2. 문장(반복, 대입)을 쓰는 언어가 열 수 있는 몫은 작다. 보류 개발 과제의 엔진 실패 29개를 교사가 SeedLM-3에서 분류한 것을 다시 세면 한 줄 식 18개, 설명과 보이는 예시만으로는 정할 수 없는 과제 9개(숨은 상수나 규칙 3개, 설명과 테스트가 어긋남 6개), 반복이나 상태가 필요한 과제 2개다(`data/seedlm/oneliners_dev_part*.json`, 개수만). 앞서 이 자리에 "절반가량은 한 줄 식으로 쓸 수 없어 문장이 필요하다"고 적었는데, 한 줄로 못 쓴 11개 중 9개는 언어가 아니라 과제 쪽 문제라서 그 문장은 고친다. 남은 여지는 한 줄로 쓸 수 있는데 코더가 못 쓰는 과제들이다.
3. 차이를 가려내려면 같은 구성을 여러 번 학습하거나, 한 실행 안에서 비교하도록 실험을 짜야 한다. 같은 체크포인트에서 같은 배치로 두 갈래를 미세조정하는 쌍 비교(SeedLM-23)는 처음부터 다시 학습하는 비교보다 싸고 잡음도 작다.
4. 순위를 바꾼 유일한 신호가 독립적인 코더들의 합의이므로, 다음 투표자는 지금의 코더들과 다른 데이터에서 배워야 한다. 구조만 다르고 같은 데이터를 먹은 코더는 독립적이지 않았다(SeedLM-20).
5. 엔진 쪽도 비슷한 벽에 닿았다. 4차 교사 라운드의 연산 74개는 학습 과제 64개를 새로 풀었지만 보류 개발 과제에서는 한 번도 쓰이지 않았다([4차 라운드](rule_round4.md)). 남은 실패는 과제마다 제각각인 긴 꼬리다.
