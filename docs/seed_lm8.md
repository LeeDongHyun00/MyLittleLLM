# SeedLM-8: 두 데이터를 합치기, 그리고 30분 뒤의 과적합

작성일: 2026-11-19. [SeedLM-7](seed_lm7.md)의 후속이다. 사전학습 가중치 없이 처음부터 학습하고, 측정은 모두 이 저장소 환경(CPU 4코어)에서 했다.

## 요약

- SeedLM-6의 두 데이터는 교사 보류 과제 139개에서 서로 다른 곳을 고쳤다(첫 검증 프로그램이 맞는 과제: s5-var 52, 접붙이기 61, 교사 합성 과제 59). 둘을 함께 쓴 코더 s8-all을 학습 전에 등록하고 학습했다(학습 중에는 아무것도 같이 돌리지 않았다).
- 주 측정은 62개로, 등록한 지지 기준(63)에 하나 모자라 판단 보류다. 새 조합 프로그램에서는 접붙이기와 같은 24개, 조각을 모두 본 프로그램에서는 38개(합성 과제 40)였다. 두 데이터의 이득은 더해지지 않고 겹쳤다.
- 실제 개발 과제에서는 오히려 나빴다. 코더 혼자 53개(s5-var 57), 엔진과 섞은 최선 67개로 채택하지 않았다. 일곱 코더가 엔진 너머로 맞힌 과제는 여전히 같은 6개다.
- 대신 모든 코더에 공통된 모양을 찾았다. 학습 30·60·90분에 잰 보류 성능(각 집합의 처음 60개)은 교사 보류 과제와 실제 보류 프로그램 모두 30분에 가장 높고 그 뒤로 떨어진다. 합성 과제만 계속 오른다. 작은 데이터(20~95번 반복)를 30분쯤 지나면 외우기 시작하는데, 쓰는 코더는 언제나 120분 끝의 것이었다. 다음 실험(SeedLM-9)은 학습 데이터에서 떼어 둔 행으로 가장 좋은 시점을 고른다.

## 1. 설계

`reports/seedlm/seedlm8_protocol.json`. s5-var의 데이터(변형 과제 10% 포함)에 접붙이기 10%와 교사 합성 과제 10%를 더했다. 합성 라이브러리 행의 비율은 42%로 줄었다(s4-post 72%, s5-var 62%). 주 측정은 교사 보류 과제 전체에서 폭 32의 첫 검증 프로그램이 맞는 수이고, 63 이상이면 지지(두 단일 데이터 코더보다 2 이상), 58~62는 판단 보류, 57 이하는 기각이다.

교사 쪽 데이터를 더할수록 교사 보류 과제는 좋아지고(52 → 62), 실제 개발 과제의 코더 혼자 점수는 내려갔다(57 → 53). 실제 개발 과제의 정답은 대개 엔진의 라이브러리 연산으로 쓰이고, 그것을 가르치는 것은 합성 라이브러리 행이다. 그 비율이 72% → 42%로 줄어든 것과 함께 나빠졌다. 다만 s6-comp(합성 52%)는 실제 보류 프로그램이 오히려 좋았으므로, 비율 하나로 다 설명되지는 않는다.

## 3. 30분 뒤의 과적합

학습 중 30·60·90분에 잰 값(각 보류 집합의 처음 60개, 폭 8 빔의 첫 후보가 예시를 재현하는 비율)을 다섯 코더에 걸쳐 놓으면 모양이 같다.

| 코더 | 교사 보류 30 → 60 → 90분 | 실제 보류 프로그램 30 → 60 → 90분 | 합성 과제 30 → 60 → 90분 |
|---|---|---|---|
| s4-post | 0.450 → 0.467 → 0.350 | 0.750 → 0.750 → 0.733 | 0.950 → 0.983 → 0.933 |
| s5-var | 0.483 → 0.417 → 0.367 | 0.700 → 0.650 → 0.617 | 0.833 → 0.900 → 0.900 |
| s6-graft | 0.500 → 0.483 → 0.450 | 0.800 → 0.650 → 0.617 | 0.867 → 0.933 → 0.933 |
| s6-comp | 0.533 → 0.483 → 0.400 | 0.850 → 0.783 → 0.717 | 0.850 → 0.883 → 0.917 |
| s8-all | 0.567 → 0.550 → 0.483 | 0.800 → 0.700 → 0.700 | 0.833 → 0.833 → 0.867 |

교사 과제 3,924행은 120분 동안 20~27번, 실제 행은 40~59번, 개발 과제 한 줄 해답은 77~95번 반복된다. 합성 행은 30만 개라 한 번도 다 돌지 않는다. 작은 데이터는 30분 무렵이 가장 좋고, 그 뒤로는 외운다. 접붙이기를 넣은 코더(s6-graft, s8-all)는 떨어지는 폭이 작았는데, 접붙이기가 작은 데이터의 반복을 희석하기 때문으로 보인다.

이것은 지금까지 비교의 조건이기도 하다. 모든 코더를 같은 120분 끝에서 비교했으므로, 데이터가 더 쉽게 외워지는 쪽이 불리했을 수 있다. 같은 실행 안에서 학습 데이터로부터 떼어 둔 행으로 가장 좋은 시점을 고르는 것이 다음 실험이다(`reports/seedlm/seedlm9_protocol.json`). 측정 집합으로 고르면 측정이 오염되므로, 학습 과제의 20분의 1(실제 행, 교사 과제, 합성 과제, 과제 id의 해시로)을 학습에서 빼서 그것으로만 고른다.

## 한계

- 30·60·90분의 값은 각 집합의 처음 60개, 폭 8 빔으로 잰 것이라 학습 끝의 값(전체, 다른 방식)과 직접 비교할 수 없다. 추세만 본다.
- s8-all의 주 측정 차이(62 대 61)는 잡음 안이다.
- 실제 개발 과제의 판정은 여전히 작은 집합(94개, 엔진 실패 29개)에 기대고 있다.
