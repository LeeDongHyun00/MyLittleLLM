# SeedLM 보강 설계: 데이터 엔진, 유도 탐색, 합의 위원회, 되묻기

작성일: 2026-11-22. [지금까지 확인한 것](seedlm_findings.md)(SeedLM-4~29, 4차 교사 라운드)과 관련 논문을 대조해, 정체된 시스템을 어떻게 보강할지 정리한 설계 문서다. 여기 적은 효과는 모두 가설이고, 단계마다 측정 전에 등록할 관문을 함께 적었다. 아직 아무것도 구현하지 않았다.

## 0. 결론 먼저

1. 지금의 병목은 모델 구조나 탐색 폭이 아니라 **사람 말로 쓴 감독 데이터의 양**이다. 코더는 합성 행 30만 개를 보지만 글로 쓴 과제는 3,700개쯤이고, 한 번 학습에 같은 문장을 18~85번 되풀이해 읽는다. 30분 뒤의 과적합, 본 조합만 쓰는 성질, 문장 외우기가 모두 여기서 나온다.
2. 그래서 보강의 중심은 **데이터 엔진**이다. 프로그램을 만들고, 교사 모델이 설명을 쓰고, 다른 풀이기가 그 설명만 보고 같은 행동을 되찾을 때만 남긴다(왕복 검증). 목표는 검증된 쌍 5만 개(지금의 10배 이상)다.
3. 그 위에 세 가지를 얹는다. 서로 다른 데이터 조각으로 학습한 코더들의 **합의 위원회**(지금까지 순위를 바꾼 유일한 신호), 코더의 확률로 방향을 잡는 **상향식 탐색**(빔이 닿지 못하는 프로그램), 후보들이 갈릴 때 구별되는 입력을 골라 **되묻기**(설명과 예시만으로는 정해지지 않는 과제).
4. 하지 않을 것도 정했다. 틀로 찍은 설명의 합성 데이터 확대, 처음부터 학습한 판정기, 과제 하나짜리 수작업 연산, 40분을 넘는 학습은 이미 기각됐으므로 되풀이하지 않는다.

## 1. 요구사항

| 구분 | 내용 |
|---|---|
| 기능 | 과제 설명과 보이는 예시 하나(`assert f(args) == expected`)를 받아 파이썬 함수를 낸다. 확신이 없으면 그렇다고 알린다 |
| 제약 | CPU 4코어, RAM 15GB, GPU 없음. SeedLM의 가중치는 사전학습 없이 처음부터 학습한다. 코더 하나의 학습은 40분 |
| 평가 규율 | 실험마다 측정 전 등록. 보류 개발 과제(94)에서 69 초과 → 검증 관문 → 잠근 시험(151) 1회. 개발·시험 과제는 개수만 본다 |
| 지연 | 과제당 수십 초 안(지금: 코더 13개 합의 약 15초, 엔진 0.3초) |
| 성공 기준 | (a) 시스템이 개발 과제 69를 넘는다. (b) 코더만의 합의가 엔진 혼자(65)를 넘는다. (c) 교사 보류 과제의 새 조합 77개에서 단일 코더가 21 → 26개 이상 |

## 2. 지금 어디서 잃고 있나

보류 개발 과제 94개의 손실 예산이다(모두 기존 보고서의 개수).

| 단계 | 과제 수 | 다음 단계와의 틈 | 틈의 성격 |
|---|---|---|---|
| 엔진 혼자 | 65 | | |
| 시스템 (엔진 + s5-var) | 69 | | |
| 엔진 쪽이나 코더 중 누군가 맞힘 | 73 | 4 | **선택**: 맞는 답이 있는데 못 고른다 |
| 한 줄 식으로 쓸 수 있는 과제까지 | 약 83 | 10 | **도달**: 아무도 맞는 식을 쓰지 못한다 |
| 전체 | 94 | 11 | **명세**: 설명과 예시로 답이 정해지지 않음 9, 반복·상태 필요 2 |

세 틈에 대해 지금까지 확인한 것은 다음과 같다.

- **선택**: 한 코더 안의 합의(SeedLM-7), 틀린 후보 밀어내기(23), 실행 결과를 읽는 판정기(24), 자기 출력 설명(25)은 모두 실패하거나 판단 보류였다. 순위를 바꾼 것은 따로 배운 코더들의 합의뿐이다(교사 보류 과제 단일 57.8 → 72.9). 구조만 다르고 같은 데이터로 배운 코더는 독립적이지 않았다(20).
- **도달**: 코더는 통째로 본 구조는 78%, 새 조합이 낀 구조는 22% 맞힌다(5). 새 조합을 틀로 찍은 설명과 함께 넓게 보여 주면 정답의 확률은 오르지만 예시만 맞히는 틀린 이웃이 더 늘었다(12, 21). 교사가 **자연스럽게 쓴** 합성 과제 1,071개는 코더를 전반적으로 낫게 했다(6). 엔진에 연산을 손으로 더 써 주는 것은 본 과제에만 통했다(4차 라운드).
- **근본 원인**: 글로 쓴 학습 과제는 교사 과제 1,308, 변형 약 680, 합성 과제 1,071, 실제 과제 525, 한 줄 식 90개로 3,700개쯤이다. 40~80분 학습에서 실제 과제 행은 40~52번, 교사 과제 행은 18~24번, 한 줄 식 행은 64~85번 되풀이된다. 보류 과제 점수는 30분에 꺾이고(8), 같은 과제를 다른 문장으로 읽히면 그 손해가 없다(26).

## 4. 상위 설계

```
              ┌──────────────────────── A. 데이터 엔진 (오프라인) ────────────────────────┐
              │ 씨앗(학습 프로그램·연산) → 프로그램/과제 생성 → 실행 검증 → 교사가 설명 작성 │
              │      → 왕복 검증(다른 풀이기가 설명+예시로 같은 행동을 되찾는가) → 조각 1..K │
              └───────────────────────────────┬───────────────────────────────────────────┘
                                              │ 서로 겹치지 않는 조각
                        ┌─────────────────────┼─────────────────────┐
                        ▼                     ▼                     ▼
                   코더 1 (후위)          코더 2 (전위)   …     코더 K        ← 40분씩, 처음부터
                        │                     │                     │
 설명 + 예시 ──┬────────┴──────────┬──────────┴──────────┬──────────┘
               │                   │                     │
               ▼                   ▼                     ▼
          규칙 엔진        코더별 빔(폭 32)     B. 유도 상향식 탐색
          (깊이 2)                              (코더 확률 → 생성 규칙 비용)
               │                   │                     │
               └───────────────────┴──────────┬──────────┘
                                              ▼
                      C. 합의 위원회: 탐침 입력에서 행동으로 묶기 → 표 세기
                         (엔진 절반 + 코더, 동점은 가장 짧은 프로그램)
                                              │
                         ┌────────────────────┴────────────────────┐
                         ▼                                         ▼
                  한 묶음이 뚜렷이 앞섬                    두 묶음이 비슷함
                  → 함수 반환 (확신)                → D. 되묻기: 구별되는 입력을 골라 질문
                                                       또는 "확신 없음" 표시와 함께 반환
```

### 구성요소 사이의 계약

- 데이터 조각의 한 행: `{id, program(pyx 토큰), cases[3], outputs[3], literals, description, describer, roundtrip: {solver, probes_agreed}, new_edges, shard}`. 지금의 교사 과제 형식(`data/seedlm/*.json`)에 출처와 검증 기록을 더한 것이라 기존 학습 스크립트가 그대로 읽는다.
- 후보: `{program, source(engine | coder 이름 | search), log_prob, behaviour(탐침 24개의 결과)}`. `outputs/seedlm/v15`의 캐시 형식과 같다.
- 위원회의 답: `{code, support, clusters: [{behaviour, voters, program}], confident, question: {input, outputs_by_cluster} | null}`. `scripts/seedlm_solve.py`의 반환값을 넓힌다.

## 5. 구성요소별 설계

### A. 데이터 엔진 (가장 먼저)

**무엇을 만드나.** 검증된 (설명, 프로그램, 예시 셋) 쌍. 두 가지 방식으로 만든다.

1. 프로그램 먼저: 기존 생성기(`pysynth`, 접붙이기, 라이브러리 샘플)가 프로그램을 만들고 실행으로 검증한 뒤, 교사 모델이 "이 함수가 하는 일을 MBPP식 한 문장으로" 쓴다.
2. 과제 먼저: 학습 프로그램이나 연산을 씨앗으로 교사 모델이 새 과제(설명, 한 줄 풀이, 입력 셋)를 만든다. 풀이가 pyx로 옮겨지고 세 입력에서 돌아야 남긴다. 지금까지 교사 서브에이전트가 하던 일(교사 과제, 합성 과제)이다.

**왕복 검증.** 설명을 쓴 모델과 다른 풀이기(로컬 1.5B 모델, 또는 엔진과 코더 합의)가 설명과 첫 예시만 보고 프로그램을 쓴다. 탐침 입력 24개에서 원래 프로그램과 행동이 같을 때만 쌍을 남긴다. SeedLM-21의 실패(틀로 찍은 설명이 프로그램을 정하지 못해 틀린 이웃을 키움)를 데이터 단계에서 막는 장치다.

**교사.** 두 층으로 둔다. 양은 저장소에 이미 있는 로컬 모델(`models/qwen2.5-coder-1.5b/3b/7b`)이, 질은 교사 서브에이전트가 맡는다. SeedLM의 가중치는 여전히 처음부터 학습한다. 사전학습 모델을 데이터 교사로 쓰는 것은 지금까지 교사 서브에이전트가 해 온 일과 같은 성격이지만, 원칙에 닿는 결정이라 9절에 따로 적었다.

**균형.** 새 연결만 좇지 않는다. 조각마다 학습 프로그램과 같은 모양, 새 연결 하나, 새 잔가지를 정해진 비율로 섞고, 같은 프로그램은 서로 다른 설명 둘까지만 둔다(바꿔 쓰기의 효과, SeedLM-26).

**위험과 대응.** 로컬 모델의 설명이 서툴 수 있다 → 왕복 수율로 측정하고 낮으면 3B·7B로 올린다. 왕복을 통과하는 쌍이 쉬운 프로그램에 몰릴 수 있다 → 새 연결 비율을 조각의 통계로 기록하고, 치우치면 과제 먼저 방식의 비중을 올린다.

### B. 코더가 이끄는 상향식 탐색

**왜.** 빔은 위에서 아래로 한 토큰씩 쓰며 폭 32에서 자른다. 폭을 128로 넓히면 맞는 프로그램이 든 과제가 65 → 86개로 늘지만 시간은 3배이고 틀린 후보도 3.9 → 14.2개로 는다(s5-var, 교사 보류). 엔진은 값이 같은 식을 합치며 빠짐없이 찾지만 깊이 2, 라이브러리 연산뿐이다.

**어떻게.** HySynth처럼 코더의 다음 토큰 분포를 과제별 생성 규칙 비용으로 바꾼다. 과제마다 코더를 한 번 돌려(빔 8의 후보들에서 부모 → 자식 쌍의 확률을 모아) 연결마다 비용을 매기고, 비용이 낮은 순서로 아래에서 위로 식을 만든다. 보이는 예시와 탐침 입력 몇 개에서 값이 같은 식은 하나만 남긴다(엔진의 값 병합과 같다). 파이썬 노드와 라이브러리 연산을 함께 쓰고, 과제당 시간 예산(예: 10초) 안에서 예시를 재현하는 식을 모두 위원회에 넘긴다.

**위험.** 후보가 늘면 예시만 맞히는 틀린 식도 는다. 그래서 B는 혼자 쓰지 않고 C의 표 세기에 후보를 대는 역할만 한다. 코더가 0에 가까운 확률을 주는 새 연결은 여전히 비싸므로, 도달 틈의 일부만 닫을 것으로 본다.

### C. 합의 위원회

**무엇이 달라지나.** 규칙은 지금 것 그대로다(탐침 24개에서 행동으로 묶고, 엔진 쪽은 코더 수의 절반만큼 표, 동점은 가장 짧은 프로그램). 달라지는 것은 투표자다.

- 투표자를 **데이터로** 다르게 만든다. 데이터 엔진의 겹치지 않는 조각마다 코더를 하나씩 학습한다(배깅). 같은 데이터에 구조만 바꾼 코더는 독립적이지 않았고(20), 다른 데이터로 배운 전위 코더는 합의를 올렸다(17, 18).
- 투표자 수는 6~8개에서 멈춘다. 이득의 대부분은 처음 다섯에서 나온다(15).
- 선택 실험: **변환 투표자**. 프로그램을 쓰지 않고 (설명, 예시, 새 입력) → 출력을 바로 예측하는 작은 모델을 데이터 엔진의 실행 결과로 학습해, 후보 묶음마다 탐침 출력의 확률로 한 표를 준다. SeedLM-24의 판정기와 다른 점은 맞다·틀리다를 후보 1만 6천 개로 배우는 대신 출력을 실행 결과 수십만 건으로 배운다는 것이다. 그래도 가까운 시도가 이미 실패했으므로 작은 시험(코더 하나 학습 분량)에서 기각되면 접는다.

### D. 되묻기와 보류

**왜.** 엔진 실패 29개 중 9개는 설명과 예시만으로는 답이 정해지지 않는다. 어떤 모델을 써도 맞히면 우연이다. 선택 틈 4개도 같은 성격이 섞여 있다.

**어떻게.** 위원회의 1위 묶음과 2위 묶음의 표가 비슷하면, 두 묶음의 출력이 갈리는 탐침 입력 중 가장 단순한 것을 골라 "이 입력의 답은 무엇인가"를 묻는다. 답을 받으면 그 입력을 두 번째 예시로 넣어 다시 고른다. 물을 수 없는 환경에서는 `confident: false`와 두 후보를 함께 돌려준다.

**측정.** 잠근 지표(예시 하나)는 그대로 두고 별도 지표를 만든다. 개발 과제에서 과제 자신의 남은 테스트를 답하는 사람으로 삼아 "질문 1회 뒤 해결 수"를 센다. 두 지표는 섞어 보고하지 않는다.

### E. 압축으로 만드는 연산 (후순위)

교사가 과제를 보고 쓴 연산은 처음 보는 과제에서 쓰이지 않았다. 대신 검증된 프로그램들(교사 과제, 데이터 엔진 산출물)에서 되풀이되는 부분 트리를 찾아 연산으로 올리면, 정의상 여러 과제에 걸친 것만 남는다(LILO, Stitch). 키워드는 그 부분 트리가 쓰인 과제 설명들의 공통 단어에서 뽑는다. 데이터 엔진이 돈 뒤에야 재료가 생기므로 뒤로 미룬다.

## 6. 규모와 비용

로컬 1.5B 모델의 측정값(프롬프트 226토큰/초, 생성 17.5토큰/초, 풀이 하나 평균 5.4초)으로 어림한 값이다. 실제 수율은 0단계에서 잰다.

| 항목 | 어림 |
|---|---|
| 설명 하나 쓰기 (프롬프트 150토큰, 생성 30토큰) | 약 2.5초 |
| 왕복 풀이 한 번 | 약 5.4초 |
| 후보 쌍 하나 | 약 8초 → 하루 1만 개(학습이 없을 때) |
| 왕복 수율을 30~50%로 잡으면 | 검증된 쌍 하루 3천~5천 개 |
| 검증된 쌍 5만 개 | CPU 10~17일(학습과 번갈아 쓰면 더 김) |
| 교사 서브에이전트로 같은 양을 쓰면 | 과제당 약 400~750토큰 → 2천만~4천만 토큰 |
| 저장 | 쌍 5만 개 약 50MB (git에는 조각 요약과 생성 스크립트, 원본은 `outputs/`) |
| 추론 | 코더 8개 약 10초 + 유도 탐색 10초 + 엔진 0.3초 |

학습과 데이터 생성은 같은 4코어를 쓰므로 번갈아 돈다. 한 번에 4스레드 작업 하나라는 규칙은 그대로다.

| 결정 | 고른 것 | 버린 것 | 이유 |
|---|---|---|---|
| 데이터의 설명 | 교사 모델이 쓰고 왕복 검증 | 틀로 찍은 설명 | SeedLM-12, 21: 틀 설명은 틀린 이웃을 키웠다 |

**제약을 푸는 대안.** 목표가 "처음부터 만든 모델"이 아니라 "이 장비에서 가장 잘 푸는 시스템"이라면, 이미 있는 1.5B 파이프라인(시험 98/151)이 출발점이고 SeedLM은 거기에 더하는 것이 없었다. 이 설계는 처음부터 만든다는 제약을 유지하는 쪽이다. 제약을 푼다면 A의 데이터로 0.5B 모델을 미세조정하는 길이 가장 짧지만, 이 환경에는 GPU가 없어 미세조정 자체가 어렵다.

단계마다 측정 전에 `reports/seedlm/`에 등록하고, 관문을 못 넘으면 다음 단계로 가지 않는다.

| 단계 | 하는 일 | 관문 | 접는 조건 |
|---|---|---|---|
| 0. 수율 측정 (1일) | 프로그램 500개를 1.5B·3B·7B로 설명하고 왕복 검증. 시간과 수율을 잰다 | 왕복 수율 25% 이상, 시간당 검증 쌍 150개 이상 | 어느 모델도 못 넘으면 과제 먼저 방식과 서브에이전트 층만 남긴다 |

기대치는 낮게 잡는다. 선택 틈은 4개, 도달 틈은 10개이고, 지금까지 스무 번 넘는 시도가 시스템을 1~2개 범위에서만 움직였다. 1단계가 이 설계 전체의 갈림길이다. 여기서 데이터의 질이 통하지 않으면 양을 늘려도 소용이 없다.

## 9. 결정이 필요한 것

1. **로컬 사전학습 모델(Qwen 1.5B~7B)을 데이터 교사로 써도 되는가.** SeedLM의 가중치는 계속 처음부터 학습한다. 지금까지 교사 서브에이전트가 과제와 연산을 써 온 것과 같은 성격이지만, "외부 말뭉치 없이"라는 원칙을 어디까지로 볼지의 문제다.
2. **되묻기 지표를 둘 것인가.** 예시 하나라는 조건이 달라지는 별도 지표다.
3. **토큰 예산.** 서브에이전트 층을 얼마나 쓸지(예: 고품질 5천 쌍에 약 300만 토큰).

## 10. 나중에 다시 볼 것

- 검증된 쌍이 5만 개를 넘으면 모델 크기(1,200만 → 3,000만)를 다시 잰다. 지금은 데이터가 먼저 막혀 있어 크기를 키운 효과가 모방으로만 갔다(SeedLM-3b).
- 조각이 많아지면 위원회를 코더 하나로 증류해 추론 비용을 줄인다.
- 검색해 온 풀이를 함께 읽는 코더(MLC식 소과제 학습): 설명의 단어로는 친척을 못 찾았지만(SeedLM-22), 데이터가 커지고 학습된 검색기가 생기면 다시 본다.
- 반복과 상태가 필요한 과제(개발 과제 2개)는 문장 언어가 필요하지만 몫이 작아 미뤘다.

## 11. 추가 (2026-11-22): 교사를 Opus 5.5로 두고 규칙을 계속 주입하는 고리

사용자 방침에 따라 교사는 Opus 5.5 서브에이전트로 둔다(9절의 결정 1은 로컬 모델을 쓰지 않는 쪽으로 정리한다). 교사 토큰이 가장 비싼 자원이 되므로, 질문은 "교사가 쓴 것 하나가 처음 보는 과제에 얼마나 옮겨 가는가"로 바뀐다.

### 11.1 무엇을 주입할 것인가: 연산이 아니라 뼈대

4차 라운드의 연산 74개는 학습 과제 64개를 새로 풀고 보류 과제에서는 한 번도 쓰이지 않았다. 과제 하나를 보고 쓴 규칙은 그 과제의 풀이였다. 그런데 엔진이 못 푸는 과제의 한 줄 식은 새 연산이 아니라 이미 있는 연산과 파이썬 노드를 새로 배열한 것이다. 그래서 배열 자체가 되풀이되는지를 쟀다(`scripts/seedlm30_sketches.py`, `reports/seedlm/sketch_coverage.json`, 교사 토큰 0, 측정 전 등록 없는 탐색 진단).

프로그램의 **뼈대**는 트리에서 토큰 S개 이하의 부분 트리를 모두 구멍으로 바꾼 것이다(S = 5면 `x % 2 == 0`이나 `len(a0) - 1` 정도가 구멍 하나에 들어간다). 구멍은 작은 전수 탐색이 채울 수 있는 부분이고, 뼈대는 남는 큰 구조다.

| 교사가 쓴 학습 프로그램 3,143개, 5겹 교차 (다른 네 몫에서 2번 이상 나온 뼈대만 인정) | 덮인 프로그램 |
|---|---|
| S = 1 (리프만 구멍) | 2% |
| S = 3 | 38% |
| **S = 5** | **62%** (뼈대 약 220개, 구멍 중앙값 3개) |
| S = 5, 가장 흔한 뼈대 50개만 | 52% |
| S = 5, 교사 프로그램 500 / 1,000 / 2,000개로 만든 뼈대 | 48% / 55% / 60% |

설정(S = 5, 2번 이상)은 이 대리 측정으로 골랐고, 보류 집합은 개수만 셌다.

| 보류 집합 (S = 5, 2번 이상) | 뼈대 + 구멍으로 표현됨 | 지금의 코더 |
|---|---|---|
| 교사 보류 139 | **118** (그중 65개는 프로그램 전체가 5토큰 이하) | 단일 코더 59~62 |
| ― 새 조합이 낀 77 | 61 | 단일 코더 약 21 |
| ― 저장된 코더 48개 누구도 못 맞힌 32 | 18 | 0 |
| 범위 밖(엔진이 못 푸는 개발 과제의 한 줄 식) 15 | **9** (그중 7개는 전체가 5토큰 이하) | 단일 코더 2~5 |

읽는 법은 세 가지다.

- 처음 보는 프로그램의 큰 구조는 대부분 이미 본 뼈대다. 새로운 것은 구멍 속의 작은 식이고, 그것은 모델이 외울 대상이 아니라 탐색이 채울 대상이다. 코더가 "본 조합만 쓴다"는 법칙은 토큰 단위에서의 이야기였다.
- 뼈대는 적은 수로 충분하다. 50개가 절반을 덮는다. 반대로 교사 프로그램을 두 배로 늘려도 5~6%p만 는다. 교사에게 풀이를 더 쓰게 하는 것은 효율이 낮다.
- 이 수는 "맞는 프로그램이 탐색 공간 안에 있다"는 뜻이지 찾아서 고른다는 뜻이 아니다. 구멍을 채우는 식이 늘면 예시만 맞히는 틀린 프로그램도 는다. 남는 문제는 여전히 선택이다.

### 11.2 고리

```
 ① 새 과제 풀(교사가 쓴 설명 + 예시, 풀이 없음)
        │  시스템이 푼다: 엔진 + 뼈대 탐색 + 코더 위원회
        ▼
 ② 고르기: 위원회가 갈리거나 아무도 못 푼 과제만 교사에게 보낸다 (전체의 일부)
        ▼
 ③ 교사(Opus 5.5): 풀이 한 줄, 또는 시스템이 낸 후보 중 맞는 것 고르기 + 그 뼈대를 부르는 말
        ▼  실행 검증(세 예시), 오염 검사
 ④ 자동 귀납: 풀이들을 압축해 뼈대 후보를 만든다 → 서로 다른 과제 2개 이상에서 나오고,
    교차 검증에서 다른 몫의 프로그램을 실제로 덮을 때만 등록 (과제 하나짜리 규칙은 못 들어온다)
        ▼
 ⑤ 주입 (학습 없이 즉시): 엔진에 뼈대 = 구멍 있는 연산으로 등록, 키워드는 그 뼈대가 쓰인 설명들의 공통 단어
    주입 (12분): 코더를 재생 데이터와 함께 400걸음 미세조정해 뼈대를 먼저 쓰게 한다
        ▼
 ⑥ 회귀 검사(풀던 과제가 깨지지 않는가) → 교차 검증 이득이 기준 아래면 그 라운드에서 멈춘다
```

기법과 근거는 다음과 같다.

| 고리의 자리 | 기법 | 근거 |
|---|---|---|
| ③→④ 규칙의 단위 | 뼈대(구멍 있는 프로그램): 신경망은 뼈대를, 탐색은 구멍을 맡는다 | [SketchAdapt](https://arxiv.org/abs/1902.06349)(Nye 외 2019); 11.1의 측정 |
| ④ 귀납 | 풀이 말뭉치를 압축해 되풀이되는 추상화를 찾는다 | [Stitch](https://arxiv.org/abs/2211.16605)(Bowers 외 2023), [LILO](https://arxiv.org/abs/2310.19791), [ReGAL](https://arxiv.org/abs/2401.16467) |
| ④ 등록 조건 | 실제 재사용을 측정해 확인한다 | [Library Learning Doesn't](https://arxiv.org/abs/2410.20274)(Berlot-Attwell 외 2024): 라이브러리 학습의 이득이 재사용이 아닌 데서 온 사례. 4차 라운드도 같은 실패였다 |
| ② 교사에게 보낼 것 고르기 | 위원회 불일치(query by committee)와 여유(margin) | [교사를 오라클로 둔 증류의 선택 기준 비교](https://aclanthology.org/2024.findings-acl.704.pdf)(ACL 2024 Findings): 두 기준이 꾸준히 이득 |
| ①→③ 오류에서 다음 데이터를 만들기 | 작은 모델의 오류를 교사에게 돌려 그 주변을 더 쓰게 한다 | [S3](https://arxiv.org/abs/2310.13671)(Wang 외 2023) |
| ⑤ 코더 쪽 주입 | 재생 데이터를 섞은 짧은 미세조정 | SeedLM-1(새 규칙만 보이면 54% → 25%로 잊고, 절반을 섞으면 유지), SeedLM-23·26의 400걸음 틀 |

교사의 일은 세 가지로 줄어든다. 풀 과제 쓰기(설명과 예시만, 싸다), 고른 과제의 풀이나 후보 판정(가장 값진 부분), 뼈대를 부르는 말 붙이기(뼈대 200개면 한 번에 끝난다). 연산을 손으로 쓰는 일은 없앤다.

### 11.3 순서와 관문

| 단계 | 하는 일 | 교사 토큰 | 관문 |
|---|---|---|---|
| a. 뼈대 탐색 (SeedLM-31) | 지금 가진 프로그램에서 뼈대 약 220개를 뽑아, 구멍을 5토큰 이하 식으로 채우는 탐색을 엔진 옆에 붙인다. 후보는 위원회로 넘긴다 | 0 | 교사 보류 과제에서 "맞는 후보가 하나라도 있음"이 단일 코더 빔(74~80)을 넘어 100 이상, 과제당 10초 이내 |
| b. 고르기 | 뼈대 빈도, 설명의 단어, 코더 확률, 위원회 표로 순위를 매긴다 | 뼈대의 말 붙이기 약 20만 | 교사 보류 과제 첫 답 66 이상(지금 단일 60, 합의 73), 개발 과제 시스템 69 초과 → 검증 관문 → 시험 1회 |
| c. 고리 1회 | 새 과제 1,000개 → 불일치 과제만 교사에게 → 귀납 → 주입 | 약 100만 | 교차 검증 덮임 +3%p 이상, 보류 과제 이득이 a·b에서 난 만큼 유지 |

a는 교사 없이 지금 할 수 있고, 여기서 맞는 후보가 늘지 않으면 이 절 전체를 접는다. **결과(2026-11-22):** a단계는 교사 보류 과제 67 → 88(기준 100에 못 미쳐 판단 보류), 엔진이 못 푸는 개발 과제 3 → 11, 과제당 4.6초였다([SeedLM-30~31](seed_lm30.md)). 도달은 열렸으므로 b단계(고르기)로 간다. A절의 데이터 엔진은 교사가 Opus인 한 양을 5만까지 키우기 어려우므로, 뼈대가 통하면 그쪽을 먼저 하고 데이터 엔진은 ①의 과제 풀을 대는 역할로 줄인다.
