# SeedLM-21~: 새 조합을 보여 주는 데이터는 왜 정답을 늘리지 못하나

작성일: 2026-11-20. [SeedLM-5](seed_lm5.md)에서 코더는 본 적 있는 조합만 만든다는 것을 확인했고, [SeedLM-6](seed_lm6.md)과 [SeedLM-12](seed_lm12.md)에서 처음 보는 연결을 학습 프로그램에 접붙인 데이터는 반복 실험에서 효과가 없었다. 이 문서는 새 연결이 실제로 어디에 있는지 다시 세고, 그 자리를 겨냥한 생성 데이터로 같은 질문을 한 번 더 시험한 기록이다. 측정은 모두 측정 전에 등록했다.

## 요약

- 보류 교사 과제의 정답 프로그램에서 학습에 없던 부모 → 자식 연결 98개 중 85개가 파이썬 노드(산술, 비교, 인덱싱, 내장 함수, 메서드, 내포)가 낀 연결이다. 라이브러리 연산끼리는 9개, 라이브러리 연산과 리프 사이는 4개뿐이다. 코더의 합성 데이터 30만 행은 라이브러리 연산만으로 되어 있다.
- 파이썬 노드와 라이브러리 연산을 섞은 프로그램 3만 개를 만들어(보류 과제의 새 연결 98개 중 31개를 덮음) 40분 코더 셋을 학습했다(SeedLM-21). 교사 정답 프로그램의 손실은 새 연결에서도(4.15 → 3.52 nats) 나머지 모든 자리에서도 내려갔지만, 정답을 쓴 과제는 줄었다. 새 조합 과제 77개에서 21.3 → 20.3개, 조각을 모두 본 과제 62개에서 38.7 → 35.0개. 기각이다.
- 접붙이기(SeedLM-12)와 같은 모양이 다른 데이터로 되풀이됐다. 새 조합을 넓게 보여 주면 맞는 프로그램의 확률과 함께 틀린 이웃의 확률도 오르고, 보이는 예시가 하나뿐이면 예시를 재현하는 이웃이 먼저 뽑힌다.

## 1. 새 연결은 파이썬 노드 쪽에 있다

연결은 프로그램 트리의 부모 → 자식 쌍(리프는 종류로 줄임)이다(`scripts/seedlm5_fragments.py`). 학습에 없다는 것은 합성 라이브러리 프로그램 10만 개와 모든 학습 프로그램(교사 과제, 변형, 개발 과제 한 줄 식, 엔진의 실제 과제 프로그램)에 없다는 뜻이다.

| 부모 → 자식 | 보류 교사 과제 | 범위 밖 15 |
|---|---|---|
| 파이썬 노드 → 라이브러리 연산 | 35 | 4 |
| 그 밖의 파이썬 노드가 낀 연결 | 50 | 17 |
| 라이브러리 연산 → 라이브러리 연산 | 9 | 0 |
| 라이브러리 연산 → 리프 | 4 | 2 |
| 합계 | 98 | 23 |

(`reports/seedlm/pysynth_coverage.json`의 갈래별 수를 묶은 것. 파이썬 노드는 내장 함수, 메서드, 내포를 포함한다.) 합성 데이터는 라이브러리 연산끼리의 연결을 촘촘히 덮지만, 파이썬 노드가 낀 연결은 교사가 쓴 수천 개 프로그램에서만 온다.

## 2. 생성기 (SeedLM-21)

`mylittlellm/seedlm/pysynth.py`는 학습 교사 과제와 변형의 입력(실제 같은 인자, 예시 셋)을 받아 식을 아래에서 위로 키운다. 한 걸음마다 지금까지의 식 위에 파이썬 노드나 라이브러리 연산 하나를 얹고, 다른 피연산자는 인자, 설명의 상수, 작은 정수와 짧은 문자열, 한 걸음짜리 곁가지 식에서 고른다. 내포는 원소(또는 `range(len(...))`, `zip`, `enumerate`)에 대한 식과 조건을 한두 걸음 만들고 `sum`, `max`, `any`, `''.join`, `len` 같은 소비자로 감싼다. 새 식은 세 예시 모두에서 실행해 본다. 남기는 프로그램은 모든 예시에서 돌고, 인자를 쓰고, 걸음마다 어떤 예시에서든 값을 바꾸고, 출력이 두 가지 이상인 것뿐이다. 텍스트는 `pyx.serialize`로 토큰이 되고 `pyx.execute`로 같은 값을 내는지 다시 확인한다. 설명은 접붙이기처럼 노드 단어로 엮는다(`pyx_words`).

라이브러리 연산을 뽑는 방식은 학습 프로그램만으로 만든 대리 측정에서 골랐다. 학습 교사 과제와 변형을 다섯 몫으로 나누고, 각 몫에서 나머지 학습 데이터에 없는 연결을 생성 프로그램 3만 개가 얼마나 덮는지 쟀다(`scripts/seedlm21_coverage.py`).

| 연산 뽑기 | 새 연결을 모두 덮은 프로그램 (970개 중) | 덮은 연결 (1,696개 중) |
|---|---|---|
| 전체 연산을 고르게 | 232 | 471 |
| 학습 프로그램이 쓰는 연산을 고르게 | 253 | 487 |
| **학습 프로그램이 쓰는 연산을 빈도의 제곱근 비율로** | **283** | **550** |

고른 설정으로 보류 집합의 덮임을 훈련 전에 한 번만 쟀다. 보류 교사 과제의 새 연결 98개 중 31개, 새 연결을 가진 프로그램 65개 중 15개를 모두 덮는다. 범위 밖 15개에서는 23개 중 9개다. 접붙이기 데이터가 새 조합 프로그램 77개 중 7개의 조각만 가졌던 것(SeedLM-6)보다 두 배 넘게 넓다.

## 3. 결과

코더는 SeedLM-12의 대조군 s12-a1~a3와 같은 인자에 생성 프로그램 15%를 더해 시드 1~3으로 40분씩 학습했다(s21-y1~y3, `reports/seedlm/seedlm21_protocol.json`). 각 과제에서 폭 32 빔의 첫 검증 프로그램이 모든 예시에서 맞는지를 센다(`scripts/seedlm21_compare.py`, `reports/seedlm/pysynth_compare.json`).

| 보류 교사 과제 | 대조군 s12-a1~a3 | s21-y1~y3 | 평균 차이 |
|---|---|---|---|
| **새 조합 77 (주 측정)** | 20, 21, 23 | 19, 22, 20 | **−1.0** |
| 조각을 모두 본 62 (보호 조건) | 39, 38, 39 | 37, 36, 32 | −3.7 |
| 전체 139 | 59, 59, 62 | 56, 58, 52 | −4.7 |
| 개발 과제 94 (혼자) | 56, 53, 58 | 56, 58, 51 | −0.7 |

| 교사 정답 프로그램 토큰의 손실 (nats, 평균) | 대조군 | s21 |
|---|---|---|
| 보류 교사: 새 연결 / 1순위 비율 | 4.15 / 32% | **3.52** / 36% |
| 보류 교사: 본 연결 | 2.24 | 2.08 |
| 범위 밖: 새 연결 | 8.25 | **7.47** |
| 범위 밖: 본 연결 | 4.20 | 3.86 |

주 측정은 +4 이상이면 지지, +1 이하면 기각으로 정했다. −1.0이라 기각이고, 노리지 않은 과제(조각을 모두 본 과제)에서는 보호 조건(−3 이내)도 넘겨 잃었다. 그런데 정답 프로그램은 어디서나 더 그럴듯해졌다. 새 연결 토큰의 손실은 0.6~0.8 nats 내려갔고, 본 연결과 리프도 함께 내려갔다. 코더 스물넷의 합의는 개발 과제 64.72(스물하나 64.63), 교사 보류 과제 72.17(71.23)로, 새 코더가 혼자 약한데도 합의에서는 교사 과제를 조금 되돌렸다(`reports/seedlm/ensemble_occam_24.json`).

## 한계

- s21 코더는 대조군과 다른 컨테이너에서 같은 40분에 걸음을 덜 갔다(1,667, 1,820, 1,812 대 2,087, 1,959, 1,943). 같은 컨테이너에서 SeedLM-20의 전위 코더도 SeedLM-18보다 11%쯤 덜 갔으므로 대부분은 장비 차이로 보지만, 데이터 몫을 가르지는 않았다.
- 시드는 한쪽에 셋이다. 생성 프로그램의 설명은 노드 단어를 엮은 것이고 자연스러운 문장이 아니다.

## 재현

```bash
python scripts/seedlm21_coverage.py --count 30000 --library sqrt --output reports/seedlm/pysynth_proxy_sqrt.json   # all, training 도 같은 식
python scripts/seedlm21_coverage.py --count 30000 --library sqrt --held-out --output reports/seedlm/pysynth_coverage.json
python scripts/seedlm21_pysynth.py --count 30000 --library sqrt --save
for seed in 1 2 3; do
  python scripts/seedlm4_train.py --name s21-y$seed --minutes 40 --d-model 320 --layers 8 --heads 10 --views 3 --seed $seed \
      --variant-share 0.1 --pysynth-share 0.15 --pysynth-count 30000 --pysynth-library sqrt
  python scripts/seedlm15_ensemble_scaling.py cache --coders s21-y$seed
  python scripts/seedlm5_fragments.py --model s21-y$seed
done
python scripts/seedlm21_compare.py --arm s21-y1 s21-y2 s21-y3 --control s12-a1 s12-a2 s12-a3 --output reports/seedlm/pysynth_compare.json
python scripts/seedlm16_occam.py --output reports/seedlm/ensemble_occam_24.json
```
