# SeedLM 종합 정리: 처음부터 만든 소형 코더와 규칙 엔진 — 무엇이 통했고 어디서 멈췄나

작성일: 2026-11-23. SeedLM-1부터 SeedLM-39까지, 그리고 교사 라운드 3~5의 결론을 한곳에 모은다. 각 실험의 자세한 내용은 7절의 문서 지도에 있다. 모든 학습과 측정은 이 저장소 환경(CPU 4코어, GPU 없음)에서 했고, 판정은 거의 모두 측정 전에 등록한 기준을 따랐다.

## 한 문단 요약

SeedLM은 사전학습 가중치 없이 처음부터 학습한 소형 트랜스포머(최대 1,240만 파라미터)와, 교사 서브에이전트가 쓴 연산 780개로 도는 규칙 엔진을 묶은 코드 생성 시스템이다. 가장 좋은 시스템(엔진 + 코더 s5-var)은 잠근 MBPP+ 시험 151문제 중 **72문제**를 푼다. 엔진 혼자는 68문제, 사전학습된 0.5B 학생 혼자는 56문제다. 성적을 만든 것은 주로 엔진이다. 교사가 실제 실패 489개를 보고 쓴 연산이 시험을 57 → 68로 올렸고(3차 라운드), 코더는 엔진의 동점 고르기와 빈자리 채우기로 +4를 보탰다(SeedLM-5). 그 뒤 서른 번 넘는 실험(SeedLM-6~39, 교사 라운드 4~5)은 시스템을 한 문제도 올리지 못했다. 원인은 세 겹이다. 코더는 본 조합만 쓰고 보여 준 과제를 외운다. 예시 하나로는 고를 신호가 거의 없다. 무엇보다 남은 실패는 엔진 연산의 조합이 아니라 과제마다 다른 지식을 요구하며, 교사가 겨냥해 쓰든 지어낸 문제로 쓰든 연산으로 넣은 지식은 처음 보는 과제로 옮겨 가지 않았다. 판정도 다시 쟀다. 개발 과제의 assert 셋은 느슨해서 엄격하게 보면 시스템은 69가 아니라 58~69 사이이고, 남은 틈은 고르기(4~7)보다 도달(18~32)이다.

## 3. 통한 것

1. **실제 실패에서 공통된 요구를 연산으로 만들기.** 3차 라운드에서 교사 다섯이 실패 489개를 보고 쓴 연산 452개가 잠근 시험을 57 → 68로 올렸다(고침 11, 깨뜨림 0). 이 프로젝트에서 시험 성적을 가장 크게 올린 단일 조치다.
2. **규칙을 지시가 아니라 실행으로 확인하기.** 규칙을 프롬프트로 읽힌 모델은 나빠졌고, 규칙을 가설로 실행해 고르는 쪽이 이겼다(1.5B와 엔진 89 → 97, [가능성 검토](rule_distillation_feasibility.md)).
3. **엔진과 코더의 역할 나누기.** 코더는 엔진을 넘어서지 못하지만, 엔진의 동점을 고르고 빈자리를 채우는 데서 +4를 보탰다(시험 68 → 72). 엄격한 판정에서도 동점 고르기의 +2는 남는다.
4. **독립된 출처 사이의 합의.** 따로 학습한 코더들의 합의는 단일 코더보다 크게 낫다(교사 보류 57.8 → 72.9). 1.5B 파이프라인에서는 엔진과의 확증이 시험 98 → 102를 만들었다([합의](consensus.md)). 반대로 한 코더의 빔 안(SeedLM-7)이나 같은 데이터에서 배운 출처끼리(SeedLM-38)의 합의는 증거가 아니었다.
5. **측정의 규율.** 한 번의 실행끼리 비교한 효과는 같은 구성의 반복 실행 사이 흔들림(교사 보류 9개)에 묻혔고(SeedLM-9, 12), 쌍 미세조정과 시드 반복이 그것을 걸러 냈다. 측정 전 등록 덕분에 개발 과제를 반복해서 들여다보는 일 없이 판정했다.

## 4. 통하지 않은 것, 그리고 거기서 나온 법칙

| 법칙 | 근거 |
|---|---|
| **본 조합의 법칙.** 코더는 통째로 본 구조는 78% 맞히지만 처음 보는 연결이 하나라도 있으면 4분의 1 아래로 떨어지고, 처음 보는 연결을 만드는 토큰을 1순위로 두지 않는다 | [SeedLM-5](seed_lm5.md) |
| **넓게 가르치면 틀린 이웃도 자란다.** 새 연결을 넓게 덮는 데이터(접붙이기, 파이썬 노드 합성 3만)는 정답의 손실을 낮추면서 예시만 맞히는 틀린 프로그램을 함께 늘렸다 | [SeedLM-12](seed_lm12.md), [SeedLM-21](seed_lm21.md) |
| **외움의 법칙.** 작은 자연어 데이터는 30분쯤 지나면 외워지고(SeedLM-8, 9, 27), 같은 문장을 되풀이하면 잃는다(바꿔 쓴 문장은 이 손해만 막는다, SeedLM-26). 구조도 마찬가지다. 뼈대마다 쓴 과제는 세 번 보여 주면 77% 쓰지만 처음 보는 과제로는 옮겨 가지 않았다 | [SeedLM-26~29](seed_lm26.md), [SeedLM-34](seed_lm34.md) |
| **예시 하나의 한계.** 보이는 예시 하나를 재현하는 프로그램들 사이에서, 코더 자신의 확률과 독립 코더의 합의 말고는 순위를 바꾼 신호가 없다. 검증기(−7~−13), 빔 안 합의, 자기 설명, 검토기, 구조 사전, 위원회 모두 실패했다 | [SeedLM-21~25](seed_lm21.md), [SeedLM-30~33](seed_lm30.md), [SeedLM-35](seed_lm35.md) |
| **판정의 느슨함.** assert 셋을 통과한 답의 여섯에 하나는 탐침에서 참조 해답과 어긋나고, 그 절반쯤은 진짜 오답이다. 후보를 70개씩 만드는 탐색이 넓힌 "도달"은 대부분 이런 우연이었다(개발 10 → 4) | [SeedLM-36~39](seed_lm36.md) |
| **지식의 벽.** 엔진의 도달은 관문을 모두 열어도, 탐색을 세 단계로 깊게 해도, 일치의 순서를 가장 잘 바꿔도 1~3%밖에 늘지 않는다. 실패를 보고 겨냥한 연산 74개(4차)도, 지어낸 연습문제로 쓴 연산 277개와 366개(5차 시범 두 번)도 처음 보는 실제 과제에서 순이득이 0이었다 | [SeedLM-36~39](seed_lm36.md) 5b절, [4차](rule_round4.md), [5차 시범](rule_round5_pilot.md) |

## 5. 왜 여기서 멈췄나

엄격하게 보면 보류 개발 과제 94개 가운데 엔진, 여러 코더의 빔, 뼈대 탐색 중 누군가 맞는 프로그램을 내는 과제는 62~76개이고, 시스템은 그중 58~69개를 고른다. 고르는 쪽에서 남은 몫은 4~7개다. 나머지 18~32개는 어디에도 맞는 프로그램이 없다. 이 과제들은 다음 중 하나다.

- 설명과 보이는 예시만으로는 답이 정해지지 않는다. 숨은 상수, 테스트에만 있는 문구, 설명과 다른 참조 해답이 그렇다. 엔진 실패를 교사가 분류했을 때 9개였다.
- 지금 연산의 조합이 아닌 과제별 지식이 필요하다. 이름 붙은 정의, 관례, 특정한 출력 형식 같은 것이다. 이런 실패는 과제마다 제각각이라, 한 과제를 보고 쓴 연산이 다른 과제에 쓰이지 않는다.

처음부터 학습한 1,240만 파라미터 모델이 실제 과제 525개와 교사 과제 약 3,000개로는 그런 지식을 얻지 못한다. 교사가 연산으로 써 넣는 지식은 공통된 요구가 남아 있을 때만(3차 라운드) 옮겨 갔다. 사전학습된 1.5B 모델이 같은 시험에서 98~102문제를 푸는 차이는 대부분 이 지식에서 나온다.

## 6. 다시 연다면

1. **지식의 출처를 바꾼다.** "사전학습 가중치 없이"라는 조건이 지금 가장 강하게 묶는 제약이다. SeedLM의 구성요소(엔진, 탐침, 엄격한 판정, 합의)를 사전학습 모델의 검증기로 쓰는 쪽은 이미 이득을 냈다(1.5B 98 → 102).
2. **처음부터라는 조건을 지킨다면, 데이터의 규모를 몇 자릿수 키워야 한다.** 교사가 쓴 교과서풍 데이터로 작은 모델을 키운 선행 연구(phi-1)는 수십억 토큰을 썼다. 이 환경의 학습 속도(어림으로 초당 8천 토큰)로는 1억 토큰에 서너 시간이 든다. 교사가 검사를 통과하는 과제를 쓰는 데도 과제 1,000개에 교사 토큰 100만~150만이 들었다(SeedLM-34, 5차 시범).
3. **어느 쪽이든 판정은 엄격하게 한다.** 개발 과제는 느슨한 판정과 엄격한 판정을 함께 보고, 채택은 두 판정 모두에서 지금 시스템을 넘을 때로 한다([SeedLM-36~39](seed_lm36.md) 4절).
