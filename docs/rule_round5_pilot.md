# 5차 라운드 시범 두 번: 교사가 지어낸 연습문제로 쓴 연산은 실제 과제에 닿지 않는다

작성일: 2026-11-23. 측정 전에 등록했다(`reports/seedlm/round5_pilot_protocol.json`). [SeedLM-36~39](seed_lm36.md)에서 엔진의 남은 실패는 지금 연산의 조합이 아니라 라이브러리에 없는 지식을 요구한다고 읽었다. 3차 라운드는 실제 실패 489개에서 공통된 요구를 연산으로 만들어 잠근 시험을 57 → 68로 올렸지만, 실제 과제 풀은 이제 다 썼다. 그래서 실패 사례를 보지 않고 지식을 주입할 수 있는지 시범으로 쟀다.

## 요약

- 과제 교사(Opus 5.5) 하나가 입문~중급 파이썬 연습문제 300개를 지어냈다(설명, assert 셋, 참조 해답). 실제 과제와 가까운 13개를 빼고 남은 287개 가운데 지금 엔진이 푸는 것은 19개뿐이었다.
- 연산 교사 하나가 실패 268개를 보고 연산 277개(모두 관문 있음)와 키워드 확장 9개를 썼다. 자기 은행에서 209개를 새로 풀고, 이미 풀던 것은 하나도 깨뜨리지 않았다.
- **주 측정:** 두 교사 모두 보지 않은 실제 학습 과제 434개에서, 연산 1,057개를 얹은 엔진의 첫 프로그램이 **하나도 바뀌지 않았다**. 새로 푼 과제에서 깨뜨린 과제를 뺀 수가 0이라 지지되지 않았다. 등록대로 개발 과제는 재지 않았다.
- **진단:** 꾸러미의 관문은 실제 설명 60개에서 열렸지만, 그 어디에서도 꾸러미 연산이 예시를 재현하는 프로그램 40개 안에 들지 못했다. 말은 가끔 맞아도 계산하는 것이 실제 과제가 묻는 것과 다르다.

## 1. 절차와 수

| 단계 | 내용 | 수 |
|---|---|---|
| 1. 과제 쓰기 | [과제 지침](round5_task_guide.md), `scripts/round5_task_check.py` | 300개, 범주마다 60 |
| 2. 거르기 | 평가 과제나 학습 쪽 실제 과제와 가까운 것 제외(여섯 단어 연속, 내용어 자카드 0.6), 지금 엔진으로 풀기 (`scripts/round5_bank.py`) | 287개 남음, 엔진이 풂 19 / 틀림 90 / 없음 178 |
| 3. 연산 쓰기 | [연산 지침](round5_teacher_guide.md), `scripts/teacher_check.py --round 5`, 연산 교사는 실제 과제를 보지 않음 | 연산 277, 은행 209개 새로 풂, 깨짐 0 |
| 4. 전이 측정 | `scripts/round5_measure.py`, 학습 쪽 실제 과제 434개 | 첫 프로그램 변화 **0** |

교사 토큰은 두 교사 합쳐 약 100만이었다(과제 43만, 연산 62만).

## 2. 왜 닿지 않았나

1. **지어낸 과제는 실제 과제보다 어렵고 다른 곳에 있다.** 지금 엔진은 학습 쪽 실제 과제의 74%(320/434)를 풀지만, 지어낸 연습문제는 7%(19/287)만 푼다. 교사가 쓴 문제는 동적 계획법, 그래프 탐색, 암호, 검증기(Luhn, ISBN) 같은 중급 문제가 많았다.
2. **겹치는 곳을 교사가 스스로 비웠다.** "벤치마크 과제를 되살리지 말라"는 규칙을 과제 교사는 넓게 읽어, MBPP나 HumanEval에서 본 기억이 나는 주제를 통째로 뺐다. 로마 숫자, 표준편차, 동전 거스름, 주식 이익, 런 길이 부호화, 회문과 괄호 검사, 대소문자 표기 변환 등이다. 이것들은 교과서의 고전 문제이기도 하다. 실제 과제와 겹칠 곳이 바로 거기였다.
3. **4차 라운드와 같은 벽이다.** 4차 라운드의 연산은 실제 학습 과제의 실패를 보고 썼는데도 개발 과제에서 한 번도 쓰이지 않았다. 3차 라운드가 공통된 요구를 걷어 간 뒤에 남은 실패는, 겨냥해서 써도(4차) 겨냥하지 않고 써도(5차 시범) 처음 보는 과제로 옮겨 가지 않는다.

## 3. 2차 시범: 고전 개념을 허용하고 입문 난이도로

사용자의 선택으로 2절의 두 번째 원인을 떼어 냈다(`reports/seedlm/round5_pilot2_protocol.json`, 측정 전 등록). 과제 교사에게 고전 개념은 일반 지식이니 쓰라고 하고, 벤치마크 항목의 문장·예시·상수만 금지했으며, 난이도를 입문 위주로 맞췄다([2차 과제 지침](round5_task_guide2.md)). 연산 교사는 실제 과제도, 1차 꾸러미도 보지 않았다.

| | 1차 시범 | 2차 시범 |
|---|---|---|
| 지어낸 연습문제 (실제 과제와 가까워 뺀 것) | 300 (13) | 300 (13) |
| 지금 엔진이 푸는 비율 (실제 학습 과제는 74%) | 7% (19/287) | 41% (119/287) |
| 연산 (모두 관문 있음) / 키워드 확장 | 277 / 9 | 366 / 20 |
| 자기 은행에서 새로 푼 것, 깨진 것 | 209/268, 0 | 160/168, 0 |
| 실제 학습 과제 434개에서 관문이 열린 설명 | 60 | 100 |
| **434개에서 첫 프로그램이 바뀐 과제** | **0** | **5** |
| 새로 푼 것 / 깨뜨린 것 (느슨함) | 0 / 0 | 1 / 0 |
| 새로 푼 것 / 깨뜨린 것 (엄격함, 주 측정) | 0 / 0 | 1 / 1 → **0, 지지되지 않음** |

바뀐 다섯 과제를 읽었다. 하나는 진짜로 새로 풀었다(비밀번호 유효성, 이전에는 프로그램 없음). 하나는 깨졌다("인접한 두 원소의 최대 곱"이 "정렬 후 아무 두 원소의 최대 곱"으로 바뀌어 assert 셋을 우연히 통과). 셋은 이미 맞던 프로그램을 같은 뜻의 다른 식으로 바꿨을 뿐이다. 고전 개념을 허용하자 교사의 연습문제는 실제 과제에 훨씬 가까워졌고, 관문은 실제 설명의 4분의 1에서 열렸다. 그러나 그 개념들이 가리키는 실제 과제는 지금 라이브러리가 이미 푼다. 도움이 될 지식은 실패 쪽에 있고, 실패는 과제마다 제각각이다.

## 4. 결론

실패를 보고 겨냥해 써도(4차 라운드), 보지 않고 지어낸 문제로 써도(5차 시범 두 번), 교사가 쓴 연산은 처음 보는 실제 과제로 옮겨 가지 않았다. 3차 라운드가 실제 실패 489개에서 공통된 요구를 걷어 간 뒤로는, 연산을 더하는 방식의 지식 주입이 지금 시스템에서 더 얻을 것이 거의 없다. 두 꾸러미(`r5_pilot`, `r5_pilot2`)는 저장소에 두되 배포 목록에는 넣지 않는다.

## (1차 시범 뒤에 적은) 다음에 할 수 있는 것

두 번째 시범을 한다면 "고전적인 개념은 일반 지식이니 써도 된다. 다만 기억나는 벤치마크의 문장, 예시, 상수를 옮기지는 말라"로 규칙을 고쳐, 2절의 두 번째 원인을 떼어 내야 한다. 그래도 4차 라운드의 결과(겨냥한 연산도 옮겨 가지 않음)를 보면 기대할 몫은 작다. 꾸러미 `r5_pilot`은 저장소에 두되 배포 목록(`data/rule_pilot/operator_packs.json`)에는 넣지 않는다.

## 재현

```bash
python scripts/round5_task_check.py --part 1
python scripts/round5_bank.py
python scripts/teacher_check.py --round 5 --pack r5_pilot --bank imagined --regress

python scripts/round5_task_check.py --part 2          # 2차 시범 (1차 파일은 outputs/rule_round5/pilot1/로 옮긴 뒤)
python scripts/round5_bank.py --parts 2
python scripts/teacher_check.py --round 5 --pack r5_pilot2 --bank imagined --regress
python scripts/round5_measure.py --pack r5_pilot2 --output reports/seedlm/round5_pilot2_transfer.json
```
