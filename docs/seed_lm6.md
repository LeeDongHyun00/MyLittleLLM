# SeedLM-6: 아는 조각을 새롭게 잇는 법을 가르치기

작성일: 2026-11-19. [SeedLM-5](seed_lm5.md)의 후속이다. 사전학습 가중치 없이 처음부터 학습하고, 측정은 모두 이 저장소 환경(CPU 4코어)에서 했다.

> **정정(2026-11-20).** 시드 셋으로 같은 비교를 반복한 [SeedLM-12](seed_lm12.md)에서 접붙이기의 효과가 재현되지 않았다(접붙이기 유무의 차이 +1, +1, −8). 아래의 접붙이기 이득(17 → 24, 52 → 61)은 한 번의 실행끼리 비교한 것이고, 같은 구성의 반복 실행 사이에서도 그만한 차이가 난다(SeedLM-9). "잇는 방식의 가짓수가 조합을 가르친다"는 결론은 철회한다.

## 요약

- SeedLM-5는 "코더는 본 적 있는 조합만 만든다"는 모양을 찾았다. 통째로 본 구조는 78% 맞히지만, 처음 보는 연결이나 잔가지가 있으면 22%로 떨어진다. 이번에는 아는 조각을 새롭게 잇는 데이터로 조합 자체를 가르칠 수 있는지 시험했다.
- 두 갈래를 학습 전에 등록했다. 자동 접붙이기(학습 프로그램의 부분 트리를 다른 프로그램의 것으로 바꿔 처음 보는 연결로 잇기) 15,402개와, 교사 서브에이전트 여섯이 학습 과제 두 개를 엮어 쓴 자연스러운 합성 과제 1,207개(평가와 겹친 24개 제외)다. 새 연결은 각각 6,723개와 1,028개다.
- 주 측정(교사 보류 과제 중 새 조합 77개, s5-var 17개): 접붙이기 24개(+7, 판단 보류. 기준 +8), 합성 과제 19개(+2, 기각). 접붙이기의 이득은 그 조각이 데이터에 없던 프로그램에서도 났다(9 대 3). 합성 과제는 대신 조각을 모두 본 프로그램에서 +5였다.
- 접붙이기는 엔진이 못 푸는 과제에서 처음 보는 연결 토큰의 손실을 9.4 → 6.7 nats로 낮추고, 학습 내내 보류 과제의 손실을 낮게 유지했다(과적합이 늦어짐).
- 그러나 실제 개발 과제로는 옮겨지지 않았다. 두 코더 모두 보류 개발 과제 최선이 68개로 기준 69를 넘지 못해 s5-var를 유지했고, 여섯 코더가 엔진 너머로 맞힌 과제는 여전히 같은 6개다.
- 해석: 조합을 가르치는 데는 자연스러운 과제보다 잇는 방식의 가짓수가 효과적이었지만, 짧고 암시적인 실제 과제 설명에서 무엇을 조합할지 읽어 내는 일은 따로 남아 있다.

## 1. 가설: 조합을 본 적이 없어서

SeedLM-5의 진단(`docs/seed_lm5.md` 7~9절)은 세 가지였다.

- 학습 프로그램을 그대로 써서는 엔진이 못 푸는 보류 과제 29개 중 4개만 풀린다. 정답은 데이터에 그대로 있지 않다.
- 코더는 통째로 본 적 있는 구조의 프로그램은 78% 맞히지만, 처음 보는 연결이나 잔가지가 하나라도 있으면 22%로 떨어진다(교사 보류 77개 중 17개).
- 처음 보는 연결을 만드는 토큰은 엔진이 못 푸는 과제에서 하나도 코더의 1순위가 아니었다.

가설은 "코더는 본 적 있는 조합만 만든다. 아는 조각을 새롭게 이은 데이터를 보여 주면 조합 자체를 배워, 처음 보는 조합의 프로그램도 더 찾는다"이다. 같은 영역의 과제를 더 쓰는 것(SeedLM-5)과 다르게, 이번 데이터는 조각은 그대로 두고 잇는 방식만 새롭다.

## 2. 두 갈래의 데이터

**접붙이기(s6-graft).** `scripts/seedlm6_grafts.py`. 학습 몫의 교사 과제와 변형 과제 1,837개(보이는 출력 문자열을 쓰는 프로그램은 뺐다)에서 숙주 하나와 기증자 하나를 고르고, 숙주의 부분 트리 하나를 기증자의 부분 트리로 바꾼다. 이음매(숙주의 부모 → 새 자식)는 어떤 학습 프로그램에도 없는 연결이어야 한다. 남기는 조건은 이렇다.

- 숙주 과제의 입력 셋에서 모두 실행되고, 출력이 입력마다 다르고, 숙주의 출력과 다르고, 인자를 그대로 돌려주지 않는다. 값은 텍스트로 저장했다가 되읽을 수 있어야 한다(생성기 객체, 집합, None은 버린다).
- 컴프리헨션은 자기가 묶은 변수를 써야 하고(`[a0 for v in a0]`나 `if 1`은 버린다), 리스트 컴프리헨션의 원소와 모든 조건은 그 변수를 읽어야 한다. 키 함수도 자기 인자를 써야 한다.
- 기증하는 부분 트리는 인자나 변수를 읽어야 한다(상수 이식 금지). 닫힌 부분 트리는 숙주의 첫 입력에서 같은 형의 값을 내는 것으로만 바꾼다. 같은 계산을 두 피연산자에 쓰는 연산(`a0 >> a0`)은 버린다(덧셈·곱셈·슬라이스는 허용).

200만 번 시도해 15,402개를 얻었다(숙주 1,716개, 기증자 1,592개, 토큰 수 중앙값 11). s5-var의 데이터에 없던 연결 6,723개와 잔가지 9,748개가 들어 있다. 변형 과제 698개가 더한 연결은 504개였다. 설명은 없으므로 조각마다 과제 문장에 흔한 낱말을 붙여 만들었다(`mylittlellm/seedlm/pyx_words.py`). 라이브러리 연산은 교사 문구, 파이썬 노드는 "sum", "product", "each", "greater than" 같은 낱말, 인자는 형("the list")을 바깥 노드부터 읽는 순서로 잇는다. 매끄러운 문장은 아니고 맞는 낱말의 묶음이다.

```
접붙이기:  [v1 for v0, v1, v2 in zip(a0, a0[1:], a0[::3]) if v1 < v0 and v1 < v2]
낱말:      write a python function to every which pairs the list first the list ... smaller than smaller than
```

**교사의 합성 과제(s6-comp).** `scripts/seedlm6_pairs.py`가 학습 몫의 과제 두 개씩 묶은 쌍 1,320개를 만들었다(절반은 기증자의 출력 형이 숙주의 인자 형과 맞는 쌍). 교사 서브에이전트 여섯이 220쌍씩 맡아, 한쪽의 계산을 다른 쪽에 넣은 자연스러운 과제(설명, 함수 이름, 입력 셋, 파이썬 식 한 줄)를 썼다. 검사기(`scripts/seedlm6_novelty.py`)는 과제 검사와 함께 "학습 프로그램에 없는 연결이나 잔가지가 하나 이상"을 요구한다. 1,207개가 모두 통과했고, 평가 과제 설명과 겹친 24개를 걸러 1,183개가 남았다(학습 몫 1,071개). s5-var의 데이터에 없던 연결 1,028개와 잔가지 1,301개가 들어 있다.

```
숙주:   리스트의 극솟값(양옆보다 작은 원소)   [b for a, b, c in zip(a0, a0[1:], a0[2:]) if b < a and b < c]
조각:   소수 판정(쌍의 기증자가 맞지 않아 교사가 다른 과제에서 가져옴)
합성:   Write a function to find the local minima of a list that are prime numbers, where a local
        minimum is an element smaller than both of its neighbours.
        [b for a, b, c in zip(a0, a0[1:], a0[2:]) if b < a and b < c and is_prime_1(b)]
```

교사들은 같은 임시 폴더를 함께 써서, 한 교사의 빌드 스크립트가 다른 교사의 것을 덮어쓴 일이 있었다. 모두 개별 폴더로 옮겨 다시 만들었고, 최종 파일은 각자 검사기를 다시 통과시켰다(합쳐서 1,207개 모두 통과).

## 3. 사전 등록

학습 전에 `reports/seedlm/seedlm6_protocol.json`을 썼다.

- 두 코더: s6-graft(s5-var + 접붙이기 10%), s6-comp(s5-var + 교사 합성 과제 10%). 나머지는 s5-var와 같다(구조, 크기, 120분, 변형 과제 10%).
- 주 측정: 교사 보류 과제 139개 중 s5-var의 데이터(합성 프로그램 10만 개 포함)에 없는 연결이나 잔가지를 가진 77개에서, 폭 32의 첫 검증 프로그램이 맞는 수. s5-var는 17개(등록 뒤, 두 코더를 학습하기 전에 같은 스크립트로 쟀다). 8개 이상 늘면 지지, 4~7개는 판단 보류, 3개 이하는 기각. 갈래마다 따로 판정한다.
- 보호 조건: 나머지 62개(조각을 모두 본 프로그램)에서 s5-var(35개)보다 4개 넘게 잃으면 비용으로 보고한다.
- 보조 측정: 엔진 실패 29개 중 코더 혼자 맞힌 수(s5-var 5), 범위 밖 15개(5), 처음 보는 연결 토큰의 손실, 이득이 추가 데이터에 그 조각이 있는 프로그램에서 났는지(덮임) 아닌지.
- 채택: 최선 방법이 보류 개발 과제에서 s5-var의 69보다 많을 때만 대체하고, 그때 검증 관문, 시험 1회, HumanEval+ 1회.

## 4. 학습

두 코더 모두 s5-var와 같은 구조(1,244만 파라미터)·데이터(변형 과제 10% 포함)·학습 시간(120분)에, 각 갈래의 데이터를 학습 행의 10%로 더했다(그만큼 합성 행이 준다).

| 학습 끝 평가 | s5-var | s6-graft | s6-comp |
|---|---|---|---|
| 학습 걸음 | 5,524 | 4,354 | 5,055 |
| 합성 과제 top-1 재현 | 95.0% | 93.3% | 95.3% |
| 실제 보류 프로그램 손실 / top-1 재현 | 1.73 / 57.3% | 1.33 / 58.7% | 1.43 / 65.3% |
| 교사 보류 과제 손실 / top-1 재현 | 2.61 / 48.2% | 2.01 / 46.0% | 2.44 / 49.6% |
| 교사 보류 과제 빔 8 재현 | 62.6% | 64.7% | 68.3% |
| 범위 밖 개발 과제(15개) 통과 | 5 | 3 | 4 |

s6-graft는 같은 120분에 걸음을 21% 덜 갔다. 학습 후반의 걸음 속도는 s5-var보다 8% 느린 정도였고(100걸음에 142초 대 132초), 차이의 대부분은 앞쪽 30분에 났다. 그 시간에 같은 CPU에서 짧은 torch 점검과 데이터 검사를 몇 번 돌렸는데, 4스레드 학습과 겹치면 학습이 크게 느려진다. 걸음 수 차이는 데이터와 이 간섭이 섞인 결과다. 같은 날 간섭 없이 학습한 s6-comp는 s5-var와 거의 같은 속도였다(500걸음에 655초 대 621초). 그런데도 보류 과제의 손실은 s5-var보다 낮게 유지됐다. 교사 보류 손실은 학습 30·60·90분에 s5-var가 1.87 → 2.13 → 2.48로 오른 반면 s6-graft는 1.75 → 1.87 → 2.03이었다. 접붙이기가 교사 과제 3,924행을 거듭 보는 데서 오는 과적합을 늦춘 것으로 보인다. s6-comp는 합성 과제 1,071개를 예시 셋씩 3,213행으로 봤고, 실제 보류 프로그램과 교사 보류 과제의 첫 후보가 모두 s5-var보다 나았다(57.3% → 65.3%, 48.2% → 49.6%). 보류된 합성 과제 112개에서 첫 후보가 예시를 재현하는 비율은 44.6%였다.

## 5. 주 측정: 처음 보는 조합

`scripts/seedlm5_fragments.py --model`, 갈래별 덮임은 `--arm`. 기준(s5-var)과 같은 과제, 같은 분할이다.

| 교사 보류 과제, 폭 32 첫 검증 프로그램이 맞음 | s5-var | s6-graft | s6-comp |
|---|---|---|---|
| **새 조합 77개 (주 측정)** | 17 | **24** (+7) | 19 (+2) |
| ― 처음 보는 연결 64개 | 17 | 21 | 17 |
| ― 처음 보는 잔가지 12개 | 0 | 3 | 1 |
| ― 처음 보는 토큰 1개 | 0 | 0 | 1 |
| 조각을 모두 본 62개 (보호 조건) | 35 | 37 (+2) | 40 (+5) |
| ― 통째로 본 37개 | 29 | 30 | 31 |
| ― 처음 보는 전체 25개 | 6 | 7 | 9 |
| 범위 밖 15개 | 5 | 3 | 4 |

- s6-graft: +7로, 지지 기준(+8)에 하나 모자라 판단 보류다. 과제별로 짝지으면 s6-graft만 맞힌 것이 11개, s5-var만 맞힌 것이 4개다(부호 검정 p≈0.12). 잔가지 단계는 0 → 3개로, s5-var가 하나도 못 맞히던 단계에서 처음으로 맞혔다. 새 조각이 접붙이기 데이터에 없는 프로그램 70개에서도 9 대 3으로 앞섰다(데이터가 그 조각을 가진 7개에서는 2 대 1). 이득이 그 조각을 직접 본 덕만은 아니라는 뜻이다.
- s6-comp: +2로 기각이다(s6-comp만 7개, s5-var만 5개). 대신 조각을 모두 본 프로그램에서 +5로 가장 많이 늘었다(10 대 5). 자연스러운 합성 과제 1,071개는 코더를 전반적으로 낫게 했지만, 새 조합을 만드는 쪽으로는 거의 움직이지 않았다.

| 교사 정답의 처음 보는 연결 토큰 | s5-var | s6-graft | s6-comp |
|---|---|---|---|
| 교사 보류: 평균 손실 / 1순위 비율 | 4.71 / 37% | 4.06 / 37% | 4.45 / 42% |
| 범위 밖: 평균 손실 / 1순위 비율 | 9.36 / 0% | 6.73 / 13% | 8.74 / 4% |

s6-graft는 엔진이 못 푸는 과제에서 처음 보는 연결 토큰의 손실을 9.4 → 6.7 nats로 낮추고, 그런 토큰을 처음으로 1순위에 올렸다(24개 중 3개). 다만 다른 토큰도 함께 싸졌으므로(본 적 있는 연결 4.9 → 4.3, 잎 5.4 → 4.2) 새 연결에만 생긴 변화는 아니다.

데이터가 더한 새 연결 수와 이득을 나란히 놓으면 이렇다. 변형 과제(SeedLM-5) 504개, 합성 과제 1,028개, 접붙이기 6,723개. 새 조합 77개에서의 이득은 s4-post 대비 s5-var는 재지 않았고, 합성 과제 +2, 접붙이기 +7이다. 점이 둘뿐이라 법칙이라 부르기는 이르지만, 자연스러움보다 잇는 방식의 가짓수가 조합을 가르친다는 쪽을 가리킨다.

## 6. 보류 개발 과제

사전 등록한 채택 측정(`reports/seedlm/holdout4_s6-graft.json`, `holdout4_s6-comp.json`). 보류 개발 과제 94개, 엔진 65개.

| 방법 | s5-var | s6-graft | s6-comp |
|---|---|---|---|
| pyx_model (코더 혼자) | 57 | 55 | 56 |
| pyx_tie / pyx_tie_fill | 67 / 68 | 68 / 68 | 68 / 68 |
| pyx_override | **69** | 65 | 68 |
| pyx_rerank / pyx_margin | 65 / 68 | 61 / 65 | 64 / 64 |
| 엔진 실패 29개 중 코더 혼자 맞힘 | 5 | 4 | 4 |

두 갈래 모두 최선이 68로, 기준 69를 넘지 못해 s5-var를 유지했다. 검증·시험·HumanEval+는 돌리지 않았다. 여섯 코더(s3-pyx, s3b-pyx, s4-post, s5-var, s6-graft, s6-comp)가 엔진 너머로 맞힌 과제는 여전히 같은 6개 안에 있다(`reports/seedlm/overlap_holdout_s6.json`).

교사 보류 과제에서 보인 새 조합의 이득은 실제 개발 과제로 옮겨지지 않았다. 교사 과제는 설명이 길고 명시적이며(인자를 순서대로 부르고 상수를 모두 적는다), 개발 과제의 설명은 짧고 암시적이다. SeedLM-5의 8절에서 잎 토큰조차 범위 밖 과제에서 두 배 가까이 비쌌던 것(5.4 대 2.8 nats)과 같은 간격이다. 조합을 배우는 것과, 짧은 문장에서 무엇을 조합할지 읽어 내는 것은 다른 일로 보인다.

## 한계

- 주 측정의 차이(+7)는 짝지은 부호 검정으로 p≈0.12이고, 사전 등록 기준에도 하나 모자랐다. 이득을 실재한다고 말할 수 없다.
- s6-graft는 같은 120분에 걸음을 21% 덜 갔다. 일부는 학습 앞쪽에 같은 CPU에서 돌린 짧은 점검 작업 탓이다. 걸음 수를 맞추면 결과가 달라질 수 있다.
- 접붙이기는 어색한 프로그램을 많이 포함한다(예: 두 번 쓰는 상수, 쓸모없는 조건). 거르는 규칙을 몇 번 고쳤지만 모두 학습 데이터만 보고 정했다. 설명은 낱말의 나열이라 실제 과제 설명과 모양이 다르다.
- 합성 과제는 교사 여섯이 같은 임시 폴더를 함께 써서 서로의 빌드 스크립트를 덮어쓴 일이 있었다. 최종 파일은 각자 다시 만들고 검사기를 통과시켰지만, 과정의 혼선은 기록해 둔다. 쌍 1,320개 중 113개는 자연스러운 조합이 없어 건너뛰었다.
- 주 측정은 교사 보류 과제(교사가 쓴 생성 과제)에서 쟀다. 실제 과제에서의 새 조합은 범위 밖 15개뿐이라 따로 판정할 힘이 없다.
- 보류 개발 과제는 이제 코더 선택에 일곱 번 쓰였다.
