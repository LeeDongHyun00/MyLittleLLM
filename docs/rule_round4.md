# 4차 교사 라운드: 남은 엔진 실패는 긴 꼬리다

작성일: 2026-11-21. [3차 라운드](rule_round3.md)와 같은 절차로, 규칙 엔진이 아직 못 푸는 학습 과제에 교사 서브에이전트가 연산을 더 썼다. 측정 전에 등록했다(`reports/seedlm/round4_protocol.json`).

## 요약

- 학습 쪽 과제 434개(엑스트라 풀의 학습 부분, 보류 개발 과제 94개는 뺌)에서 지금의 엔진은 320개를 풀고 114개를 못 푼다(프로그램 없음 70, 틀린 프로그램 44).
- 교사 셋이 연산 76개를 썼다(모두 키워드 게이트). 기억에 기대 썼다고 스스로 밝힌 2개를 빼고 74개가 남았다. 학습 과제에서 푸는 수는 320 → 384개(+64)가 됐고 깨진 과제는 없었다.
- 보류 개발 과제 94개에서는 아무것도 바뀌지 않았다. 엔진 65, 시스템(엔진 + s5-var pyx_override) 69 그대로다. 최종 프로그램에 4차 연산이 들어간 개발 과제는 0개였다. 등록 기준(69 초과)에 못 미쳐 채택하지 않았고, 배포 라이브러리는 그대로다.
- 3차 라운드는 실패 489개의 공통된 요구를 연산으로 만들어 잠근 시험을 57 → 68로 올렸다. 그 뒤에 남은 실패는 과제마다 제각각인 긴 꼬리다. 그것을 고치는 연산은 사실상 과제 하나에 하나씩이고, 처음 보는 과제에서 다시 나오지 않는다.

## 1. 절차

| 단계 | 내용 |
|---|---|
| 실패 은행 | `scripts/round4_bank.py`. 학습 쪽 434개를 지금의 엔진으로 다시 돌려 실패 114개를 범주별로, 푸는 320개를 회귀 검사용으로 저장 (`reports/seedlm/round4_bank_summary.json`) |
| 교사 | 서브에이전트 셋, [4차 지침](round4_teacher_guide.md). 수치(실패 37), 수열·중첩(38), 문자열·참거짓(35). 금지 경로를 열지 않고 자기 파일만 고친다 |
| 검사 도구 | `scripts/teacher_check.py --round 4`. 배포 라이브러리(3차 연산, 퇴출 목록, 탐색 기능) 위에 새 꾸러미를 얹고, 개발 과제나 검증·시험 과제가 섞이면 실행을 거부한다 |
| 선별 | `scripts/round4_select.py`. 3차 라운드의 퇴출 규칙을 학습 과제 434개에서만 적용 |
| 측정 | `scripts/with_library.py`로 후보 라이브러리를 얹어 `scripts/seedlm4_tasks.py holdout` |

교사들이 남긴 풀지 못한 이유는 대부분 같은 줄에 선다. 테스트나 참조 해답에만 있는 문구와 상수('Not Possible', 'Accept'/'Discard', n = 10), 설명과 다른 참조 해답, 인자 넷 이상의 조합, 숫자를 말로 쓴 길이 같은 것이다. 엔진 실패의 상당수가 설명과 보이는 예시만으로는 답이 정해지지 않는 과제라는 [SeedLM-3의 분류](seedlm_findings.md)와도 맞다.

## 3. 읽기

학습 과제에서 +64인데 보류 과제에서 0이라는 것은, 이번 연산들이 일반 규칙이 아니라 본 과제의 풀이였다는 뜻이다. 모두 키워드 게이트를 달았고 교사들도 일반성을 지키려 했지만, 처음 보는 과제의 설명은 그 키워드를 부르지 않았다. 3차 라운드에서 연산이 시험 과제로 옮겨 간 것은 그때의 실패가 같은 요구(약수, 자릿수, 정규식 판정 등)를 여러 번 되풀이했기 때문이다. 그 공통분모를 다 거둔 뒤에는, 교사가 쓰는 연산도 코더가 배우는 조합처럼 본 것에 머문다.

교사들이 짚은 엔진 쪽 한계는 다음 라운드의 재료로 남긴다.
- 두 파생 값을 잇는 탐색(named pairs)이 꺼져 있다. 그래서 설명이 다 부르는 한 단계짜리 우연이 두 단계짜리 바른 프로그램을 늘 이긴다.
- C에서 옮긴 과제는 배열 길이를 따로 넘기는데, 이 인자를 쓰지 않는 바른 연산이 동점 처리에서 진다. 이 규칙은 엔진 기능 `length_argument`로 넣어 봤다(목록 인자의 길이와 같은 정수 인자는 그 목록을 쓰면 쓴 것으로 친다). 지금의 라이브러리로 학습 과제 434개에서 새로 푼 과제 2개, 깨진 과제 1개라 개발 과제에서 따로 시험하지 않았고, 배포 목록에서 꺼 두었다.
- 같은 참거짓 값을 내는 술어가 여럿이면 먼저 등록된 쪽이 이긴다.

```bash
    python scripts/seedlm4_tasks.py holdout --model s5-var --suffix _r4
```
