# 다음 세션 작업 카드

2026-11-05 기준. 카드별 상태를 아래에 기록한다. 준비·개발 완료와 독립 평가 완료는 구분한다.
모든 카드는 한 브랜치와 새 인수인계로 끝낸다. 과거 공개 문항은 회귀/개발용으로 사용한다.

## E01 — 새 평가 프로토콜과 검수 준비

- **역할/상태:** S5, completed_preparation. E01 준비 완료; H1/새 후보/잠금은 E02 입력 대기.
- **입력:** 계약, 기존 [평가 설계](../experiment_design.md), [검수 안내](../../data/review/README.md), 과거 실패 분류.
- **범위:** 개발·최종 시험 접근 경계, 누출 그룹, 근거 적중/답변/보류/오류/지연 지표와 사전 채점 기준 작성.
  새로운 질문 후보와 사람 검수 양식은 만들 수 있지만 AI 답안을 `approved`로 바꾸지 않는다.
- **산출물:** 새 protocol, 후보 데이터 manifest, 검수자용 자료, 모델 응답을 보지 않고 작성하는 gold 절차.
- **완료 조건:** 규칙/연도/복사본 누출 처리, 분모·호출 수·표본 독립성·허용 출력·비교군이 명시됨.
  사람 검수 없는 표본과 시험 접근 권한을 구분함. H1 미확보 시 준비 작업은 완료, 최종 평가만 대기.
- **제외:** 과거 점수 재작성, 승인된 독립 gold가 있다는 주장. 표본 수/합격선은 근거와 함께 사전에 정한다.

## D01 — 월 상한·표·각주 근거 확인

- **역할/상태:** S1, partial. 별도 배포본 진단 완료; 기존 원문 해시 재확보·최신 수정본 확인 대기.
- **입력:** `kosaf-2026-housing-plan-faq`, v2 V12 실패, PDF 10쪽 상한 조항과 현재 색인.
- **범위:** 원문 해시/쪽을 확인하고 상한·지급 범위·예외를 함께 보존하는 개발 fixture 작성.
  표 구조/각주 손실을 기록하고 필요하면 Docling 방식과 현재 추출 결과를 제한된 페이지에서 비교.
- **산출물:** 원문 manifest, 조항 위치/추출 비교, 제한된 검증 발췌, 제외/보류 이유.
- **완료 조건:** 근거가 원문에 실제 존재하는지, 추출 또는 검색 중 어느 단계에서 누락됐는지 확인됨.
  새 필드가 필요하면 기존 검색 소비자에 미치는 영향을 기록함. 도구 도입 전 메모리/시간을 확인함.
- **제외:** 전체 RAGFlow/Docling 설치를 성공 조건으로 삼기, 공식 자료 전체 Git 배포, 최종 시험 정답 생성.

## R01 — 자유 질문 핵심 조항 검색

- **역할/상태:** S2, partial. [두 후보 비교](../../reports/r01_retrieval_development.md)를 완료했지만 무퇴보 채택 조건 미충족. 기본 검색 유지.
- **입력:** 현재 BM25 k=2 기준선, 공개 V12, D01 결과. 생성 설정은 고정.
- **범위:** 개인 배경 문구 제거/질의 분해, 조항 단위 검색, 후보 병합 중 하나씩 비교.
  대학·연도·학기 필터와 예외/부정 표현을 보존한다. 이미 퇴보했던 하이브리드 검색을 자동 기본 채택하지 않는다.
- **산출물:** 새 run ID의 질의/근거/순위/설정, 개발 Recall@k와 누락 원인, 후보 선택 이유.
- **완료 조건:** V12 상한 근거를 찾되 ID·정답을 하드코딩하지 않음. 기존 범위 필터와 반례 회귀 점검 통과.
  검색 개선만의 효과를 보고하고 최종 성능 확정은 E02에 넘김.
- **제외:** 질문에 따라 정답 숫자를 주입하기, 골드 쪽을 제공한 oracle 실험을 실제 검색 성공으로 합산하기.

## M01 — 생성 반복·잘림과 오류 처리

- **역할/상태:** S4, ready; E01의 비교/기록 규칙 확인. 같은 호스트 무거운 작업은 단독 실행.
- **입력:** 고정 Qwen/llama.cpp, 현재 minimal/JSON/384 설정, 개발용 고정 근거와 V12 실패 출력.
- **범위:** 예시/프롬프트 정리, 제한된 생성 설정 후보, 반복/잘림 실패 처리의 효과를 각각 비교.
  근거 누락 조건과 충분한 근거 조건을 구분한다. 재시도는 한도·호출 수·실패 상태를 기록하는 별도 설계로 다룬다.
- **산출물:** 원시 응답, finish_reason, 검증 결과, 토큰/지연/호출 수, 선택 설정의 근거.
- **완료 조건:** 실패한 출력을 답변으로 내보내지 않음. 보류를 정답 성공으로 잘못 세지 않음.
  같은 검색 입력에서 기존 설정과 비교하고 통과 사례의 내용/인용 퇴보를 검토함.
- **제외:** 출력 토큰 무제한 확대, 빈 답/상수 답으로 형식 통과율만 개선, 시험 후 설정 선택.

## L01 — 부분 규칙과 설명의 경계

- **역할/상태:** S3, completed_development. [부분 판정 설명/경계 회귀](../../reports/l01_rule_boundaries.md) 완료. 원문 재검수/H1/실서비스 지연은 별도.
- **입력:** 9개 규칙, 적용 범위/해시 검증, 현재 문답과 경계 테스트.
- **범위:** 미확인·모순·적용 범위 밖·학교 유형 예외·법정 지위 미확인에 대한 회귀 검토.
  거짓 결론에서 어떤 요건이 부족한지 설명할 수 있는 범위를 설계한다.
- **산출물:** 조항 연결 경계 사례, 실패 설명의 변경, 의미상 부분 판정임을 보장하는 검증.
- **완료 조건:** 모름은 unknown 유지, 정수 조건 제약 유지, 최종 합격/선발 주장 없음.
  새 규칙이 필요하면 원문/버전/검수 상태와 manifest 갱신을 함께 제시함.
- **제외:** 자연어 조건 자동 추출을 검증 없이 도입, 개인 기록 확인으로 확대.
