상태는 **prepared_not_frozen**이다. 질문 모집·H1 확보·분할·최종 실행은 아직 하지 않았다.
[기계 판독 프로토콜](../../data/evaluation/e01/protocol.json),
[후보 manifest](../../data/evaluation/e01/candidate_manifest.json),

[현재 I/O](../project/INTERFACES.md)다. 이 문서는 실행 계약이나 CLI 기본값을 변경하지 않는다.

## 1. 질문과 표본의 독립성

연구 질문은 공식 원문 접근 조건에서 검색 변경 R01과 생성 변경 M01이 근거 적중,
정확한 답변·추가 질문·보류 및 실패 비용에 어떤 차이를 만드는가이다.
주된 비교는 동일 질문의 변경 전/후 grounded 응답이다. 교육격차 개선이나 운영 배포 적합성을 검증하지 않는다.

| cohort | 사용과 주장 | 최종 시험 취급 |
|---|---|---|
| `public_regression` | 기존 평가·예시·학습/개발 문항, V04/V07/V12, 테스트 fixture 및 그 누출 연결 그룹 | 개발/회귀 전용. 사람 검수 후에도 미노출 시험이 되지 않음 |
| `new_questions_known_rules` | H1이 새로 쓴 질문이지만 이미 구현·개발한 규칙/템플릿을 공유 | 별도 질문 보류 평가 가능. 새 규칙 일반화나 정식 그룹 시험으로 합산 금지 |
| `unseen_rule_groups` | 노출 감사에서 기존 개발 자료와 연결되지 않은 새 규칙 그룹 | 아래 48/12/40 분할의 유일한 대상. 미확보 시 대기 |

현재 9개 구현 규칙, 비용 함수, 공개 상한 사례와 그 연도/표현 변형은 이미 노출됐다.
같은 PDF의 아직 개발하지 않은 조항은 독립성 감사 후 후보가 될 수 있으나,
문항/해설/구현 논리의 노출과 open-book 원문 접근을 구분한다. 새 대학·새 연도 일반화는 별도 설계가 필요하다.
기반 모델의 사전학습 노출 여부는 알 수 없다. H1 승인과 미노출 그룹 판정도 서로 별개다.

## 2. 사전 표본 계획과 분할

- 탐색 파일럿 목표는 **25개의 미노출 연결 그룹 × 그룹당 2문항 = 50문항**이다.
  그룹 수 기준 train 12 / dev 3 / test 10, 행 수 목표 24 / 6 / 20으로 48/12/40을 맞춘다.
  두 문항은 같은 규칙의 통상 적용과 경계/정보 부족 등으로 작성하되 독립 표본 2개로 세지 않는다.
- 25는 비율을 정확히 구현하면서 소규모 두 사람 검수와 단일 CPU 호스트 실행을 준비하기 위한
  실무적 파일럿 크기다. 검정력 계산이나 목표 정확도에서 얻은 수가 아니다. 시험 독립 단위는
  최대 10그룹이며 그룹 간 상관도 남는다. 이 크기로 ±3%p 정밀도나 운영 정확도를 주장하지 않는다.
- 현재 확보 수는 **0그룹/0문항**이다. 25개가 불가능하면 시험을 열지 않고 표본 계획을 개정한다.
  공개 규칙을 재명명하거나 같은 그룹을 쪼개어 수를 채우지 않는다. 그룹 합병 후 25개 미만이 되어도 동일하다.
- H1은 모델 출력을 보기 전에 단순 조회·조건 조합·경계/예외·연도 변경·정보 부족·근거 밖 질문·계산의
  coverage를 기록한다. 존재하지 않는 유형을 억지로 만들지 않는다. 부족한 유형은 별도 회귀 cohort로 검토하고
  최종 manifest에 유형별 행/그룹 수와 부재 이유를 고정한다. 유형별 성능을 전체 모집단위 성능으로 확대하지 않는다.
- 25개를 초과하는 적격 그룹은 정렬한 그룹 ID에 `random.Random(20261104).shuffle`을 적용해
  앞의 25개를 선택한다. 각 그룹의 두 문항은 모델 없이 H1이 확정한다. 나머지는 이번 실험에서 열지 않는다.
  선택된 그룹을 [분할 스크립트](../../scripts/split_dataset.py)의 `--seed 20261104`로 분할한다.
  학습 부분은 개발에 사용하되 이번 작업에서는 가중치 학습을 하지 않는다.
- 실제 행 비율·그룹 수·대학/규칙/질문 유형별 구성을 공개한다. 이 분할기는 reviewer 신원,
  승인 증거, 의미상 중복을 검사하지 않으므로 H1 감사와 승인 장부가 먼저 필요하다.

누출 그룹은 다음 관계의 **전이적 연결 성분**이다. A–B와 B–C가 연결되면 A/B/C를 모두 같은 그룹으로 둔다.
같은 규칙의 2025/2026 버전(수치 변경 포함), 정오표/수정본, PDF/HTML 복사본, 같은 표·각주,
질문 패러프레이즈, 답을 유도하는 공통 템플릿, FAQ와 대응 원문, 전국 공통 규정의 대학별 재게시를 연결한다.
단순히 '질문 문장 형식이 비슷함'이 아니라 답을 전이할 수 있는 의미/규칙 관계를 검토하고 이유를 기록한다.
복수 규칙 질문은 사용한 그룹을 합병한다. 정규화 텍스트 해시와 유사도 검색은 후보 탐지 도구일 뿐이다.
노출 그룹과 연결된 새 후보는 그룹 전체를 회귀로 이동한다. 분할 후 교차 연결 발견 시 실행을 중지한다.
시험을 이미 열었다면 그 시험은 소진된 것으로 기록하고 새 run/시험 후보를 준비한다.

## 3. 접근 경계와 데이터 동선

| 담당 | 시험 동결 전 허용 | 금지/제약 |
|---|---|---|
| S1–S4, 개발 S5 | 공개 회귀, train/dev, 검색 허용 공식 원문, 공개 프로토콜 | 잠근 test 질문·gold·검수 답안·시험별 조항/ID 목록 접근 금지 |
| H1 두 검수자 | 질문·조건·전체 범위 원문/수정본 목록, 자신의 답안 | 최초 답안 제출 전 AI 답안·모델 출력·상대 검수 답안 금지 |
| 지정 데이터 보관자 | 후보/노출/검수/분할/접근 장부 및 private test | 시험을 읽은 뒤 개발·후보 선택에 관여 금지 |
| E02 실행 담당 | 동결 후 실행 시점의 질문/명시 조건, 허용 색인 | gold·필수 사실·금지 주장·gold 쪽/청크를 요청에 넣지 않음 |
| 출력 채점 H1 | gold 동결 후 익명 응답, 근거, 확정 gold | arm·모델명·자동 점수·상대 점수를 보기 전 독립 채점 |

보관자와 두 H1은 아직 미지정이다. 사람이 아닌 S5/LLM judge는 H1 서명을 대신할 수 없다.
한 사람이 시험을 열고 개발에 돌아오면 독립 경계가 깨졌음을 기록한다.
현재 S5는 공개 준비물만 작성하며 private 시험을 생성하거나 열지 않는다.

Git에는 프로토콜·빈 양식·공개 노출 자료의 해시만 둔다. 실제 검수 사본, 실제 신원 대응표,
새 시험 질문/답/그룹별 근거와 접근 장부는 **보관자가 관리하는 별도 비공개 저장소**에 보관한다.
이 저장소의 `data/private/`와 `outputs/`는 Git 제외일 뿐 접근 통제가 아니다.
공유 workspace에 잠근 시험을 두거나 `.gitignore`를 ACL로 설명하지 않는다.
현재 접근 통제는 준비 절차이며 계정/권한은 설정하지 않았다. H1/보관자 지정과 권한 확인을 E02 진입 조건으로 둔다.

접근 장부에는 UTC 시각, 실제 actor의 private ID, 역할, 자료 digest, read/write/release,
목적, 승인자, 노출 사고와 후속 조치를 남긴다. 배포되는 각 사본의 digest와 수신자를 기록한다.
개발 공개분과 private 시험을 물리적으로 분리한 뒤 실행 담당에게 최소 필드만 전달한다.
질문마다 `question`, `year`, `task`, `institution`, 선택적 `semester`, 명시 입력 `facts`만 런타임으로 전달한다.
ID는 실행 장부용이고 프롬프트에 넣지 않는다. `academic_year`→`year`는 명시 변환하고,
규칙 facts와 계산 facts는 분리한다. 모르는 bool/int는 생략하고 false/0/null로 채우지 않는다.
조건과 자연어가 불일치하면 데이터 검수 문제로 보류한다.

## 4. 원문과 검색 접근

모든 RAG 비교군은 같은 기관·적용 연도/학기·as_of 범위의 검증된 공식 규정 원문을 사용한다.
원문/정오표 URL·기관·수집일·적용일·SHA-256·PDF 실제 쪽·표/각주/조항을 보관한다.
색인 snapshot과 허용/제외 구간 manifest를 시험 전에 고정한다.
QA, gold, 검수 답안, 답안 생성에 사용한 해설/FAQ는 주 실험의 색인에 넣지 않는다.
한 PDF에 규정과 FAQ가 섞인 경우 **쪽/구간별 allowlist**를 만들어 모든 비교군에 동일하게 적용한다.
구분할 수 없는 구간은 주 실험에서 제외한다. 현재 색인이 이를 만족한다고 가정하지 않는다.
FAQ 포함 실험은 별도 protocol/run이며 주 실험 분모에 합산하지 않는다.

H1은 전체 해당 원문과 수정본 목록에서 근거를 찾는다. 검수 시작 시 개발자가 골라 준 정답 쪽이나
gold 청크 목록만 제공하지 않는다. 최종 근거는 원문 SHA·조항/표/각주로 정의하고 청크 ID에 종속시키지 않는다.
S1은 시험 gold를 보지 않고 전체 허용 원문의 조항→청크 대응표를 작성한다.
보관자/H1이 이 표를 private gold에 연결하고 의미를 확인한다. 해시가 다른 수정본은 별도 검토한다.
허용 대체 근거 묶음(AND 조항들의 OR)을 gold에 미리 기록할 수 있다.

## 5. 비교군과 실행 조건

| arm | 검색 | 생성 | 공통 부분 규칙/계산/보류 |
|---|---|---|---|
| `B00` 기준 | R0: BM25 k=2 | G0: minimal/JSON/384 | 동결된 동일 구현 |
| `B10` 검색 변경만 | R1: dev에서 선택한 R01 후보 | G0 | 동일 |
| `B01` 생성 변경만 | R0 | G1: dev에서 선택한 M01 후보 | 동일 |
| `B11` 결합 | R1 | G1 | 동일 |
| `N0` 비LLM | R0 | 없음 | 결정 가능한 규칙/계산 결과, 그 외 검색 근거와 보류 |

`B11−B00`이 사전 주 비교이며 `B10−B00`, `B01−B00`은 구성 요소 차이,
`(B11−B10)−(B01−B00)`은 상호작용을 기술한다. N0는 도구 기준선이다.
N0가 근거 목록만 내보냈으면 답변 성공으로 세지 않는다. 실제 비LLM 어댑터는 E02에서 준비해야 한다.
규칙이 근거를 직접 가져온 경로와 계산/보류 경로는 `route`로 따로 집계하며 BM25 검색 성공에 넣지 않는다.
규칙으로 즉시 끝나는 사례에 R/G 효과가 없으면 그대로 보고한다.
L01도 바뀐다면 공통으로 고정할 규칙 버전을 사전 명시한다. 서로 다른 L을 섞은 결과를 R/G의 효과로 부르지 않는다.
구현이 다른 구버전 전체와의 비교가 필요하면 별도 arm/프로토콜 개정으로 선언한다.

R0/G0 기준 코드는 `f3595fba13dda11903fdb8900e5c73202a66f6a9`이다.
Qwen3-4B Q4_K_M와 llama.cpp b11960은 [runtime lock](../../config/runtime.lock.json)을 따른다.
G0는 temperature=0, seed=42, max_tokens=384, stream=false, cache_prompt=false,
요청 `chat_template_kwargs.enable_thinking=false`다. 서버 thinking, 실제 chat template/tokenizer,
8192 문맥, 슬롯 1, thread/batch, 양자화/바이너리 해시, HW/메모리와 의존성도 **관측해** 잠근다.
예전 설치 기록만으로 현재 설정이 일치한다고 쓰지 않는다. claim-check는 모든 주 arm에서 끈다.
G1의 프롬프트/최대 출력/검증/시간 제한은 M01 dev 선택 후 기록한다. 미기입이면 시험을 시작하지 않는다.
이 설계의 주 비교는 자동 재시도 **0회**다. 재시도 전략은 별도 비용 포함 실험으로 분리한다.
G0 네트워크 timeout은 현재 코드의 360초이며 arm별 전체 deadline과 solver 한도도 동결한다.

기본적으로 같은 질문의 B00/B01에는 동일한 R0 근거 바이트/순서, B10/B11에는 동일한 R1 근거를 준다.
R1의 k/청크·문맥 예산·전처리도 사전 동결한다. 결과를 보고 k나 토큰을 변경하지 않는다.
검색만 평가는 generation 전에 수행한다. G만 분석은 동일 근거 조건에서 비교하고
H1 기준 충분/불충분 근거 strata로 나눈다. 정답 쪽을 주는 oracle-context 진단은 필요 시 별도 run이다.
이를 실제 검색이나 end-to-end 성공에 합산하지 않는다.

시험은 arm×문항 작업 순서를 seed=20261104로 섞어 단일 슬롯에서 실행한다.
서버 warm-up은 공개 dev 1회로 분리하고 시험 토큰/호출에는 합산하지 않되 별도 보고한다.
현재 평가 스크립트는 고정 경로를 사용하므로 이 설계를 바로 실행하는 runner가 아니다.
E02에서 run ID·새 경로·동결 검사·입력 allowlist·시간 계측을 지원하는 harness를 먼저 준비한다.

## 6. 사전 의미 채점 기준

최종 시스템의 허용 status는 `answer`, `cannot_determine`, `invalid_response`다.
`clarify`는 평가상의 행동이며 시스템 status가 아니다. 모델 JSON은 현재 네 필드
`status/answer/citations/follow_up`를 유지한다. 규칙 `decision=true/false/unknown`은 부분 요건만 뜻한다.

| gold action | 완전 성공 조건 |
|---|---|
| `answer` | 필수 사실·범위·조건·예외·단위가 모두 맞고, 의미상 지지하는 인용을 제공하며 금지 주장이 없음. 규칙 답은 부분 결론이 명확해야 함 |
| `clarify` | `cannot_determine`이며 결론을 바꿀 수 있는 누락/모순 조건을 구체적으로 질문하고, 이미 주어진 사실을 무시하지 않음. 승인/배제를 단정하지 않음 |
| `abstain` | `cannot_determine`이며 근거/범위/개인 기록의 한계를 맞게 밝히고 가능한 확인 경로를 제시. 정책을 개인 합격/지급으로 확대하지 않음 |

필요 조건을 이미 줬는데 '조건을 만족하면 가능'만 반복하는 답은 정답이 아니다(V04/V07 유형).
불명확한 문장, 필수 예외 누락, 잘못된 인용, 모름을 false로 취급, 근거 없는 확정은 strict 실패다.
보류 문구와 단정이 섞이면 단정도 채점하며 안전한 보류로 통과시키지 않는다.
시스템 오류·timeout·length 잘림·JSON/스키마 오류는 gold가 abstain이어도 정답 보류로 세지 않는다.
잘린 raw 응답은 보존하되 사용자 답변으로 채택하지 않는다. 규칙 결과를 모델이 낸 답처럼 세지 않는다.

H1 gold는 질문별 `required_facts`, `forbidden_claims`, 최소 추가 질문,
부분 판정/적용성, 허용 대체 근거, 허용 수치 오차를 모델 출력 전에 확정한다.
금액은 정수 KRW 일치를 기본으로 하고 기간·단위·상한·중복지원·대출/실부담 구분을 함께 검사한다.
다른 반올림 허용이 공식 원문에 필요하면 해당 gold에 원문과 함께 사전 기입한다.
법정 지위/실제 선발·입금 여부를 가정해 채우지 않는다.
정규식 자동 점수, AI 의미 검토, H1 독립 점수와 조정 점수는 별도 열로 보존한다.

## 7. 지표, 분모와 실패 집계

각 arm/cohort에 고정된 전체 문항 N을 분모로 사용한다. 실패 행을 제거하지 않는다.
분모가 0이면 `null`/N/A와 n=0을 기록한다. 자동 지표와 사람 지표를 한 점수로 합치지 않는다.

| 지표 | 분자 / 분모 또는 집계 규칙 |
|---|---|
| H1 strict 성공 | 위 행동·내용·근거 전부 통과 / N |
| 답변 coverage | 유효 `answer` / N (오답도 답변 수에 포함) |
| 답변 정확도 | 완전 정답인 `answer` / 모든 유효 `answer` |
| 행동 정확도 | gold action에 맞는 실질 행동 / N; 빈 추가 질문은 clarify 아님 |
| clarify 적절성 | 필요한 질문을 맞게 제시 / gold=clarify 수 |
| abstain 적절성 | 한계와 확인 경로가 적절한 보류 / gold=abstain 수 |
| 불필요 보류 | `cannot_determine` / gold=answer 수; invalid/timeout은 별도 오류 |
| 잘못된 배제 | 가능한 부분 요건에 불가/불충족 단정 / gold 부분 판정=true 수 |
| 잘못된 승인 | 불가능한 부분 요건에 가능/충족 단정 / gold 부분 판정=false 수 |
| 미확인 단정 | unknown 또는 clarify/abstain에 근거 없는 승인·배제 / 해당 gold 수 |
| 근거 Recall@2 | 각 문항에서 적중한 필수 조항 비율의 평균 / gold 검색 가능 근거가 있는 자유 검색 문항 수 |
| 전체 근거 적중@2 | 사전 허용 근거 묶음 하나의 모든 조항·예외·각주가 top 2에 있음 / 위 검색 대상 수 |
| 실제 전달 근거 충족 | 실제 모델 입력이 완전한 근거 묶음을 포함 / 모델 문맥을 계획한 검색 대상 수 |
| 인용 지지 | 인용으로 뒷받침되는 검증 가능 주장 수 / 유효 답변 내 검증 가능 주장 수; 누락 인용은 실패 |
| 계산 성공 | 금액·기간·단위·제약·조건부 표현 전부 정확 / gold 계산 문항 수 |
| 실패율 | 각 오류 발생 문항 수 / N, 그리고 generation 오류는 실제 호출 수도 병기 |

Recall은 문항별 허용 근거 묶음 중 최대 조항 recall을 사용한다. 묶음은 결과를 보기 전 확정한다.
retrieved chunk가 부분 문자열만 갖고 표 머리말·필수 각주를 잃었다면 조항 적중으로 인정하지 않는다.
R1은 공통 @2와 고정한 실제 @k를 함께 보고한다. 직접 제공한 규칙 근거는 별도 `source_bound` 지지 검사다.
근거 없는 질문에는 Recall=1을 주지 않고 별도 abstain/오류로 집계한다.
비LLM N0에는 모델 입력 근거 지표를 N/A로 둔다.

오류 태그는 다중 선택: `retrieval_missing`, `source_or_version_mismatch`, `exception_omitted`,
`unsupported_assertion`, `false_exclusion`, `false_approval`, `unknown_as_false`, `calculation`,
`unnecessary_abstention`, `repetition`, `truncated`, `invalid_json_or_schema`, `invalid_citation`,
`solver_timeout`, `transport_timeout_or_error`, `missing_response`.
V12식 검색 누락과 반복/잘림은 각각 표시한다. 태그 합계가 N을 넘을 수 있음을 명시한다.

문항 micro와 누출 그룹별 성공률의 동일 가중 macro를 둘 다 보고한다.
대학/범위/유형/route별 n과 그룹 수를 붙이며 작은 strata를 숨기거나 독립 대학 수로 부풀리지 않는다.
주 비교와 구성 차이의 95% 구간은 같은 test 그룹을 모든 arm에서 함께 재표집하는
paired cluster bootstrap(2,000회, seed=20261104, percentile 2.5/97.5)으로 구한다.
그룹 내 모든 행을 유지한다. 시험 그룹 10개는 불확실한 탐색값임을 명시한다.
비율 지표의 재표집 분모가 0인 횟수와 유효 횟수를 보고하고 0으로 대체하지 않는다.
유효 재표집이 95% 미만이거나 그룹이 2개 미만이면 그 구간은 N/A다.
승인된 목표 정확도/배포 합격선은 **없다**. 결과를 보고 합격선을 만들어 통과를 선언하지 않는다.

## 8. 호출·지연·동결과 중단 규칙

- 질문 N, arm별 판단 수, 계획 호출, 실제 HTTP 시도, 성공 응답, 오류/timeout, 재사용 응답,
  규칙 처리, warm-up을 분리한다. 원시 요청마다 call ID와 요청/응답 해시, 사용 arm을 연결한다.
  timeout 시 사용량은 unknown이지 0토큰이 아니다.
- 주 비교는 응답 재사용 없이 arm별 실행을 기본으로 한다. 20 test 문항 × Qwen 4 arms는
  최대 80 model calls, N0 포함 100 judgments 계획이며 규칙/보류 직결 시 호출이 줄어든다.
  이는 아직 실행 수가 아니다. 재사용 진단을 별도로 할 경우 실제 호출 한 번을 여러 번 세지 않는다.
- 전체 지연은 입력 검증·검색·판정·생성을 포함해 단조 시계로 재고, 생성 지연과 검색 시간을 따로 기록한다.
  arm별 p50/p95는 정렬값 `ceil(p*n)`번째(nearest-rank), n도 병기한다.
  완료 요청 지연과 timeout/중단의 관측 소요·설정 한도를 함께 보고한다. 캐시 재생 지연을 실시간 지연에 합치지 않는다.
  입력/출력 토큰 합계·분포, usage 누락 수, peak RSS/동시성/CPU 및 서버 설정을 기록한다.
- E02 lock에는 protocol/코드/dirty diff/원문·구간 allowlist/색인/그룹·분할/질문·gold·검수/
  프롬프트·스키마/모델·런타임/실행순서/arm 설정/채점 코드/환경의 해시를 포함한다.
  private 값은 보관자에게 두고 공개 보고에는 허용된 aggregate/digest만 둔다.
  시험 질문 공개 전에 후보 코드를 고정하고, 생성 전에 원시 요청에 gold가 없는지 보관자가 감사한다.
- 새 run ID와 새 출력 디렉터리를 사용하고 기존 경로가 있으면 중단한다.
  resume은 동일 lock이고 기록된 완료 call은 재실행하지 않는 경우만 허용한다.
  미완료/전송 여부 불명 시 원래 오류를 보존한다. 재요청은 사전 재시도 0회 규칙 때문에 주 run에 추가하지 않는다.
- 시험 결과를 본 뒤 코드·프롬프트·채점·gold를 바꾸면 새 실험이다. 원본은 보존하고
  정정 사유/영향/원점수와 정정 분석을 별도 기록한다. 과거 답변을 지우거나 denominator를 줄이지 않는다.
  실행 중 치명적 환경 장애로 중단되면 `incomplete`로 보고하고 누락을 실패 수에 남긴다.

## 9. E02 진입 조건과 다음 담당자

E01 준비 완료와 E02 실행 허용은 다르다. 현재 아래 조건은 모두 최종 확인 전이다.

1. H1 두 명과 보관자의 실제 지정, 독립성·접근 권한·자료 배포 확인.
2. S1 원문 수정본/쪽/표/각주와 규정/FAQ 구간 확인. 후보별 검수 2건 및 조정 승인 증거.
3. 노출/누출 감사와 목표 25개 그룹 모집 완료, private split/digest 및 실제 coverage 고정.
4. R01/M01 후보와 동일 L 버전 결정; public dev만으로 설정 선택. 공통 상태 채택은 S0 담당.
5. E02 harness의 allowlist·불변 lock·새 run 경로·실패/호출 계측 검증. 현재 구 평가 스크립트로 대체 금지.
6. 실행 설정/지표/허용 출력/표본을 동결한 뒤 시험 접근 허용. 누락 시 최종 평가 대기.

H1 미확보로 S1 D01, S2 R01, S4 M01의 공개 개발 실험을 막지는 않는다.
이들 결과는 개발 성능으로 기록하고 시험 결과로 설정을 선택하지 않는다.
E01 검증은 문서/metadata 일관성만 확인하며 사람 검수·의미 정답·런타임 성능을 인증하지 않는다.
