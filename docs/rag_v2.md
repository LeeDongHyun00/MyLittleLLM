# 계층형 검색·의미 검색·예시·출력 개선

Qwen3-4B Q4_K_M의 가중치를 더 학습시키지 않고, 공식 문서에서 근거를 찾고 답하는 경로를 개선한다. 기존 CPU 서버에서 실행하며 QLoRA는 사용하지 않는다. 앞서 실행한 SFT·OPSD 어댑터와 LLMLingua-2 압축은 별도 비교 결과로 보존한다.

## 논문과 실제 적용 범위

| 연구 | 이 저장소에 적용한 부분 | 재현하지 않은 부분 |
|---|---|---|
| [HiChunk, ACL 2026](https://aclanthology.org/2026.acl-long.1372/) | 페이지→부모 절→검색용 작은 구간의 계층, 같은 부모의 검색 결과 병합, 조건·각주를 포함하도록 부모 확장 | 원 논문의 학습된 청킹 모델과 대규모 학습. 여기서는 PDF 절 구분자와 토큰 예산을 사용한 응용 구현이다. |
| [Qwen3 Embedding, 2025](https://arxiv.org/abs/2506.05176) | 공식 Embedding-0.6B와 Reranker-0.6B 실제 추론, BM25와 RRF 결합, yes/no 점수 재정렬 | 논문 전체 벤치마크 및 BF16 대비 검색 품질 비교. CPU에서는 Linear 층에 동적 INT8 양자화를 적용한다. |
| [TripletRAG, GroundLM 2026](https://aclanthology.org/2026.groundlm-1.72/) | 기존 개발 자료의 질문·근거·답변 묶음 중 의미가 가까운 예시 1개를 제공 | 새 교사 모델 학습이나 자동 대규모 데이터 생성. 예시는 원문과 대조했으나 독립 사람이 승인한 gold가 아니다. |
| [AloLab, 2026](https://arxiv.org/abs/2605.02363) | 이전 평가에서 확인한 잘림·중복·후속 질문 문제를 반영한 후보 프롬프트 2개, 기존 개발 문항으로 선택 | 외부 최적화 모델을 사용하는 원 논문의 전체 탐색. 구조화 JSON 출력 제약을 함께 적용한 제한적인 응용이다. |

논문명은 구현의 출처이며 논문과 동일한 개선율을 재현했다는 뜻이 아니다. HiChunk와 의미 검색은 한 검색 개선 조건으로, 프롬프트와 JSON 스키마는 한 출력 개선 조건으로 묶었다. 이 실험만으로 각각의 독립 효과를 분리할 수 없다.

## 검색과 실행

`config/rag_v2.json`에 모델 revision과 검색 예산을 고정한다. 실제 파일 해시는 설치 후 `outputs/retrieval_assets.json`에 기록한다.

- 검색 모델: `Qwen/Qwen3-Embedding-0.6B`, revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`.
- 재정렬 모델: `Qwen/Qwen3-Reranker-0.6B`, revision `e61197ed45024b0ed8a2d74b80b4d909f1255473`.
- 학년도·대학·과제·학기를 먼저 제한한다. 범위를 찾지 못하면 생성 모델을 호출하지 않는다.
- 부모 최대 640토큰, 검색 구간 192토큰/32토큰 겹침, dense·BM25 각각 상위 32개, RRF 상수 60, 실제 재정렬 최대 8개.
- 토큰 구간의 원문 글자 위치를 사용해 한글 한 글자가 중간에서 깨지지 않도록 한다. 초기 색인에서 발견한 경계 문제를 시험 전에 수정했으며, 재색인 때 문장·모델 설정이 같은 임베딩만 해시를 검증한 기존 색인에서 재사용한다.
- 근거 최대 2개·900토큰. 같은 부모는 한 번만 제공한다. 부모가 남은 예산을 초과하면 해당 검색 구간을 사용한다.
- 예시 사실과 현재 근거를 구분하고, JSON 스키마의 인용 ID 목록은 현재 검색 결과만 허용한다.
- 출력 제한은 160토큰이다. 잘린 출력·존재하지 않는 인용은 실패로 처리한다. 스키마가 사실의 정확성을 보장하지는 않는다.

공식 문서 8개 전체를 색인한다. 기존과 동일하게 연도별 열 관계를 잃은 비교표 페이지는 제외하며, 정답 페이지로 검색 범위를 좁히지 않는다. PDF 추출·절 분리 오류 가능성은 남아 있다.

```bash
.venv/bin/python -m pip install -r requirements-retrieval.txt
.venv/bin/python scripts/install_retrieval_assets.py
.venv/bin/python scripts/build_hierarchical_index.py
```

서버는 별도 터미널에서 `./serve.sh`로 실행한다. 저장소의 개발 평가로 선택된 설정이 있으면 다음처럼 실제 개선 경로를 사용한다.

```bash
.venv/bin/python chat.py --pipeline improved --year 2026 --institution 부산대학교 \
  --question '원서 결제 후 주소와 모집단위를 수정할 수 있나요?'
```

`--without-examples`는 예시만 제외하는 비교 옵션이다. 기존 `chat.py` 기본 경로는 `legacy`로 유지한다. 계산기 `--facts`, 문서 없는 추론, LLMLingua-2 압축은 기존 경로에서 사용할 수 있다. 새 경로와 지원하지 않는 옵션을 섞으면 명시적으로 중단한다.

실제 CLI에서는 `LowMemoryQwenRetrievalModels`가 FP32 모델의 큰 복사본을 만들지 않는 in-place INT8 변환과 사용하지 않는 CPU 메모리 반환을 사용한다. 64회 평가가 끝난 뒤 일반 로더를 쓰던 CLI 검사에서 생성 서버 연결이 끊겼고 환경의 OOM kill 기록도 확인해 로딩 시 최대 메모리를 줄였다. 기존 평가 생성자와 해시는 그대로 보존했다. 새 로더는 동일한 encode/rerank 함수를 상속하며, 기존 개발 문항 A04의 검색 결과 ID와 모든 후보 점수가 동일함을 확인했다. [검증 기록](../reports/rag_v2_low_memory_check.json)은 새 시험을 반복한 결과가 아니다.

개발 비교에서 두 후보 모두 이전의 엄격 기준으로 0/4였다. `minimal`은 사전에 정한 동률 규칙에 따라 평균 출력 토큰이 더 적어 선택됐으며, 정확도가 더 높아서 선택된 것은 아니다. 올바른 표현을 놓친 기존 정규식 사례와 실제 검색·추론 오류가 섞여 있다. [개발 응답 검토](../reports/rag_v2_development_review.json)에 이를 분리해 기록했다. `improved`는 실험 경로 이름이며 검증된 품질 향상을 보장하는 표시가 아니다.

## 새 평가 설계

이전 28문항과 학습 예시 5개는 개발 자료다. 새 시험은 **16문항·15개 규칙 그룹**, 부산대 입시 절차 8개와 한국장학재단 주거안정장학금 절차 8개로 고정했다. 두 학년도의 동일한 등록금 납부 규칙은 같은 그룹이다. 개발 자료와 문서 자체는 공유하므로 새 대학·새 문서 일반화 평가가 아니다. 모두 답할 수 있는 문항으로, 정보 부족 시 보류 능력을 새로 측정하지 않는다.

정답·필수 사실 표현·근거 조항 패턴을 먼저 고정한 뒤 다음 순서로 실행한다.

1. 기존 개발 문항 A04·A12·S04·S06에서 프롬프트 두 개를 8회 비교한다. 이전의 고정된 서술형 기준 통과 수, 평균 출력 토큰 수, 이름 순으로 선택한다.
2. 새 16문항의 네 조건 요청 64개를 모두 만들고 SHA-256 해시로 잠근다. 각 문항 안에서 조건 순서를 seed 42로 섞는다.
3. 같은 Qwen3-4B Q4_K_M, 어댑터 없음, temperature 0, seed 42, thinking 비활성, 최대 출력 160토큰으로 순차 실행한다. 검색 모델 추론과 생성 추론을 동시에 돌리지 않는다.
4. 64개 응답이 모두 끝난 뒤 채점한다. 새 시험 결과로 프롬프트·정답 패턴·검색 설정을 고치지 않는다.

| 조건 | 검색 | 프롬프트·형식 | 예시 |
|---|---|---|---|
| legacy | 기존 BM25, 근거 2개 | 기존 프롬프트·JSON 객체 | 없음 |
| retrieval | 계층형 하이브리드+재정렬 | 기존 프롬프트·JSON 객체 | 없음 |
| prompt_schema | 개선 검색 | 개발 자료로 선택한 프롬프트·JSON 스키마 | 없음 |
| triplet | 개선 검색 | 선택한 프롬프트·JSON 스키마 | 기존 자료에서 검색한 1개 |

주 지표는 **완성된 유효 JSON + 필수 사실 패턴 충족 + 실제 인용 구간의 근거 조항 충족**이다. 근거 페이지 번호만 맞아도 통과시키던 이전 방식의 한계를 줄였다. 원래 정답 페이지 외에 같은 조항이 있는 유효한 인용도 인정한다. 그래도 정규식 기반 대리 지표이며 답변 전체의 의미나 모든 추가 주장을 검증하지 않는다. 독립 전문가 정확도로 부르지 않는다.

기존 일반 CLI의 기본 출력 한도는 384토큰이지만 이 비교에서는 네 조건 모두 160토큰으로 통일했다. 따라서 잘림 감소를 포함한 결과는 제한된 출력 예산에서의 개선 여부이며, 기존 CLI의 기본 설정 전체를 그대로 비교한 수치는 아니다. 출력 한도를 늘린 기존 방식과의 별도 비교는 수행하지 않았다.

규칙 그룹 단위 bootstrap 신뢰구간과 조건별 개선·퇴보 수를 함께 보고한다. 16문항의 작은 평가이므로 일반적인 입시 상담 성능으로 확대 해석하지 않는다. 실제 생성 시간과 검색 시간을 각각 공개하며, 합산한 시간은 미리 측정한 검색 비용을 더한 추정치다. 최초 모델 로딩과 전체 색인 생성 시간은 별도로 기록한다.

```bash
# 새 버전의 데이터·출력 폴더에만 최초 1회 실행한다.
.venv/bin/python scripts/prepare_rag_v2_data.py
.venv/bin/python scripts/prepare_rag_v2_inputs.py
.venv/bin/python scripts/select_rag_v2_prompt.py
.venv/bin/python scripts/run_rag_v2_evaluation.py
```

이미 존재하는 시험셋·색인·실행 결과는 덮어쓰지 않는다. 프로세스 중단 복구에 한해 `run_rag_v2_evaluation.py --resume`으로 해시를 검증하고 아직 실행하지 않은 요청을 이어 간다. 실패 응답을 새 답이 나올 때까지 반복 생성하지 않는다.

원문 PDF 전체와 전체 검색 문맥은 Git에서 제외한다. 공개 예시 파일에는 예시 답변을 검증하는 데 필요한 소량의 근거 발췌가 포함된다. 시험 질문·정답 기준·응답·실행 해시·집계는 검토할 수 있도록 저장한다.
