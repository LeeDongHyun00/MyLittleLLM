# SeedLM: 규칙 엔진이 가르친, 처음부터 만든 소형 언어 모델

작성일: 2026-11-18. [규칙 증류 가능성 검토](rule_distillation_feasibility.md)의 후속이다. 사전학습 가중치도 외부 말뭉치도 쓰지 않고 트랜스포머를 처음부터 학습시켰다. 측정은 모두 이 저장소 환경(CPU 4코어, GPU 없음)에서 했다.

## 1. 무엇이고 무엇이 아닌가

- **처음부터 만들었다.** 구조, 토큰 배치, 학습 루프, 옵티마이저, 빔 탐색을 직접 작성했다. 학습 데이터는 전부 규칙 엔진의 연산 라이브러리가 만든다. 연산 프로그램 하나를 뽑아 무작위 인자에 실행하고, 모델에게 "이 입력과 출력을 보고 프로그램을 맞혀라"를 시킨다. 정답이 실행으로 만들어지므로 라벨 오류가 없고 데이터가 떨어지지 않는다.
- **하는 일은 하나다.** 예시의 입력과 기대 출력, 그리고 과제 설명이 이름을 부른 연산 목록을 보고 연산 프로그램을 제안한다. 제안은 실행해서 예시를 재현하는지 확인한 뒤에만 쓰인다.
- **범용 코딩 LLM이 아니다.** 자연어를 이해하지 못하고 Python 코드를 자유롭게 쓰지 못한다. 파라미터는 약 142만 개다.

### 왜 범용 코딩 LLM을 처음부터 만들지 않았나

이 환경에서 불가능하기 때문이다. 근거는 규모다.

| | 이 환경에서 측정 | 범용 소형 코딩 모델 |
|---|---|---|
| 파라미터 | 142만 | 5억(Qwen2.5-Coder-0.5B) 이상 |
| 학습량 | <!-- SEEN_SENTENCE --> | 수조 토큰 규모의 사전학습 |
| 장비 | CPU 4코어 | GPU 수십~수백 장으로 수 주 |

공개된 선례도 같은 방향이다. TinyStories는 100만~3,500만 파라미터 모델을 V100 한 장으로 최대 30시간 학습해 짧은 동화를 쓰게 했지만 100만 파라미터 모델은 "사실 질문에 하나도 답하지 못한다"고 보고했다. nanochat의 CPU 경로(M3 Max에서 약 30분)는 문서에 "이 방식으로는 좋은 결과를 얻을 수 없다"고 적혀 있다. 그래서 처음부터 만드는 모델은 **좁지만 실제로 쓰이는 일**에 맞췄다.

## 2. 설계: 직교성을 어디에 넣었나

| 설계 | 내용 | 직교성과의 관계 | 근거와 주의 |
|---|---|---|---|
| 회전 위치 임베딩 | 위치를 질의·키 벡터의 회전으로 넣는다 | 회전은 직교 변환이라 벡터 길이를 보존한다. 위치 표를 학습할 필요가 없다 | 현행 소형 모델 레시피의 표준 |
| 직교 초기화 + 항등 블록 | 모든 행렬을 직교 행렬로 시작하고, 잔차 흐름에 쓰는 두 사영은 0으로 시작한다 | 신호의 크기를 층마다 보존한다. 각 블록은 처음에 항등 함수다 | 언어 모델에서의 근거는 얇다. 현행 레시피는 직교 초기화를 쓰지 않는다. 그래서 3절에서 직접 비교했다 |
| 규칙마다 직교 방향 | 연산 토큰의 임베딩 행을 서로 직교하게 시작한다(폭이 허락하는 만큼) | 규칙 사이의 간섭을 줄인다 | 연산 328개 > 폭 160이라 완전한 직교는 아니다(행 사이 내적 평균 0.02) |
| 직교화 갱신(Muon) | 은닉 행렬을 기울기 방향이 아니라 모멘텀의 직교화(UVᵀ 근사)로 갱신한다 | 갱신의 모든 방향 크기를 비슷하게 맞춘다 | 공식 구현을 그대로 옮겼다. 1억 파라미터 이상에서는 AdamW 대비 1.1~1.4배가 보고됐지만, 수백만 파라미터·CPU·작은 배치에서의 비교는 찾지 못했다. 3절에서 측정했다 |
| 새 규칙의 직교 추가 | 새 연산의 임베딩·출력 행을 기존 연산 행이 가장 덜 쓰는 방향에서 시작하고, 그 행만 학습한다 | 기존 규칙의 행을 건드리지 않는다 | 연속학습의 직교 부분공간 방법(O-LoRA, 저특이값 방향 미세조정)과 같은 생각이다. 4절에서 측정했다 |
| 코사인 주의, RMSNorm, ReLU² | 질의·키를 정규화하고, 사전 정규화에 파라미터 없는 RMSNorm, 활성화는 ReLU² | 직교성과 직접 관련은 없다 | 현행 소형 모델 레시피를 따랐다 |
| 문법 제약 빔 탐색 | 연산의 인자 수를 세어, 완성될 수 있는 프로그램만 디코딩한다 | — | 규칙(문법)이 모델의 출력을 제한한다 |

넣지 않은 것: nGPT식 전면 정규화(재현 연구에서 이득이 원 논문보다 작았고, 이미 쓰는 코사인 주의 대비 1.29배로 보고됐다), 직교 미세조정(OFT 계열, 사전학습 가중치가 있어야 의미가 있다).

토큰 배치는 다음과 같다. 프로그램 부분만 학습 대상이다.

```
BOS  <인자 목록의 바이트>  OUT  <기대값의 바이트>  NAMED  <설명이 부른 연산 토큰들>  PROG  <프로그램(전위 표기)>  EOS
```

## 재현

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu
python scripts/seedlm_train.py --name main --minutes 25 --optimizer adamw --init orthogonal --holdout-ops 30
python scripts/seedlm_add_rules.py --base main --method rows --save-as main-all
python scripts/seedlm_tasks.py --model main-all --splits train val
python -m unittest tests.test_seedlm -v
```

학습은 서버(llama.cpp)가 꺼진 상태에서 돌린다. 두 프로그램이 4코어를 나눠 쓰면 측정 시간이 비교 불가능해진다.
