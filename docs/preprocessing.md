# 설정 조정과 PDF 전처리 구현

Qwen3-4B Q4_K_M의 가중치를 추가 학습하지 않고 출력 예산·문서 전처리·검색·검증을 변경하는 실험이다. [조사 근거](preprocessing_research.md)의 우선순위를 구현했다. 기존 `legacy`, `improved` 경로와 과거 평가 결과는 보존한다.

[실행 결과](../reports/preprocessing_report.md): 새 12문항의 자동 기준은 concise 10/12, 입력 확대 10/12, preprocessed 9/12였다. 출력 잘림은 없었으나 전처리의 정확도 향상은 확인하지 못했다. 이번 비교에서는 생성 비용이 낮은 `concise`를 기준 경로로 권장하며, `preprocessed`는 실험 옵션으로 유지한다.

## 실행

```bash
.venv/bin/python -m pip install -r requirements-preprocessing.txt
.venv/bin/python scripts/build_preprocessed_index.py
./serve.sh
```

색인 생성은 기존 원문·추출 파일과 로컬 Qwen 토크나이저가 필요하다. 생성된 색인이 있으면 덮어쓰지 않는다. 현재 설치된 환경에는 색인을 이미 생성했다.

기존 BM25 상위 2개와 짧은 프롬프트·JSON 스키마:

```bash
.venv/bin/python chat.py --pipeline concise --max-tokens 384 \
  --year 2026 --institution 부산대학교 \
  --question '수시 합격자의 등록의사는 어떻게 확인하나요? 예치금이 필요한가요?'
```

표·조항 전처리, 전형 범위 검사, BM25 근거 유지, 의미 검색 후보 병합:

```bash
.venv/bin/python chat.py --pipeline preprocessed --max-tokens 384 \
  --year 2026 --institution 부산대학교 --admission-track 논술 \
  --question '검정고시 자료 온라인 제공이 안 되는 논술전형 지원자는 성적증명서도 제출하나요?'
```

`--lexical-only`를 추가하면 임베딩·재정렬 모델을 로드하지 않고 전처리 색인과 BM25만 사용한다. 이는 별도 경로이며 의미 검색을 사용하는 주 평가와 동일한 결과를 보장하지 않는다. 전형 계열을 명시하지 않으면 질문에 하나만 나타날 때 자동 인식한다. 지역인재 등 모든 세부 전형의 조건을 자동 판별하는 기능은 아니다.

`--max-tokens`는 64–1,024 범위에서 지정할 수 있다. 기본값은 legacy/concise/preprocessed 384, 기존 improved 160이다. 기본 파이프라인은 여전히 legacy다.

## 구현한 전처리

- 공식 원문 8개를 사용한다. 부산대 2025·2026 수시 요강과 2026 주거안정장학금 계획의 지정 범위에는 pdfplumber 0.11.8을 실제 실행했다. 다른 문서는 기존 추출 텍스트를 사용한다.
- 문장을 토큰 수에 맞춰 자르면서 뒤의 예외를 버리지 않도록, 번호 조항과 뒤따르는 주의사항을 함께 유지한다. 예산보다 큰 조항은 중간 절단 없이 건너뛰며 기록한다. 따라서 긴 조항이 검색에서 빠지는 한계는 남는다.
- 표의 병합 셀은 실제 셀 좌표로 복원한다. 위 행의 값을 무조건 복사하지 않는다. 표 머리글과 셀 원문, 좌표를 각 행에 저장한다. 머리글이 확인되지 않는 표는 행 색인에서 제외하고 본문 추출을 유지한다.
- 주거 계획 PDF 25쪽의 혼합 학기 일정표는 원문 해시·표 좌표·행 수를 확인한 주석으로 학기를 구분한다. 이 페이지의 평면 텍스트를 새 경로에 넣지 않는다. 2학기 계획 행은 1학기 질의에서 제외한다. 2학기 질의에서는 해당 행을 검색할 수 있지만, '일정 반영 예정'을 확정 날짜로 취급해서는 안 된다.
- 부산대 2026 요강의 검수한 페이지 범위에 학생부교과·학생부종합·논술·실기/실적 계열을 표시한다. 원문이 바뀌면 주석 재검수가 필요하도록 해시를 고정했다. 모든 대학·연도의 세부 전형에 적용되는 범용 분류기는 아니다.
- 검색용 문장에는 대학·학년도·PDF 페이지와 확인된 적용 범위를 붙인다. 질문에서는 이미 범위 필터에 사용한 대학·연도·일반 문서명을 제거한 검색문도 사용한다. 날짜·차수·부정·예외 조건은 유지한다.

Docling, OCR, 새로운 압축 모델은 이번 경로에 추가하지 않았다. 이번 문서들은 디지털 PDF의 표 구조 문제가 우선이어서 pdfplumber로 시작했다. 문자량이 적은 페이지는 OCR 검수 대상으로 기록한다. 기존 다년도 비교표 격리도 유지했다. 표 각주의 행별 적용 관계는 완전 자동 해석하지 않으며 페이지 주의사항임을 표시한다.

## 검색과 생성

새 경로는 기존 BM25, 전처리 문단·행의 BM25, 실제 Qwen Embedding/Reranker가 만든 후보 페이지의 전처리 구간을 후보로 삼는다. 이전에 최종 2개로 축소하면서 잃던 근거를 줄이기 위해 신경망 후보 8개의 페이지를 활용한다. 각 후보 목록에서 차례로 선택해 어휘 검색 근거가 모두 사라지지 않게 한다.

최대 4개 구간·1,800 근거 토큰이며 실제 생성 모델의 토크나이저로 계산한다. 이미 있는 긴 근거에 완전히 포함되는 짧은 구간은 중복으로 제외한다. 반대로 짧은 구간 뒤의 예외를 포함하는 긴 구간은 단순 중복으로 버리지 않는다. 이것은 재정렬 점수의 확률 보정이나 학습된 선택기가 아닌 명시적 선택 규칙이다.

temperature 0, seed 42, thinking 비활성화, 예시 없음으로 생성한다. JSON 스키마와 인용 ID 검사는 형식 검사이며 사실·예외 해석의 정확성 보증은 아니다. 근거가 없으면 생성 호출 없이 답변을 보류한다. 근거가 있지만 충분하지 않은 경우의 보류 판단은 여전히 모델에 의존한다.

## 계산 도구 연결

`--pipeline preprocessed --task housing --semester 1 --facts 파일.json`으로 기존 주거비 계산기를 연결했다. 계산 조건과 질의의 연도·학기가 같아야 한다. 2026년 1학기 3–6월, 선발·지급 승인·중복수혜 없음이 확인된 시나리오만 지원한다. 3월 정액 지원은 `pledge_submitted=true`도 요구한다.

```json
{
  "year": 2026,
  "semester": 1,
  "month": 4,
  "selected": true,
  "payment_approved": true,
  "duplicate_support": false,
  "recognized_expense_krw": 120000
}
```

지원 금액·실제 지출 범위의 조항을 반드시 함께 넣고, 3월에는 서약서 제출 조건도 넣는다. 모델 답변의 원화 금액이 계산 결과와 상한에서 벗어나거나 실제 계산 금액을 빠뜨리면 검증 실패로 처리한다. 이 검사는 금액 일치 검사이며 지급 보장 표현 등 모든 의미 오류를 검증하지는 않는다. 자격 확인과 지급 승인을 자동으로 취득하는 기능도 아니다.

## 평가 재현

```bash
.venv/bin/python scripts/run_preprocessing_development.py
.venv/bin/python scripts/prepare_preprocessing_holdout.py
.venv/bin/python scripts/evaluate_preprocessing.py --prepare
.venv/bin/python scripts/evaluate_preprocessing.py --run
```

이미 실행한 단계는 덮어쓰지 않는다. 중단된 추론은 해당 실행기의 `--resume` 옵션으로 누락된 요청만 이어간다. `--prepare`는 별도 프로세스에서 검색 모델을 사용하고 종료하여, 생성 평가 중 큰 검색 모델이 메모리를 점유하지 않게 한다. 로컬 모델과 원문 전체는 Git에서 제외되어 있어 새로운 환경에서는 기존 설치·수집 절차가 먼저 필요하다.

완료한 고정 평가의 코드 커밋은 `ebbc891fbbe1f6cc10ed6ccfd79d4359f81fa2cb`다. 이후 계산 금액 검증에서 음수·원 단위 소수 오인식을 고쳤으므로 현재 코드로 과거 실행을 `--resume`하면 의도대로 해시 검사가 실패한다. 기존 평가를 검증·이어가기 위해서는 해당 커밋을 사용하고, 새 코드 실험은 별도 실행 경로로 분리해야 한다. 후속 수정은 12문항에서 호출하지 않은 계산 검증 분기에만 해당하며, 저장된 36개 요청의 동일성도 따로 검사했다.

개발 단계는 이미 공개된 8문항에서 기존 160토큰 응답을 재사용하고, 기존 지시 384토큰과 짧은 지시·스키마 384토큰을 각각 새로 실행한다. 개발 검색 점검에는 기존 16문항을 사용한다. 두 결과 모두 새 시험 정확도가 아니다.

자동 선택 기준은 긴 기존 프롬프트를 추천했지만, 맞는 핵심 사실 뒤에 잘못된 추가 주장을 붙인 답도 통과시켰다. 새 시험 전에 개발 검토로 이 문제를 확인하고, 짧은 `minimal`·스키마를 검색 비교의 공통 조건으로 고정했다. 짧은 답변에도 실제 오류가 있으므로 정확도 우위로 주장하지 않는다. 이 선택 수정은 `config/preprocessing_selected.json`과 개발 검토 기록에 남겼다. 실행을 다른 환경에서 재현할 때도 이 선택 파일을 사용한다.

새 시험은 기존 질문과 다른 규칙 그룹 12개, 답변 가능 10문항과 보류 필요 2문항이다. 같은 원문 문서를 공유하므로 새 대학·새 문서 일반화 검증이 아니다. 독립 전문가가 검수한 정답셋도 아니다. 조건은 다음 세 가지다.

| 조건 | 검색·입력 | 생성 |
|---|---|---|
| concise_k2 | 기존 BM25 상위 2개 | 동일한 선택 프롬프트·출력 384 |
| bm25_budget | 기존 BM25, 최대 4개·1,800토큰 | 동일 |
| preprocessed | 전처리·범위 검사·검색 병합, 최대 4개·1,800토큰 | 동일 |

동일한 최대 예산이어도 실제 입력 길이는 다를 수 있다. 최종 조건은 전처리·질의 정리·범위 검사·선택 방법을 묶은 비교이므로 개별 기술의 효과로 분리해 주장하지 않는다. 답변·근거 패턴의 자동 점수와 전체 응답의 의미 검토를 구분해 보고한다. 시험 결과를 보고 프롬프트·검색·정답 기준을 다시 조정하지 않는다.
