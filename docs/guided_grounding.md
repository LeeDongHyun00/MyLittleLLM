# 한국어 조건 수집과 입시 규칙 확대

`--pipeline grounded`에 한국어 문답으로 필요한 조건을 수집하는 기능과 부산대 2026 수시의 세 가지 부분 판정 규칙을 추가했다. 규칙은 총 9개다. 기존 Qwen3-4B 서버, BM25 상위 2개 검색, 짧은 프롬프트·JSON 스키마·384 출력 토큰을 유지한다. 모델 가중치는 학습하지 않았다.

[새 12개 사례 평가](../reports/grounding_v2_report.md)의 자동 통과는 같은 근거 Qwen 5/12, 확대 규칙·보류 11/12였다. 자유 질문 1건은 검색 조항 누락과 생성 반복·잘림으로 실패했다. 자동 점수와 전체 응답의 의미 검토를 함께 공개한다.

## 한국어 문답으로 실행

현재 범위에서 사용할 수 있는 규칙 목록:

```bash
.venv/bin/python chat.py --pipeline grounded --year 2026 \
  --task admissions --institution 부산대학교 --list-rules
```

JSON 파일 없이 수시 추가 지원 횟수 확인:

```bash
.venv/bin/python chat.py --pipeline grounded --year 2026 \
  --task admissions --institution 부산대학교 \
  --guided-rule admissions_susi_application_limit \
  --question '수시 추가 한 번 지원의 횟수 요건을 판정해 주세요.'
```

이번 전형이 6회 제한에 포함되는지 확인하는 질문에 `예`, 기존 산입 횟수에 `5`를 입력하면 횟수 요건 충족으로 답한다. 기존 산입 횟수에 `모름`이라고 답하면 횟수를 확인해 달라고 요청하며 판정을 보류한다. 대학별 복수지원 조합이나 최종 합격까지 판정하지 않는다.

주거장학금 성적·학점 확인:

```bash
.venv/bin/python chat.py --pipeline grounded --year 2026 --semester 1 \
  --task housing --institution 한국장학재단 \
  --guided-rule housing_academic \
  --question '성적·이수학점 요건만 확인해 주세요.'
```

일반 학기제와 신·편입·재입학 첫 학기 면제 여부에 모두 `예`라고 답하면 성적·학점 질문을 더 하지 않고 해당 부분 요건을 판정한다. 이 두 확인은 실제 학교 기록을 조회한 결과가 아니라 사용자가 제공한 조건이다.

- 예/아니요 질문은 `예`, `네`, `아니요`, `아니오` 등을 받는다. 정수 질문은 단위 없이 숫자를 입력한다.
- `모름` 또는 빈 입력은 미확인으로 남긴다. 미확인을 아니요·0으로 바꾸지 않는다. `/quit`이나 입력 종료는 수집을 멈추고 확인된 조건으로만 처리한다.
- `--guided-rule`은 한 질문의 상담에 사용하므로 `--question`을 함께 지정한다. 기존 `--facts` 파일을 함께 지정하면 같은 규칙의 빠진 조건을 이어서 수집할 수 있다.
- 규칙은 사용자가 명시적으로 선택한다. 자연어에서 규칙이나 개인 조건을 자동 추출하지 않는다. 질문과 조건 간 모든 의미 충돌을 탐지하는 기능도 없다.
- 판정 전에 규칙의 원문 해시·핵심 구절과 대학·학년도·학기를 확인한다. 적용 범위 확인이 없으면 먼저 질문하고, 적용 범위 밖이면 해당 규칙으로 결론을 내리지 않는다.

## 추가한 규칙

모두 부산대학교 2026학년도 수시모집요강의 일부 조건에 한정한다. 다른 대학·연도로 확대 적용하지 않는다.

| 규칙 | 원문 PDF 쪽 | 판정 범위와 조건 |
|---|---:|---|
| `admissions_susi_application_limit` | 27 | 이번 전형이 6회 제한에 산입됨을 먼저 확인한다. 이번 접수 이전의 산입 횟수가 6회 미만인지 판단한다. 산업·전문대와 열거된 제외 특별전형의 분류는 사용자가 확인해야 한다. 같은 대학의 여러 전형도 각각 계산한다. |
| `admissions_low_income_status` | 54 | 학생부종합 저소득층학생전형에 한정한다. 정규 고교 졸업(예정) 또는 인정된 동등 학력, 그리고 법정 수급권자·수급자/차상위계층/한부모가족지원법 지원대상 중 하나의 조건을 판정한다. 가족 형태나 소득 숫자에서 법정 지위를 추정하지 않는다. |
| `admissions_vocational_subject` | 54 | 최신 공지·입학처로 모집단위와 기준학과·교과의 대응을 확인한 경우에만 판정한다. 해당 학교 유형의 졸업(예정), 마이스터·체험형 특성화고 제외, 동일계열 기준학과 이수 또는 관련 전문교과 30단위 이상을 확인한다. 최종 지원자격 심의는 별도다. |

`eligible_school_graduate`는 특성화고 또는 같은 교육과정을 운영하는 일반고 학과의 졸업(예정)이라는 일반 학교 조건을 나타낸다. 마이스터·체험형 학교 제외 여부는 별도 필드로 확인한다. 입력한 조건들이 참이라고 외부 검증하는 기능은 없다. 학점·점수 입력은 현재 정수 범위만 지원하며 소수를 반올림해 판정하지 않는다.

기존 6개 규칙과 계산기의 범위는 [기존 구현 문서](grounding.md)를 참고한다. 원문 검수는 AI가 수행했으며 독립 전문가의 승인은 아직 없다.

## 추가 질문 선택과 보류

질문 선택은 현재 확인된 조건을 고정하고, 한 미확인 변수만 달라지는 두 가능한 상황에서 결론이 달라질 수 있는지 Z3로 검사한다. 결론과 무관한 질문은 제외하고, 답이 입력될 때마다 다시 판단한다. 변수 간 제약 때문에 여러 값이 함께 바뀌어야 하는 경우에는 빠진 질문을 보수적으로 유지한다. 질문 수가 항상 최소라는 보장은 없다.

논리 연산 시간 초과는 조건 부족이나 거짓으로 바꾸지 않고 별도 보류한다. 학교별 수혜 횟수가 전체 누적보다 큰 모순 입력도 보류한다. 일반 학기제 등 규칙 적용 조건 자체가 미확인이면 해당 조건부터 묻는다.

개인 기록 보류 검사는 실제 입금·선발 결과 질문과 일반 기준·확인 절차 질문을 구분하도록 보완했다. 예를 들어 `입금됐나요?`는 보류하고, `제가 입금됐는지 확인하는 방법을 알려 주세요`는 문서 검색으로 보낸다. 한국어 표현을 제한적으로 분류하는 규칙이므로 모든 의도·부정·복합 문장을 해결하지는 않는다.

신경망 검증은 계속 `--claim-check` 실험 옵션이다. 이번 개선 비교에서는 사용하지 않는다.

## 재현과 검수

새 12개 시나리오의 비교 명령:

```bash
.venv/bin/python scripts/evaluate_grounding_v2.py --stage prepare
.venv/bin/python scripts/evaluate_grounding_v2.py --stage generate
.venv/bin/python scripts/evaluate_grounding_v2.py --stage evaluate
```

코드·원문 색인·요청·정답·모델 실행 조건을 먼저 고정한다. 기존 출력 폴더를 덮어쓰지 않으며, 중단된 생성은 `--stage generate --resume`으로 이어간다. 결과 확인 후 코드를 수정했다면 과거 잠금 실행은 당시 코드 커밋으로 재현해야 한다.

이번 고정 코드 커밋은 `cc99c19ac6b663a0428dc8820c24094d7c1d9fc7`이다. 평가 후 모델 요청·규칙·채점 기준을 바꾸지 않았다. 검수 양식의 V12에는 검색에서 빠졌던 원문 PDF 10쪽 참고를 추가했으며 모델에 제공한 구간과 구분해 표시했다.

이 평가는 새로 구현한 규칙을 대상으로 한 공학적 점검이다. 같은 규칙과 문서를 공유하며, AI가 작성한 조건·정답을 사용한다. 자연어 조건 추출이나 새 대학 일반화 성능은 측정하지 않는다. 한국어 문답 CLI는 별도의 스크립트 입력 점검으로 확인한다. 실제 사용자가 수행한 사용성 평가가 아니다.

독립 검수를 위한 [빈 검수 양식](../data/review/grounding_v2_blind_review.csv)을 만들었다. 질문·조건·원문 링크·PDF 쪽만 포함하고 제안 정답과 모델 응답은 넣지 않았다. 검수자는 먼저 답과 근거를 작성한 뒤 [제안 정답](../data/evaluation/grounding_v2_scenarios.jsonl)과 대조할 수 있다. 검수자·검수일은 비어 있으며 독립 검수가 완료된 것으로 취급하지 않는다. 원문을 읽어도 한 가지 답으로 정하기 어려우면 수정·제외 사유를 남겨야 한다.

평가에 사용한 시나리오는 공개 이후 개발 자료로 취급한다. 다음 일반화 검증에는 별도로 검수한 새로운 사례가 필요하다.
