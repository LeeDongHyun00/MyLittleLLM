# 제안 판정: 목적은 지지, 현재의 정답 정의와 무작위 분할은 반대

모집요강과 공식 설명을 이용해 입시·장학 상담의 정확도를 평가하는 방향은 적절하다. 그러나 **모집요강을 입력, 설명 자료 전체를 정답으로 정하고 60:40으로 임의 분할하면 상담 능력을 검증했다고 보기 어렵다.** 비율보다 표본, 정답, 누출 통제와 비교 대상이 중요하다.

## 무엇이 잘못될 수 있나

| 현재 가정 | 문제 | 수정 |
|---|---|---|
| 설명 자료는 정답이다 | 일반 조언, 전년도 입결, 빠진 예외, 수정 전 규정이 섞일 수 있음 | 설명은 정답 후보. 질문별 공식 근거와 버전을 대조하고 사람 검수 |
| 문서 60%를 읽히면 학습된다 | 프롬프트 입력, RAG 색인, 계속 사전학습, 지도 미세조정은 다른 실험 | 무엇의 가중치를 업데이트하는지와 입력·출력 단위를 명시 |
| 질문을 무작위로 나누면 독립 평가다 | 같은 규칙의 표현 변경, PDF/HTML 복사본, 2025/2026 반복 문구가 양쪽에 유입 | 동일 규칙·템플릿·버전의 연결 그룹으로 분할 |
| 2025 학습, 2026 시험이면 누출이 없다 | 반복 조항이 많고 기반 모델이 웹문서를 이미 봤을 가능성도 있음 | 연도 일반화 실험으로 명명하고 변경 조항/반례를 별도 보고 |
| 답안과 문장이 비슷하면 정확하다 | 금액·마감일·예외 하나만 틀려도 실제 상담에서는 치명적 | 구조화 필드, 원문 근거, 추가 확인 및 보류의 적절성 채점 |
| 모집요강이면 장학금·실부담도 계산된다 | 학기별 지원액, 중복수혜, 등록금/기숙사 자료 부족 | 별도의 비용·지원 정책 원문과 계산 규칙 수집 |

실제 사례: [부산대 2026 수시 2차 수정공고](https://go.pusan.ac.kr/college_2016/pages/index.asp?b=B_1_1&bn=48469&f=ALL&m=read&nPage=1&p=50)는 2025-09-01 수정본이다. 그보다 앞선 가이드북의 모든 설명을 최종 정답으로 간주할 수 없다. [2025 주거안정장학금 변경 공고](https://www.kosaf.go.kr/ko/notice.do?mode=view&page=1&seqNo=20088)는 변경사항이 2학기부터 적용된다고 명시한다. 연도만 같아도 정답이 달라질 수 있다.

## 데이터 단위

하나의 학습/평가 표본은 다음 정보를 갖는 질문-답변이다.

```text
id, question, academic_year, semester, institution, admission_track,
applicant_conditions, answer, expected_action(answer/clarify/abstain),
required_facts, forbidden_claims,
evidence[{source_id, sha256, pdf_page 또는 section, rule_id}],
explanation_source_ids, institution_group, leakage_group,
review_status, reviewer_ids, reviewed_at, as_of_date
```

예: “2026학년도 A대 B전형, 2024년 졸업자는 지원할 수 있는가?”에 대해 졸업연도 제한, 추천/거주 조건, 예외를 원문에서 확인한다. 설명 자료를 통째로 출력하도록 학습하는 것이 아니다. 표에서 `2024.2~2026.2`를 읽을 때 열 제목, 각주, 예외를 함께 보존한다.

`data/examples/qa_candidates.jsonl`은 형식을 설명하기 위한 초안이다. 사람의 독립 검수가 완료된 gold가 아니며 분할 스크립트는 이를 거부한다. FAQ에서 정답을 만들었다면 대응하는 규정 원문까지 추적한다. 설명이 없는 규정에서도 직접 질문을 만들어 쉬운 FAQ에 편중되는 것을 막는다.

## 60:40을 유지하는 수정안

전체의 **60%를 개발용, 40%를 잠근 최종 시험용**으로 배정한다. 개발용 60% 안에서 80:20으로 나누면 전체 기준 **학습 48% / 검증 12% / 시험 40%**다. 검증셋으로 프롬프트, 청크 길이, 검색기, LoRA 설정을 정하고 시험셋은 최종 비교에 한 번 사용한다. 시험을 보고 고치면 해당 셋은 개발셋이 되며 새로운 시험셋이 필요하다.

배정 단위는 독립적인 그룹이다. 그룹 크기가 다르면 행 수의 비율이 정확히 48/12/40이 되지 않는다. 스크립트는 실제 행 비율과 그룹 수를 보고한다. 비율을 맞추려고 동일 규칙을 쪼개지 않는다.

실험을 섞어 하나의 정확도로 보고하지 않는다.

1. **규칙 일반화:** 같은 대학의 관련 규칙, 연도별 대응 조항, FAQ 변형을 하나의 `leakage_group`으로 묶는다. 대학은 양쪽에 나타날 수 있다. 공통 전국 규정·공통 질문 템플릿도 연결된 그룹으로 묶거나 별도 챌린지셋으로 둔다.
2. **새 대학 일반화:** 특정 대학의 두 연도 자료에서 만든 QA를 모두 같은 `institution_group`으로 묶는다. 학습에서 제외한 대학의 문서를 읽고 답하는 능력을 측정한다. 이번 3개 대학은 수집 파일럿이며 독립 대학 평가에는 부족하다. 지역/설립유형 등을 고려해 예를 들어 10~20개 대학으로 확대한 후 그룹 배정을 고정한다. 전국 공통 장학금은 대학 수로 독립 표본을 부풀리지 않는다.
3. **연도 갱신:** 2025 QA로 개발하고 2026 QA로 평가한다. 동일 대학의 규정 재등장은 이 실험에서 의도된 조건이다. 변경/미변경 조항을 별도 보고하고 `as_of_date` 이후 자료는 제공하지 않는다. 이것은 대학 미지 실험과 다르며 위 48/12/40 배정과도 별도다.

분할 전 정규화 해시, 유사 문장 검색, 동일 근거 조항/템플릿 연결을 검사한다. 사람이 규칙 그룹을 검수하고 분할 파일의 해시를 고정한다. 스크립트는 의미가 같은 질문을 자동으로 전부 발견하지 못한다.

## RAG 평가에서 허용되는 자료

실제 서비스처럼 **시험 대상 대학의 모집요강을 검색할 수 있게 하는 것**은 open-book 평가의 정당한 조건이다. 시험 정답을 몰래 보여주는 것과 구분해야 한다.

- 개발/시험 QA, gold 답변, 이 QA를 생성한 해설 문구는 학습 및 시험 검색 색인에 섞지 않는다. 기본 실험은 공식 규정 원문만 검색한다.
- 정답 작성에 사용한 FAQ를 서비스 색인에도 넣고 싶다면 별도 `FAQ 포함` 실험으로 명시한다. 규정 해석과 FAQ 재검색 점수를 구분한다.
- 정책 원문과 FAQ가 한 PDF에 들어 있으면 섹션별 접근 규칙을 만든다. 단순히 파일명을 분리하는 것으로 누출이 사라지지 않는다.
- 검색 가능 자료의 버전·해시·메타데이터를 고정하고 모든 RAG 비교군에 동일하게 제공한다. 시험의 근거 페이지를 직접 제공하는 oracle-context 실험은 실제 검색 성능으로 보고하지 않는다.
- 사전학습 데이터 노출 여부는 여기서 증명할 수 없다. 사람이 새로 작성한 적용 질문, 규정이 바뀌는 경계 사례, 명확히 합성임을 표시한 반사실 규정 시험을 보완적으로 사용한다.

## 비교 실험

| 조건 | 모델/방법 | 알 수 있는 것 |
|---|---|---|
| A | 현재 GGUF Qwen, 외부 문서 없음 | 기존 지식의 한계. 원문 접근 조건이 다른 대조군임을 명시 |
| B | 검색 결과와 규칙/양식만 제공, LLM 없음 | 단순 검색·규칙 시스템 대비 LLM의 가치 |
| C | 현재 Qwen + 공식 원문 RAG | 우선 구현할 기준선 |
| D | LoRA Qwen + C와 동일한 RAG | 미세조정의 추가 이득 |
| E | C 또는 D + 검증된 조건 판정/계산 코드 | 규칙·계산 도구의 추가 이득 |

처음부터 D만 만들어 정확도를 보고하면 검색이나 모델 암기만으로 얻을 수 있는 효과와 구별되지 않는다. C에서 반복되는 오류를 분류한 뒤 필요할 때 D를 추가한다. 미세조정 목표는 연도별 규칙 암기보다 근거 인용, 조건 확인, 설명 형식, 불확실할 때 보류하는 행동이다.

모델 파일 해시, 변형명, tokenizer/chat template, 양자화, thinking 설정, 컨텍스트 길이, 최대 생성 토큰, temperature, seed(지원 시), 서버 버전, 검색 설정, 하드웨어를 기록한다. 프롬프트를 고정하고 모델이 바뀌면 동일 조건으로 재평가한다.

## 정확도와 실패 비용

- **핵심 조건 완전 정답률:** 학년도·전형·자격·수능 최저·날짜·금액 등 해당 질문의 필수 필드가 모두 정확한 비율. 질문 유형별로 보고한다.
- **근거 정확도:** 인용한 페이지가 실제 주장을 뒷받침하는지, 해당 연도/버전인지 검수한다. URL이 존재하는 것만으로 맞다고 채점하지 않는다.
- **검색 Recall@k:** gold 근거 조항이 검색 결과에 포함되는 비율. 검색 실패와 생성 실패를 분리한다.
- **잘못된 배제:** 실제 지원 가능한 사람에게 지원 불가라고 답한 비율. 반대 오류도 별도로 보고한다.
- **보류와 추가 질문:** 정보가 부족한 표본에 필요한 질문을 했는지, 답할 수 있는 표본을 과도하게 거부하는지 평가한다. 답변 커버리지와 답변한 항목의 정확도를 함께 제시한다.
- **비용 계산:** 중복지원 제한, 등록금 상한, 기간/단위, 대출 구분을 포함해 코드와 사람이 검증한 결과에 대조한다.
- **운영 성능:** 응답 시간 p50/p95, 입력·출력 토큰, 메모리, 하드웨어와 동시접속 조건.

두 검토자가 모델명을 가린 상태에서 독립 채점하고 불일치를 조정한다. LLM judge는 보조 도구로만 사용한다. BLEU/ROUGE나 문장 임베딩 유사도만으로 정확도를 선언하지 않는다. 하나의 종합점수로 큰 오류를 가리지 않는다.

평가 질문은 단순 조회, 여러 조건 조합, 경계/예외, 연도 변경, 정보 부족, 문서에 없는 질문을 포함한다. 대학/전형/지역별 macro 점수와 문항별 micro 점수를 함께 보고한다. 파생 질문 수를 독립 표본 수로 간주하지 말고 대학·규칙 그룹을 고려한 bootstrap 등으로 신뢰구간을 계산한다. 예를 들어 완전히 독립적인 400문항에서 정답률 90%라면 단순 근사 95% 오차는 약 ±3%p이나, 같은 규칙의 변형이 많으면 이보다 불확실성이 크다.

## 실행 순서와 현재 상태

1. 원문 수집 및 수정본·각주 검수 → 이번 작업에 수집기와 파일럿 목록 포함.
2. 규정 원문/해설 구간 구분, 표 구조 검수 → 부분적으로만 확인; 전수 검수 필요.
3. 사람 검수 QA 구축, 그룹 지정, 잠근 시험셋 작성 → 아직 미완료. 공개 초안은 최종 시험용으로 재사용하지 않는다.
4. Qwen RAG 기준선과 비LLM 기준선 → 후속 작업에서 CPU 모델을 직접 설치해 RAG 및 개발 예시 5개의 문서 유무 비교를 실행했다. [실제 결과](../reports/pilot_report.md). 비LLM 검색 인터페이스를 포함한 사용자 수준 비교와 잠근 시험 평가는 아직 필요하다.
5. 오류 분석 후 LoRA 여부 결정 → 아직 학습하지 않음.
6. 정보 이해도·신청 누락 등 사용자 실험 → 별도 단계. QA 정확도만으로 교육격차나 대학 진학률 개선을 입증하지 않는다.
